이 장은 프로젝트를 맡아 꾸려 가는 **프로젝트 관리자**를 위한 안내입니다. 프로젝트 관리자는 프로젝트의 규칙(켜고 쓸 기능, 팀, 달력, 업무 흐름)을 정하고, 함께할 사람과 권한을 정하고, 작업 계획(WBS, 일을 단계별로 쪼갠 목록)을 만들고 가져오는 사람입니다.

이 장에서 할 수 있는 일은 다음과 같습니다.

- 처음 프로젝트를 준비할 때 [프로젝트 준비 체크리스트](#프로젝트-준비-체크리스트)를 따라 빠뜨린 설정이 없는지 확인합니다.
- [프로젝트 설정 화면](#프로젝트-설정-화면-사용법)의 모든 카드를 이해하고 바꿉니다. 기본 정보, 기능 켜고 끄기, 팀, 업무영역, 달력, 업무 흐름이 여기에 있습니다.
- [멤버와 권한 관리](#멤버와-권한-관리)에서 사람을 명단에 넣고 빼고, 권한을 정하고, 이메일로 초대합니다.
- [WBS를 엑셀로 가져오기](#wbs를-엑셀로-가져오기)로 작업 계획을 한 번에 채웁니다.
- [주간보고 시트와 업무영역](#주간보고-시트와-업무영역)에서 새 주차 시트를 만듭니다.
- [관리자 승인이 필요한 일](#관리자-승인이-필요한-일)을 처리합니다.

관리자가 아닌 분이 이 장의 화면을 열면 일부가 보이지 않거나, 보이더라도 바꿀 수 없습니다. 프로젝트를 새로 만들거나 지우는 일은 워크스페이스 관리자의 몫이므로 [워크스페이스 관리자](/help/workspace-admin) 장을 보세요.

## 프로젝트 관리자란

프로젝트 관리자는 한 프로젝트 안의 설정, 사람, 작업 계획을 책임지는 등급입니다. 프로젝트마다 등급이 따로 정해집니다.

| 등급 | 어떻게 정해지나요 | 이 프로젝트에서 할 수 있는 일 |
|---|---|---|
| 조회 전용 | **팀 구성** 명단에 없거나, 명단에 있어도 권한 칸이 **없음(조회 전용)** 인 사람 | 볼 수만 있습니다. |
| 멤버 | **팀 구성** 명단에서 권한이 **멤버** 인 사람 | 일반 업무(담당 작업 입력, 이슈·회의·주간보고 작성 등)를 합니다. |
| 프로젝트 관리자 | **팀 구성** 명단에서 권한이 **관리자** 인 사람 | 이 장의 모든 일을 합니다. |
| 워크스페이스 관리자 | 그 프로젝트가 속한 워크스페이스의 관리자 | 그 워크스페이스의 모든 프로젝트에서 관리자를 겸합니다. 명단에 있으면 팀 구성 표에 **워크스페이스 관리자에서 상속** 이라고 표시됩니다. |
| 플랫폼 관리자 | 서비스 전체를 관리하는 사람 | 모든 프로젝트에서 관리자와 같은 일을 합니다. |

내가 이 프로젝트의 관리자인지 확인하는 가장 쉬운 방법은 화면 왼쪽 메뉴를 보는 것입니다. **설정** 메뉴가 보이면 관리자입니다. 관리자가 아닌 사람이 주소를 직접 입력해 설정 화면에 들어가려 하면 **개요** 화면으로 돌아갑니다.

> **팁** 메뉴 이름은 워크스페이스 관리자가 바꿀 수 있습니다. 이 장의 메뉴 이름이 화면과 다르면 같은 자리의 메뉴를 찾아 보세요.

> **주의** 프로젝트 관리자 권한을 다른 사람에게 주거나 회수하는 일은 워크스페이스 관리자 이상만 할 수 있습니다. 프로젝트 관리자끼리는 서로의 관리자 권한을 바꿀 수 없습니다. 자세한 내용은 [권한 바꾸기](#권한-바꾸기)에 있습니다.

## 관리자 화면 한눈에 보기

관리자가 자주 가는 곳은 다음과 같습니다.

| 하려는 일 | 가는 곳 |
|---|---|
| 프로젝트의 규칙을 정하거나 바꾸기 | 왼쪽 메뉴 **설정** (화면 제목은 **프로젝트 설정**) |
| 사람을 넣고 빼고 권한 정하기, 초대하기 | 왼쪽 메뉴 **팀 구성** |
| 엑셀로 작업 가져오기 | **설정**의 **일반** 목차에 있는 **WBS 데이터 가져오기 · 내보내기** 카드에서 **가져오기 마법사 열기**를 누릅니다. 작업 계획이 비어 있을 때는 **작업 계획** 화면의 **엑셀로 가져오기** 버튼으로도 갈 수 있습니다. |
| 작업을 직접 추가하고 구조 고치기 | 왼쪽 메뉴 **작업 계획** |
| 새 주차 주간보고 시트 만들기 | 왼쪽 메뉴 **주간보고** |
| 준비 상황 확인 | **설정** 맨 위 **프로젝트 준비**, 또는 **개요** 맨 위의 준비 안내 줄 |

## 프로젝트 준비 체크리스트

새 프로젝트를 만든 뒤 무엇부터 해야 할지 모를 때 쓰는 목록입니다. **설정** 화면 맨 위에 **프로젝트 준비** 상자로 나타나고, **개요** 화면 맨 위에는 한 줄짜리 안내 줄로 나타납니다. 두 곳 모두 프로젝트 관리자에게만 보입니다.

각 단계는 "확인했어요" 버튼을 누르는 방식이 아닙니다. 실제 설정 상태를 보고 자동으로 **완료**인지 **아직**인지 판정합니다.

| 단계 | 완료로 보는 조건 | **열기**를 누르면 가는 곳 |
|---|---|---|
| 기본 정보 | 프로젝트 이름과 시작일·종료일이 모두 들어 있을 때 | **설정**의 **일반** |
| 단계 이름 | WBS 단계 이름이 저장되어 있을 때 | **설정**의 **일반** |
| 팀 | 이 프로젝트가 쓰는 팀 가운데 활성 팀이 하나 이상 있을 때 | **설정**의 **팀·업무영역** |
| 멤버 | 명단에 활성 상태인 사람이 두 명 이상 있거나, 보낸 초대가 한 건 이상 있을 때 | **팀 구성** |
| 업무영역 | 활성 업무영역이 하나 이상 있을 때. 주간보고 기능이 켜져 있을 때만 이 단계가 나타납니다. | **설정**의 **팀·업무영역** |
| 달력 | 시간대, 근무 요일, 주 시작 요일이 모두 저장되어 있을 때. 새 프로젝트는 워크스페이스의 값이 복사되어 이미 완료인 경우가 많습니다. | **설정**의 **달력** |
| 첫 데이터 | 작업 계획에 항목이 한 개 이상 있을 때 | **작업 계획** |

단계 이름 옆에는 현재 상태가 **완료**, **아직**, **건너뜀**, **확인 불가** 중 하나로 표시됩니다. **확인 불가**는 그 단계의 상태를 읽지 못했다는 뜻이며, 화면을 새로고침해 보세요.

### 체크리스트 사용하기

1. **설정** 화면을 엽니다. 맨 위 **프로젝트 준비** 상자에 `3/7 완료` 같은 진행 상황이 보입니다.
2. 아직 안 한 단계 오른쪽의 **열기**를 누릅니다. 해당 설정 위치로 이동합니다.
3. 설정을 마치고 저장한 뒤 **설정**으로 돌아오면 그 단계가 **완료**로 바뀌어 있습니다.
4. 지금 필요 없는 단계는 **건너뛰기**를 누릅니다. 그 단계는 **건너뜀**으로 바뀌고 다음 안내 대상에서 빠집니다. 마음이 바뀌면 **건너뛰기 취소**를 누릅니다.
5. 목록이 필요 없으면 상자 오른쪽 위의 **닫기**를 누릅니다. 상자가 접히고 **준비 체크리스트 열기 · 3/7 완료** 버튼만 남습니다. 이 버튼을 누르면 다시 펼쳐집니다.

모든 단계를 마치면 **준비 단계를 모두 마쳤습니다.** 라고 표시됩니다. 남은 단계를 모두 건너뛴 경우에는 **남은 준비 단계가 없습니다.** 라고 표시됩니다.

### 개요 화면의 준비 안내 줄

**개요** 화면 맨 위에 **프로젝트 준비**, 진행 상황, **다음: 팀** 같은 다음 단계 링크, **전체 보기**, 닫기(X) 버튼이 한 줄로 나옵니다. 남은 단계가 없거나 닫기를 누르면 이 줄은 보이지 않습니다. **전체 보기**를 누르면 **설정** 화면으로 이동합니다.

> **팁** 건너뛰기와 닫기는 이 계정과 이 프로젝트에 대해 지금 쓰는 브라우저에만 저장됩니다. 설정 자체는 바뀌지 않습니다. 다른 브라우저나 다른 컴퓨터에서는 다시 나타날 수 있습니다. 브라우저가 저장을 허용하지 않으면 **이 브라우저에서는 건너뛰기·닫기를 저장할 수 없습니다.** 라는 안내가 나옵니다.

## 프로젝트 설정 화면 사용법

프로젝트의 규칙은 모두 **설정** 화면 한 곳에 모여 있습니다. 이 절은 화면의 공통 사용법이고, 각 카드의 자세한 사용법은 이어지는 절에 나옵니다.

### 설정 화면 여는 방법

1. 화면 왼쪽 메뉴에서 **설정**을 누릅니다.
2. **프로젝트 설정** 화면이 열립니다. 제목 아래에는 프로젝트 이름과 기간이 `프로젝트 이름 · 2026-01-05 – 2026-12-18` 모양으로 보입니다. 기간이 비어 있으면 **미정**이라고 나옵니다.

### 화면 구성과 목차

화면 왼쪽(좁은 화면에서는 위쪽)에 **설정 검색** 입력칸과 목차가 있고, 오른쪽에 카드가 세로로 이어집니다. 목차에서 항목을 누르면 그 위치로 이동하고, 스크롤하면 지금 보고 있는 항목이 강조됩니다.

목차 항목과 그 안의 카드는 다음과 같습니다. 일부는 해당 기능이 켜져 있을 때만 보입니다.

| 목차 항목 | 들어 있는 카드 | 보이는 조건 |
|---|---|---|
| **일반** | **기본 정보**, **WBS 단계**, **추가 축 이름**, **대시보드 판정 기준**, **WBS 데이터 가져오기 · 내보내기**, **AI 어시스턴트 의미검색 색인** | 항상. **서버 LLM 설정** 카드는 플랫폼 관리자에게만 보입니다. |
| 기능과 메뉴 항목 | 켜고 끌 기능 목록, **작업 계획 기본 보기** | 항상. 목차에서 **일반** 바로 아래에 있고, 이름이 `·메뉴`로 끝납니다. |
| **팀·업무영역** | **권한**, **팀 관리**, **업무영역**, **이슈 영역** | **이슈 영역**은 이슈 기능이 켜져 있을 때만 |
| **이슈** | **이슈 코드·분석 규칙** | 이슈 기능이 켜져 있을 때만 |
| **회의록** | **회의록 첨부 정책**, **외부 업로드 폴더 자동 정리** | 회의록 기능이 워크스페이스에서 켜져 있을 때만 |
| **용어·분류** | 근태 유형, 회의 분류, 이슈 심각도, 이슈 출처, 원인 분류 카드 | 각각 해당 기능(근태, 회의, 이슈, 이슈 분석)이 켜져 있을 때만 |
| **양식** | **보고서 양식** | 항상(WBS 내보내기 양식은 늘 있고, 주간보고·이슈 분석 양식은 해당 기능이 켜져 있을 때 더해집니다) |
| **추가 필드** | **추가 필드** | 항상 |
| **상태·승인** | **이슈 상태**, **WBS 승인 흐름**, **에이전트**, **프로젝트 상태 관리** | **이슈 상태**는 이슈 기능이 켜져 있을 때만 |
| **달력** | **달력 — 기준일·주 시작·근무 요일·날짜 예외** | 항상 |
| **기록** | **설정 변경 이력** | 항상 |
| **위험 구역** | 프로젝트 삭제 | 워크스페이스 관리자(플랫폼 관리자 포함)에게만 |

### 설정 찾기

카드가 많아서 어디 있는지 모를 때는 목차 위의 **설정 검색** 입력칸을 씁니다.

1. **설정 검색** 입력칸에 찾는 말의 일부를 입력합니다. 예를 들어 `근무`, `팀`, `승인`, `달력`을 입력해 보세요. 카드에 적힌 제목, 안내 문구, 항목 이름의 글자를 기준으로 찾습니다.
2. 입력한 말과 맞지 않는 카드는 화면에서 숨겨지고, 맞는 카드만 남습니다.
3. 입력칸을 비우면 모든 카드가 다시 나타납니다.

> **팁** 맞는 카드가 하나도 없으면 목록이 텅 비어 보입니다. 오류가 아니니 검색어를 줄이거나 입력칸을 비우세요.

### 저장하는 방법과 충돌 안내

설정 화면은 카드마다 저장 방식이 조금씩 다릅니다. 공통 규칙은 다음과 같습니다.

- **카드마다 따로 저장합니다.** 한 카드를 고친 뒤 그 카드의 **저장** 버튼을 눌러야 반영됩니다. 다른 카드에서 고친 값은 함께 저장되지 않습니다.
- **먼저 검토하는 카드도 있습니다.** 마일스톤 키워드, 켜고 끌 기능, 단계별 실적 크레딧은 **변경 내용 검토**를 눌러 바뀌는 내용을 먼저 보고, 새로 나타나는 저장 버튼(**검토 후 저장**, **변경 저장**, **저장** 등)을 눌러 저장합니다.
- **저장 줄이 화면 아래에 붙어 있는 카드도 있습니다.** 카드가 길어도 저장 버튼을 찾기 쉽도록 화면 아래쪽에 따라다닙니다.
- **성공하면** 저장 버튼 근처에 **저장했습니다.** 같은 안내가 나옵니다. 바뀐 값이 없으면 **바뀐 값이 없습니다.** 라고 나옵니다.
- **입력이 잘못되면** 빨간 글씨로 이유가 나오고 저장되지 않습니다. 고친 뒤 다시 저장하세요.

**다른 관리자와 동시에 고쳤을 때.** 두 관리자가 같은 설정을 동시에 고치면 나중에 저장하는 사람에게 **다른 사용자가 설정을 바꿨습니다.** 라는 상자가 나옵니다. 상자에는 **내 값**과 **최신 값**이 나란히 보이고 두 버튼이 있습니다.

- **내 값 다시 적용**: 내가 입력한 값을 그대로 저장합니다.
- **최신 값 사용**: 다른 사람이 저장한 값을 받아 화면에 채웁니다.

카드에 따라 상자의 문구와 버튼 이름이 조금 다를 수 있습니다. 상자 대신 **다른 사용자가 설정을 먼저 바꿨습니다. 최신 값을 확인한 뒤 다시 저장하세요.** 라는 안내만 나오고 화면이 새로 고쳐지는 카드도 있습니다. 그럴 때는 새로 보이는 값을 확인한 뒤 필요한 부분을 다시 입력해서 저장하세요.

**저장 결과를 모를 때.** 인터넷이 끊기는 등의 이유로 저장이 됐는지 알 수 없으면 **저장 결과를 확인하지 못했습니다.** 라는 안내가 나오고 저장 버튼이 **저장 결과 확인 및 재시도**로 바뀝니다. 이 버튼은 같은 요청을 다시 보냅니다. 이미 저장된 내용이면 중복으로 저장되지 않으니 안심하고 누르세요.

**설정을 불러오지 못했을 때.** 화면 위쪽에 **설정을 불러오지 못해 이 화면을 그릴 수 없습니다. 잠시 뒤 새로고침하세요.** 라는 안내가 나오면 잠시 뒤 새로고침합니다. **설정이 손상되었습니다.** 또는 **필요한 설정이 없습니다.** 라고 나온 카드는 그 카드에서 값을 고르거나 입력해 다시 저장하면 고쳐집니다. 카드 안에 `저장하면 고쳐집니다` 같은 안내가 함께 나옵니다. 어떤 설정이 문제인지는 `손상되었거나 비어 있는 설정: 설정 이름`처럼 한국어 설정 이름으로 알려 줍니다.

## 기본 정보와 마일스톤 키워드

**일반** 목차의 첫 카드 **기본 정보**에서 프로젝트 이름, 설명, 기간을 확인하고 고칩니다. 같은 카드 아래쪽에는 마일스톤 키워드를 정하는 칸이 있습니다.

### 이름·설명·기간 바꾸기

1. **설정**에서 **기본 정보** 카드를 찾습니다. 카드 안에 **프로젝트명**, **설명**, **시작일**, **종료일**이 한 줄씩 보입니다. 설명이 비어 있으면 **설명이 아직 없습니다.** 라고 나옵니다.
2. 카드 오른쪽 위의 **편집**을 누릅니다. **기본 정보 편집** 창이 열립니다.
3. **프로젝트명**, **설명**, **시작일**, **종료일**을 고칩니다. 프로젝트명은 꼭 있어야 하고, 시작일과 종료일은 달력에서 고릅니다.
4. **저장**을 누릅니다. 창이 닫히고 **기본 정보를 저장했습니다.** 라는 안내가 나오며 카드의 값이 새로 바뀝니다.

창을 닫았다가 다시 열면 입력 칸은 저장된 값으로 새로 채워집니다. 고치다 만 값이 남아 있지 않으니 안심하세요.

> **주의** 프로젝트명은 100자 이하의 한 줄이어야 합니다. 시작일이 종료일보다 늦으면 **시작일은 종료일보다 늦을 수 없습니다.** 라고 나오며 저장되지 않습니다.

> **팁** 기간을 줄였더니 일정이 기간 밖으로 나간 작업이 생기면 **작업 계획** 화면에 `프로젝트 기간 밖 작업 3건` 같은 안내가 나오고 해당 행의 날짜가 강조됩니다. 저장은 막지 않으니 그 작업의 일정을 확인해서 고치세요.

워크스페이스 관리자에게는 이 카드 위쪽에 `○○ 워크스페이스 설정 →` 링크가 한 줄 더 보입니다. 프로젝트 관리자에게는 보이지 않습니다.

### 마일스톤 키워드 정하기

마일스톤은 일정에서 이정표가 되는 중요한 작업입니다. 작업 이름에 키워드가 들어 있으면 **개요** 화면의 마일스톤 타임라인에 이정표로 표시됩니다.

1. **기본 정보** 카드 아래쪽 **마일스톤 키워드** 입력칸을 찾습니다. 오른쪽 위에 **프로젝트 설정** 또는 **제품 기본값**이 보입니다. 직접 저장한 적이 없으면 **제품 기본값**입니다.
2. 한 줄에 키워드 하나씩 입력합니다. 처음에는 `마일스톤`, `milestone`, `킥오프`, `kick-off`, `오픈`, `완료보고`가 들어 있습니다.
3. **변경 내용 검토**를 누릅니다. 입력칸 아래에 **현재:** 키워드와 **변경:** 키워드가 나란히 보입니다.
4. 맞으면 **검토 후 저장**을 누릅니다. 고칠 것이 있으면 **계속 수정**을 누릅니다.
5. **마일스톤 키워드를 저장했습니다. 대시보드에 즉시 적용됩니다.** 라는 안내가 나오면 끝입니다.

> **주의** 키워드는 최대 50개이고 하나당 40자까지입니다. 저장하면 영문은 소문자로 바뀝니다. 모두 지우고 저장하면 마일스톤 표시가 나오지 않습니다. 작업 자체는 바뀌지 않고 표시 기준만 바뀝니다.

## WBS 단계 이름 정하기

작업 계획은 큰 일 아래에 작은 일이 달리는 나무 모양입니다. **WBS 단계** 카드에서 깊이마다 부를 이름을 정합니다. 예를 들어 1단은 "단계", 2단은 "업무", 3단은 "세부 작업"이라고 부를 수 있습니다. 이 이름은 작업 계획 화면의 배지, 보고서, 엑셀의 머리글에 그대로 쓰입니다. 이름 개수가 곧 작업 계획의 최대 깊이입니다.

1. **설정**의 **일반** 목차에서 **WBS 단계** 카드를 찾습니다. `1단`, `2단`처럼 번호가 붙은 입력칸이 줄지어 있습니다.
2. 이름을 고치려면 해당 입력칸을 수정합니다.
3. 단계를 늘리려면 **단계 추가**를 누르고 새 입력칸에 이름을 씁니다.
4. 단계를 줄이려면 줄 오른쪽의 X 버튼(`2단 삭제`처럼 읽힙니다)을 누릅니다. 단계가 하나뿐이면 X가 나오지 않습니다.
5. **저장**을 누릅니다. **WBS 단계를 저장했습니다.** 라는 안내가 나옵니다.

> **주의** 단계는 1개 이상 10개 이하이고, 이름은 비울 수 없고 20자 이하이며 서로 달라야 합니다. 이미 작업 계획에 깊은 항목이 있으면 그 깊이보다 적게 줄일 수 없습니다. 예를 들어 이미 3단까지 항목이 있는데 2단으로 줄이면 **기존 WBS 에 깊이 3단 항목이 있어 2단으로 줄일 수 없습니다.** 라고 나옵니다. 먼저 작업 계획에서 깊은 항목을 정리하세요.

## 추가 축 이름과 대시보드 판정 기준

### 추가 축 이름 바꾸기

작업마다 "업무 분류"를 적는 칸이 있습니다. 엑셀로 가져올 때는 **업무영역** 열이 이 칸에 해당합니다. **추가 축 이름** 카드에서 이 칸을 우리 프로젝트에서 부르는 이름으로 바꿉니다. 일괄 편집 창, 변경 이력, 엑셀 가져오기와 내보내기의 그 열 이름이 바뀝니다.

1. **일반** 목차의 **추가 축 이름** 카드를 찾습니다. 입력칸에 `기본 이름 사용`이라고 연하게 보이면 아직 바꾸지 않은 상태입니다.
2. 원하는 이름(1~20자)을 입력합니다. 예: `담당 사업부`
3. **저장**을 누릅니다. **저장했습니다.** 라고 나옵니다.

이름을 비우고 저장하면 기본 이름으로 돌아갑니다.

### 대시보드 판정 기준 바꾸기

**개요** 화면과 이슈 목록은 "마감이 임박했다"와 "위험하다"를 일정한 기준으로 판정합니다. **대시보드 판정 기준** 카드에서 이 기준을 바꿉니다. 저장한 데이터는 바뀌지 않고, 다음에 여는 화면부터 새 기준이 적용됩니다.

| 항목 | 의미 | 입력 범위 | 처음 값 |
|---|---|---|---|
| **마감 임박 기준** | 마감까지 남은 날이 이 일수 이하인 미완료 작업·이슈를 "임박"으로 봅니다. | 1~60 (뒤에 **일 이내**가 붙습니다) | 7일 |
| **지연 '위험' 기준** | 지연 작업이 이 건수 이상이면 위험(빨강)으로, 그보다 적으면서 1건 이상이면 주의로 표시합니다. | 1~999 (뒤에 **건 이상**이 붙습니다) | 4건 |

1. 두 칸에 숫자를 입력합니다.
2. **저장**을 누릅니다.

범위를 벗어나면 **마감 임박 기준은 1~60일, 위험 기준은 1~999건 사이의 정수로 입력하세요.** 라고 나오고 저장되지 않습니다.

## AI 어시스턴트 색인 관리

AI 어시스턴트가 최신 작업을 찾아서 답할 수 있도록, 작업 계획의 항목과 멤버를 검색용 색인으로 만들어 두는 곳입니다. **일반** 목차의 **AI 어시스턴트 의미검색 색인** 카드에 있습니다. AI 어시스턴트 자체의 사용법은 [AI 도우미](/help/ai-assistant) 장을 보세요.

카드 오른쪽 위에 현재 상태를 알리는 배지가 있습니다.

| 배지 | 뜻 |
|---|---|
| **색인 최신 · 120건** | 색인이 최신입니다. |
| **재색인 필요 (WBS 변경 감지)** | 작업 계획을 고친 뒤 색인을 아직 갱신하지 않았습니다. |
| **AI 검색 준비 중** | AI 검색 기능이 아직 준비되지 않았습니다. |
| **AI 키 미설정 · 결정형 답변 동작** | AI 연결이 설정되어 있지 않습니다. 이때도 AI 어시스턴트는 정리된 데이터를 바탕으로 답합니다. |
| **WBS 데이터 없음** | 색인할 작업이 아직 없습니다. |
| **색인 상태 확인 불가** | 상태를 읽지 못했습니다. |

1. 배지에 **재색인 필요 (WBS 변경 감지)** 가 보이면 **AI 색인 재생성**을 누릅니다.
2. 버튼이 **색인 중…** 으로 바뀝니다. 끝나면 `AI 색인 완료`와 `120개 문서를 색인했어요.` 같은 안내가 나옵니다.

WBS를 엑셀로 가져오면 색인은 자동으로 갱신됩니다. 작업을 직접 고친 뒤에는 위처럼 눌러 주세요. 안내가 `AI 색인 일부 완료`로 나오면 일부를 건너뛴 것이니 잠시 뒤 다시 누르면 나머지가 색인됩니다. `색인 실패`와 함께 "기존 색인은 보존됩니다"라고 나오면 잠시 뒤 다시 시도하세요. `AI 키 미설정`이라는 안내가 나오면 서비스에 AI 연결이 아직 설정되지 않은 것이니 플랫폼 관리자에게 알리세요.

> **주의** 챗봇 기능이 이 프로젝트에서 꺼져 있으면 색인을 다시 만들 수 없습니다. 먼저 [기능 켜고 끄기](#기능-켜고-끄기)에서 챗봇을 켜세요.

## 기능 켜고 끄기

프로젝트에서 쓸 기능을 고르는 곳입니다. 꺼진 기능은 왼쪽 메뉴에서 사라지고 그 기능의 화면도 열리지 않습니다. 다시 켜면 이전 데이터가 그대로 살아납니다. 목차에서 **일반** 바로 아래, 이름이 `·메뉴`로 끝나는 항목입니다.

고를 수 있는 기능은 칸반, 회의, 주간보고, 이슈, 이슈 분석, 공지, 근태, 에이전트, 위키, 챗봇입니다. 개요, 작업 계획, 팀 구성, 설정은 항상 켜져 있어 끌 수 없습니다.

### 기능을 켜거나 끄는 방법

1. 이 항목의 카드를 엽니다. 켜진 기능이 체크된 칸으로 나열되어 있습니다. 꺼진 기능은 "꺼진"으로 시작하고 개수가 붙은 접힘 목록 안에 들어 있으며, 눌러서 펼칠 수 있습니다.
2. 켜고 싶은 기능은 체크하고, 끄고 싶은 기능은 체크를 풉니다.
3. **변경 내용 검토**를 누릅니다. **변경 내용 검토** 상자에 `추가:`와 `제외:`가 나오고, 기능을 끄면 영향을 받는 데이터 건수(예: `이슈 12건`)도 함께 보입니다.
4. 안내를 읽고 **변경 저장**을 누릅니다. 저장 줄에 저장됐다는 안내가 나옵니다.

끄더라도 데이터는 지워지지 않으며, 다음 화면 요청부터 새 설정이 적용됩니다.

> **주의** 어떤 기능은 다른 기능이 먼저 켜져 있어야 동작합니다. 이슈 분석은 이슈가, 위키는 워크스페이스의 회의록 기능이 켜져 있어야 합니다. 앞 기능이 꺼져 있으면 뒤 기능은 켜 두어도 쓸 수 없습니다.

> **팁** 어떤 기능이 체크 칸이 아니라 `워크스페이스 미허용 또는 배포 비가용 — 저장값 유지`라는 노란 상자나 `이 배포/계약에서 사용할 수 없는 …` 문구 안에 나온다면, 워크스페이스에서 허용하지 않았거나 이 서비스에서 쓸 수 없는 기능입니다. 프로젝트 관리자는 켜거나 끌 수 없습니다. 쓸 수 있는 기능의 범위는 플랫폼 관리자만 정하므로, 워크스페이스 관리자를 통해 플랫폼 관리자에게 요청해야 합니다.

에이전트를 켰는데도 화면에 `에이전트 사용 설정은 켜져 있지만 현재 기능은 닫혀 있습니다…` 라는 경고가 나오면, 에이전트를 한 번 껐다가 저장한 뒤 다시 켜서 저장하세요.

### 작업 계획 기본 보기

같은 카드 아래쪽 **작업 계획 기본 보기** 구역에서 작업 계획 화면을 처음 열었을 때 어떤 모양으로 보일지 고릅니다.

1. 세 개의 선택 카드 가운데 하나를 누릅니다.
   - **표**: 행과 열로 편집합니다.
   - **간트**: 일정 막대로 봅니다.
   - **보드**: 카드로 묶어 봅니다(칸반).
2. **기본 보기 저장**을 누릅니다.

**보드**는 칸반 기능이 켜져 있을 때만 고를 수 있습니다. 꺼져 있으면 카드에 **(칸반 꺼짐)** 이라고 나오고, **칸반이 꺼져 있어 보드를 기본 보기로 고를 수 없습니다. 작업 계획은 표로 열립니다.** 라는 안내가 나옵니다.

## 팀 관리

여기서 말하는 팀은 작업의 담당 팀, 명단의 소속, 칸반, 보고서 집계에 쓰는 이 프로젝트의 팀 목록입니다. **팀·업무영역** 목차의 **팀 관리** 카드에서 만듭니다. 이 목차의 첫 카드 **권한**은 안내만 있습니다. 권한과 초대는 **팀 구성** 화면에서 하니 카드의 **팀 구성 열기** 링크를 눌러 이동하세요.

### 팀을 쓰는 두 가지 방법

이 프로젝트가 아직 자기 팀을 만들지 않았다면 워크스페이스에 등록된 공용 팀을 그대로 가져다 씁니다. 이를 "상속"이라고 합니다. 카드에 **현재 워크스페이스 공용 팀을 상속 중입니다. 이 프로젝트만의 팀을 정의하면 상속이 끊깁니다.** 라고 나오며 두 버튼이 있습니다.

- **공용 팀 전환으로 시작**: 지금 쓰는 공용 팀을 같은 코드·이름·색의 이 프로젝트 팀으로 바꿉니다. 작업 담당, 명단의 팀, 업무영역 담당, 수락 전 초대의 팀 연결도 새 팀으로 함께 옮겨집니다. 이후 공용 팀을 고치거나 추가해도 이 프로젝트에는 반영되지 않습니다. 확인 창이 한 번 나오고, **전환하기**를 누르면 되돌릴 수 없습니다.
- **빈 목록에서 시작**: 이 프로젝트만의 팀을 처음부터 만듭니다. 이름과 코드를 입력하는 칸이 나옵니다. 첫 팀을 추가할 때 확인 창(**공용 팀 상속 종료**)이 한 번 나오고 **계속**을 누르면 상속이 끊깁니다. 이미 공용 팀에 걸려 있던 작업 담당은 화면에서 `목록 밖 팀`으로 처리됩니다.

워크스페이스에 공용 팀이 없으면 **공용 팀 전환으로 시작**은 누를 수 없고 안내가 나옵니다. 그때는 **빈 목록에서 시작**으로 첫 팀을 만드세요.

### 팀 추가하기

1. **이름** 칸에 팀 이름을 입력합니다. 예: `설계팀`
2. **코드(선택)** 칸은 비워 두어도 됩니다. 비우면 이름에서 코드를 만들어 칸 아래에 `저장될 코드: …`로 미리 보여 줍니다. 코드는 엑셀로 가져오고 내보낼 때 팀을 가리키는 식별자입니다.
3. **팀 추가**를 누릅니다. `'설계팀' 팀을 추가했습니다.` 라는 안내가 나오고 목록에 나타납니다.

### 목록에서 팀 고치기

팀이 하나 이상 생기면 **팀 목록** 표가 나타납니다. 열은 **순서**, **색**, **이름**, **코드**, **상태**, **팀별 진척현황**, **작업**입니다.

- **순서 바꾸기**: 위·아래 화살표를 눌러 한 칸씩 옮깁니다.
- **색 바꾸기**: 이름 앞의 색 동그라미를 눌러 여덟 가지 색 가운데 하나를 고릅니다.
- **이름 바꾸기**: 이름 옆 연필 버튼을 누르고 새 이름을 입력한 뒤 Enter(또는 체크 버튼)로 저장하고, Esc(또는 X 버튼)로 취소합니다. 이름은 언제든 바꿀 수 있습니다.
- **코드 바꾸기**: 코드 옆 연필 버튼을 누르면 **팀 코드 바꾸기** 창이 열립니다. **새 코드**를 입력하고 **코드 바꾸기**를 누릅니다. 작업 담당, 명단, 업무영역, 회의록은 그대로 이어집니다.
- **진척 숨기기**: 작업 열의 **진척** 버튼(눈 모양)을 누르면 **개요**의 **팀별 진척현황**에서 이 팀을 숨기거나 다시 보여 줍니다. **팀별 진척현황** 열에는 **표시** 또는 **숨김**이 나옵니다.
- **비활성으로 바꾸기**: **비활성화**를 누르면 화면에서 팀이 숨겨지고 기존 데이터는 보존됩니다. **상태** 열이 **비활성**으로 바뀌고 같은 자리 버튼이 **활성화**로 바뀝니다. 팀은 삭제하지 않고 비활성으로 둡니다.

> **주의** 코드를 바꾸면 이미 내려받은 엑셀 파일의 팀 열에는 옛 코드가 남습니다. 그 파일을 다시 가져오면 팀 열이 맞지 않을 수 있습니다. 세부업무 이름, 변경 이력, 회의록의 지난 버전에 적힌 옛 코드도 바뀌지 않습니다. 저장해 둔 엑셀 양식의 팀 열은 새 코드로 함께 맞추며, 맞추지 못한 프로젝트가 있으면 알려 줍니다. 코드 바꾸기 창의 경고를 꼭 읽어 보세요.

### 두 팀을 하나로 합치기

팀을 잘못 나눠서 만들었을 때 한 팀을 다른 팀으로 합칩니다.

1. 합쳐서 없앨 팀 행의 **합치기**를 누릅니다. **다른 팀으로 합치기** 창이 열립니다.
2. **합칠 대상 팀**에서 남길 팀을 고릅니다. 다른 활성 팀이 없으면 고를 수 없다는 안내가 나옵니다.
3. 팀을 고르면 **대상 팀으로 옮겨지는 것**이 나옵니다. 작업 담당 몇 건, 명단의 팀 몇 건, 업무영역 담당, 회의록, 회의록 팀 폴더, 수락 전 초대, 연동 자격증명 같은 항목의 개수입니다.
4. 노란 경고를 읽고 **합치기**를 누릅니다. 합쳐지면 `'설계팀' 팀을 '개발팀' 팀으로 합쳤습니다.` 라는 안내가 나옵니다.

> **주의** 합치기는 되돌릴 수 없습니다. 두 팀이 함께 담당하거나 소속이던 곳은 한 줄로 합쳐지고(주관·대표인 쪽이 남습니다), 이름이 같은 회의록 폴더는 합쳐지지 않고 이름 뒤에 옛 팀 이름이 붙습니다. 합친 뒤 옛 팀은 비활성으로 남습니다.

## 업무영역 관리

주간보고 시트의 행이 되는 영역을 관리합니다. **팀·업무영역** 목차의 **업무영역** 카드에서 합니다. 이 카드는 주간보고 기능이 꺼져 있어도 보이지만, 주간보고를 쓰는 프로젝트에서만 의미가 있습니다. 시트에서 한 줄(행)이 업무영역 하나입니다. 업무영역이 하나도 없으면 주간보고 시트를 만들 수 없습니다.

카드 위쪽에는 `업무영역 3개`처럼 개수가 나오고, 오른쪽에 **새 영역** 버튼이 있습니다. 표에는 **순서**, **코드**, **이름**, **담당 팀**, **상태**, **작업** 열이 있습니다. 영역이 하나도 없으면 `아직 업무영역이 없습니다. 영역을 하나 이상 저장해야 주간보고를 시작할 수 있습니다.` 라고 나옵니다.

### 업무영역 만들기

1. **새 영역**을 누릅니다. 표 아래에 입력 상자가 나타납니다.
2. **이름** 칸에 영역 이름을 입력합니다. 예: `설계`, `개발`, `테스트`. **코드** 칸은 이름을 따라 자동으로 채워집니다. 코드를 직접 고치면 그 뒤로는 이름을 따라가지 않습니다.
3. **순서** 칸에 숫자를 입력합니다. 작은 숫자가 위에 옵니다. 0 이상의 정수여야 합니다. 새 영역에는 마지막 번호 다음 값이 미리 들어 있습니다.
4. **담당 팀**에서 이 영역을 맡는 팀을 정합니다. 팀 이름 옆 선택 상자에서 **주**(주 담당) 또는 **보조**(보조 담당)를 고릅니다. 맡지 않는 팀은 `—`로 둡니다.
5. **활성** 칸이 체크된 것을 확인합니다.
6. **저장**을 누릅니다. `'설계' 영역을 저장했습니다.`처럼 영역 코드가 들어간 안내가 나오고, 이번 주 이후 주간 시트에 행이 생겼으면 `이번 주 이후 주간 시트 2곳에 이 영역 행을 더했습니다.` 라고 함께 나옵니다.

### 업무영역 고치기와 비활성

1. 표에서 고칠 영역의 **편집**을 누릅니다. 이름, 순서, 담당 팀, 활성 여부를 고칠 수 있습니다.
2. **저장**을 누릅니다. 그만두려면 **취소**를 누릅니다.

> **주의** 영역 코드는 만든 뒤에 바꿀 수 없습니다. 쓰지 않는 영역은 삭제하지 말고 **활성** 체크를 풀어 비활성으로 두세요. **활성** 체크를 풀면 그 아래에 **비활성으로 두면 이번 주 이후 주간 시트에서 숨겨지고, 이미 쓴 내용은 남습니다.** 라는 안내가 나옵니다. 영역을 지우는 기능은 없습니다.

> **팁** 영역 이름을 바꾸려면 새 영역을 만들기보다 기존 영역의 **편집**에서 이름만 고치세요. 코드가 같아 이전 기록과 이어집니다.

## 이슈 설정

이슈 기능이 켜져 있을 때만 이 절의 카드가 보입니다.

### 이슈 영역

**팀·업무영역** 목차의 **이슈 영역** 카드에서 만듭니다. 사용법은 [업무영역 만들기](#업무영역-만들기)와 같고 다음만 다릅니다.

- 코드는 영문 대문자와 숫자로 1~8자여야 합니다(예: `WEB`, `UI2`).
- 이슈 번호에서 영역을 나타내는 자리에 이 코드가 들어갑니다. 만든 뒤에는 바꿀 수 없습니다.
- 영역이 없으면 `이슈 영역을 추가할 수 있습니다.` 라고 나옵니다.

### 이슈 코드·분석 규칙

**이슈** 목차의 **이슈 코드·분석 규칙** 카드에서 새 이슈에 붙는 번호의 모양을 정합니다. 바꿔도 기존 이슈의 번호는 그대로입니다.

| 칸 | 설명 |
|---|---|
| **접두** | 번호 앞에 붙는 글자. 영문 대문자, 숫자, 하이픈으로 8자 이하입니다. 처음 값은 `ISS`입니다. |
| **패턴** | 번호의 모양. 아래 자리 표시를 섞어 씁니다. 처음 값은 `{prefix}-{seq:3}`입니다. |
| **번호 범위** | **프로젝트 전체**(프로젝트 전체에서 한 줄로 번호를 매김) 또는 **영역별**(영역마다 따로 매김) |
| **번호 초기화** | **초기화하지 않음** 또는 **매년**(해마다 1번부터 다시 시작) |
| **코드 예시** | 지금 입력한 규칙으로 만든 번호의 예가 바로 보입니다. |

패턴에서 쓸 수 있는 자리 표시는 다음과 같습니다.

- `{prefix}`: 접두가 들어갑니다.
- `{area}`: 이슈 영역의 코드가 들어갑니다.
- `{yyyy}`, `{yy}`: 4자리, 2자리 연도가 들어갑니다.
- `{seq:3}`: 일련번호가 들어갑니다. 콜론 뒤 숫자(2~6)는 자리 수이고, 패턴에 정확히 하나가 있어야 합니다.

그 밖에 영문, 숫자, `.` `_` `#` `/` `-`만 쓸 수 있습니다. 예를 들어 접두 `ISS`, 패턴 `{prefix}-{seq:3}`이면 `ISS-001`, `ISS-002`처럼 번호가 매겨집니다.

1. 접두, 패턴, 번호 범위, 번호 초기화를 고르고 **코드 예시**가 원하는 모양인지 확인합니다.
2. 이슈 분석 기능이 켜져 있으면 **분석 분류 입력**이 보입니다. **선택**이면 이슈를 등록할 때 분석 분류를 안 골라도 되고, **필수**이면 꼭 골라야 합니다. 이슈 분석이 꺼져 있으면 이 칸 대신 켜라는 안내가 나옵니다.
3. **저장**을 누릅니다. **이슈 설정을 저장했습니다.** 라고 나옵니다.

> **주의** 규칙이 맞지 않으면 빨간 글씨로 이유가 나옵니다. 영역별 번호는 패턴에 `{area}`가 있어야 하고, 매년 초기화는 `{yyyy}` 또는 `{yy}`가 있어야 합니다. 번호가 40자를 넘을 수 있는 규칙도 저장되지 않습니다.

## 회의록 설정

회의록 기능이 워크스페이스에서 켜져 있을 때 **회의록** 목차에 두 카드가 나타납니다.

### 회의록 첨부 정책

**회의록 첨부 정책** 카드에서 새로 올리는 첨부 파일의 조건을 정합니다. 이미 올린 파일은 지우거나 바꾸지 않고, 바꾼 정책은 이후 첨부에만 적용됩니다.

1. **회의록 첨부 사용**을 체크하면 첨부를 쓸 수 있습니다. **안전 형식 미리보기(이미지·PDF)** 를 체크하면 이미지와 PDF는 화면에서 바로 미리 볼 수 있습니다.
2. **파일당 최대 용량(MB)**, **회의록당 최대 개수**, **회의록당 총 용량(MB)** 를 입력합니다. 서비스가 정한 한도는 파일당 20MB, 회의록당 10개이며 칸 아래에 `운영 상한: 파일당 …MB · 최대 10개`처럼 보입니다. 그보다 크게는 정할 수 없습니다.
3. **허용 형식**에서 **제한 없음** 또는 **목록의 형식만**을 고릅니다. 목록을 고르면 `pdf, png, xlsx`처럼 쉼표로 구분해 입력합니다. 목록이 비어 있으면 모든 첨부가 거부된다는 경고가 나옵니다.
4. **저장**을 누릅니다. **첨부 정책을 저장했습니다.** 라고 나옵니다.

### 외부 업로드 폴더 자동 정리

회의록 연동 프로그램이 회의록과 함께 폴더 경로를 보낼 때, 그 경로대로 회의록을 폴더에 넣을지 정합니다.

1. **보낸 폴더 경로대로 넣기** 오른쪽 스위치 버튼을 눌러 **켜짐** 또는 **꺼짐**으로 바꿉니다. 처음은 켜짐입니다.
2. **저장**을 누릅니다.

켜져 있으면 같은 회의록을 다시 보낼 때 그때의 폴더 경로로 위치가 바뀝니다. 꺼져 있으면 폴더 경로를 받지 않은 것처럼 다뤄서 새 회의록은 담당 팀 폴더에 들어가고, 다시 보낸 회의록은 지금 위치에 그대로 있습니다. 바꾼 뒤의 업로드부터 적용되고 이미 정리된 회의록은 옮기지 않습니다.

## 용어와 분류 고치기

근태 유형, 회의 분류, 이슈 심각도처럼 선택지로 쓰이는 이름을 프로젝트에 맞게 바꿉니다. **용어·분류** 목차에 아래 카드 가운데 해당 기능이 켜진 것만 나옵니다.

| 카드 | 어디에 쓰이나요 | 보이는 조건 |
|---|---|---|
| **근태 유형** | 근태 등록 선택지, 범례, 월 집계 | 근태 기능이 켜져 있을 때 |
| **회의 분류** | 회의 등록 선택지와 색 | 회의 기능이 켜져 있을 때 |
| **이슈 심각도** | 이슈 심각도 선택지, 순위, 색 | 이슈 기능이 켜져 있을 때 |
| **이슈 출처** | 이슈 분석의 출처 분류 | 이슈 분석 기능이 켜져 있을 때 |
| **원인 분류** | 분석서와 AI 분석의 원인 분류 | 이슈 분석 기능이 켜져 있을 때 |

모든 카드는 같은 표를 씁니다. 표 한 줄이 선택지 하나입니다.

### 항목 고치기

1. 카드의 표에서 고칠 줄을 찾습니다. 열은 카드마다 조금씩 다르지만 다음이 기본입니다.
   - **순서**: 위·아래 화살표로 순서를 옮깁니다.
   - **코드**: 만들 때 정한 식별자입니다. 한 번 만들면 바꿀 수 없습니다.
   - **이름**: 화면에 보이는 이름입니다. 1~40자입니다.
   - **짧은 이름**(근태 유형): 표에서 좁게 보일 때 쓰는 이름입니다. 1~10자입니다.
   - **색**: 초록, 파랑, 하늘, 빨강, 보라, 주황, 회색 가운데 고릅니다.
   - **집계 분류**(근태 유형): 근무, 휴가, 출장, 재택, 결근 가운데 고릅니다. 월 집계에서 어떻게 셀지 정합니다.
   - **등록 선택지**(근태 유형): 체크하면 근태를 등록할 때 선택지에 나옵니다.
   - **공지 기본**(회의 분류): 체크하면 이 분류로 새 회의를 만들 때 **이 회의를 공지사항으로도 등록** 칸이 처음부터 체크되어 있습니다. 처음에는 모든 분류가 꺼져 있습니다.
   - **범주**(이슈 상태): **열림**, **진행중**, **보류**, **해결** 가운데 고릅니다.
   - **사용**: 체크를 풀면 새로 고를 수는 없고 기존 기록은 그대로 보입니다.
2. 고친 뒤 표 아래 **저장**을 누릅니다. **저장했습니다.** 라고 나옵니다.

### 항목 추가하기

1. 표 아래 **새 코드(영소문자·숫자·_)** 칸에 코드를 입력합니다. 영소문자로 시작하는 1~20자이고, 영소문자·숫자·밑줄만 쓸 수 있습니다. 예: `training`
2. **새 이름** 칸에 이름을 입력합니다. 비우면 코드가 이름이 됩니다.
3. **추가**를 누르면 표 맨 아래에 새 줄이 생깁니다. 이름, 색 같은 값을 고쳐 줍니다.
4. **저장**을 누릅니다.

### 항목 지우기와 기록 옮기기

줄 끝의 휴지통 버튼으로 지울 수 있습니다. 이미 그 항목을 쓰는 기록이 있으면 저장할 때 `'training' 을(를) 쓰는 기록이 5건 있어 지울 수 없습니다. 다른 항목으로 옮긴 뒤 지우세요.` 같은 안내가 나옵니다. 이때 표 아래에 **기록 옮기기** 줄이 나타납니다.

1. **옮길 대상**에서 기록을 받을 다른 항목을 고릅니다.
2. **기록 옮기기**를 누릅니다. `기록 5건을 옮겼습니다. 이어서 저장하세요.` 라고 나옵니다.
3. 다시 **저장**을 누릅니다. 이번에는 지워집니다.

이슈 상태는 같은 **범주** 안의 다른 상태로만 옮길 수 있습니다. 같은 범주에 옮길 상태가 없으면 `같은 범주의 다른 활성 상태가 없습니다 — 먼저 추가해 저장하거나 이슈를 하나씩 옮기세요.` 라고 나옵니다.

> **주의** 기록이 있는 근태 유형의 **집계 분류**는 바꿀 수 없습니다. 새 항목을 만들어 기록을 옮긴 뒤 바꾸세요. 기록이 있는 이슈 상태의 **범주**도 마찬가지입니다. **원인 분류**는 분석서가 참조하므로 지울 수 없고 **사용**만 끌 수 있습니다. **이슈 출처**의 **회의록** 항목은 회의록에서 만든 이슈가 쓰는 고정 항목이라 지우거나 끌 수 없습니다.

## 보고서 양식 올리기

주간보고, 이슈 분석서, WBS 엑셀 내보내기는 기본 양식으로 만들어집니다. 회사 양식이 따로 있으면 **양식** 목차의 **보고서 양식** 카드에 올려서 대신 쓰게 할 수 있습니다.

종류는 **주간보고 (PPTX)**, **주간보고 (XLSX)**, **이슈 분석 (PPTX)**, **WBS 내보내기 (XLSX)** 입니다. 주간보고 종류는 주간보고 기능이, 이슈 분석 종류는 이슈 분석 기능이 켜져 있을 때 나옵니다. 종류마다 상자가 따로 있고 상자 위에 지금 **기본 양식 사용 중**인지 **사용자 양식 사용 중**인지 표시됩니다.

### 양식 올리기와 켜기

1. 종류별 상자 아래 **새 양식 올리기 (.pptx, 10MB 이하)** 에서 파일을 고릅니다. 종류에 맞는 파일 형식(PPTX 또는 XLSX)만 올릴 수 있습니다.
2. 올리면 바로 등록되고 활성화됩니다. `양식 v1 을 등록하고 활성화했습니다. 보고서에 바로 쓰입니다.` 라는 안내가 나오고 목록에 버전(`v1`), 파일 이름, 크기, **활성** 표시가 나타납니다. 파일에 문제가 있으면 `스캔 오류 1`, `경고 2`처럼 건수가 함께 표시됩니다.
3. 이후 그 종류의 보고서와 내보내기는 활성 양식으로 만들어집니다. 주간보고 화면의 **주간보고서 상세(PPT)** 와 **요약 PPT** 가 같은 양식을 씁니다.

양식 파일 안에 데이터가 들어갈 자리(자리표시자, 아래 참고)가 하나도 없으면 활성화하지 않고 `양식 v1 을 등록했지만 자리표시자({{…}})가 없어 보고서 내용이 들어갈 자리가 없습니다.` 라고 알립니다. 목록에는 `경고 1`로 남습니다. 이때 그대로 **활성화**를 누르면 올린 파일이 내용 없이 그대로 내려옵니다.

### 회사 주간보고 양식을 그대로 올리기 (표 자동 연결)

자리표시자를 넣지 않은 회사 주간보고 PPT 라도, 아래 꼴의 표가 한 장에 있으면 올릴 때 자동으로 연결됩니다.

| 구분 | 금주 실적 | 차주 계획 |
|---|---|---|
| (첫 번째 줄) | | |

- 첫 열 머리글에 **구분·업무영역·영역·팀·항목·부문·분류·과제·업무명·부서** 가운데 하나가 있어야 합니다.
- 내용 두 열은 머리글에 **실적·완료·수행·결과·진척·진행**(금주 실적 자리)과 **계획·예정**(차주 계획 자리)이 있거나, 그 낱말이 없으면 기간 낱말의 순서로 정합니다 — **전주·지난주** → **금주·이번주** → **차주·다음주** 가운데 앞 기간이 실적, 뒤 기간이 계획입니다. 예를 들어 "전주 | 금주" 표는 전주 열에 금주 실적, 금주 열에 차주 계획이 들어가고, "금주 | 차주" 표는 금주 열에 실적, 차주 열에 계획이 들어갑니다.
- 내용 두 열은 가로로 병합된 머리글 아래가 아니어야 하고 표 너비의 15% 이상이어야 합니다. 월~금 요일 칸 위에 "전주/금주"를 적은 일정 격자는 주간 내용 표로 보지 않습니다.
- 그런 표가 여러 장이면 내용 두 열이 가장 넓은 표 하나를 고릅니다.

연결되면 `슬라이드 5의 표에서 "구분"·"전주 (10/05~10/16)"·"금주 (10/19~10/23)" 열을 찾아 업무영역별로 채우도록 연결했습니다.` 처럼 어느 슬라이드의 어떤 머리글을 이었는지 알려줍니다. 보고서를 만들 때는 그 표의 첫 번째 줄이 **업무영역마다 한 줄**로 늘어나고(영역 이름 · 금주 실적 · 차주 계획), 한 장에 5줄을 넘으면 같은 슬라이드가 복제되어 이어집니다. 첫 줄 뒤에 있던 보기용 줄은 지워지고, 첫 줄의 높이는 머리글 줄 높이에 맞춰 내용에 따라 늘어납니다. 그 표가 없는 다른 슬라이드(표지, 인원 현황, 일정 등)는 손대지 않고 그대로 나옵니다.

머리글에 적어 둔 날짜("10/05~10/16")는 글자 그대로 남습니다. 매주 바뀌게 하려면 그 자리에 아래 자리표시자를 직접 넣으세요.

### 자리표시자 직접 넣기

PowerPoint 에서 글자가 들어갈 자리에 `{{데이터 이름}}` 을 적으면 보고서를 만들 때 그 자리에 값이 들어갑니다. 주간보고 PPT 에서 자주 쓰는 이름은 다음과 같습니다.

| 자리표시자 | 들어가는 값 |
|---|---|
| `{{report.project_name}}` | 프로젝트 이름 |
| `{{report.week_label}}` | 주차 라벨 (예: 2026년 10월 2주차 (10/12~10/16)) |
| `{{report.week_range}}` | 보고 주차의 날짜 범위 (예: 10/12~10/16) |
| `{{report.prev_week_range}}` · `{{report.next_week_range}}` | 전주 · 차주의 날짜 범위 |
| `{{kpi.plan}}` · `{{kpi.actual}}` | 계획 공정율 · 실적 공정율 (%) |
| `{{#rows sections}}{{.name}}` | 표의 한 줄을 업무영역마다 복제 — 첫 칸에 적고, 같은 줄의 다른 칸에 아래 둘을 넣습니다 |
| `{{.this_content}}` · `{{.next_content}}` | 그 업무영역의 금주 실적 · 차주 계획 |
| `{{#slide sections}}` | 슬라이드 하나를 업무영역마다 복제 — 슬라이드 안에 `{{.name}}`·`{{.this_content}}`·`{{.next_content}}` 를 씁니다 |
| `{{slide.continuation}}` | 줄이 넘쳐 복제된 슬라이드에만 `(계속)` 표기 |

자리표시자가 하나라도 있는 파일은 표 자동 연결을 하지 않고 적힌 자리표시자만 채웁니다.

### 기본 양식으로 되돌리기

활성 양식 줄의 **해제**를 누르면 `양식을 해제했습니다. 기본 양식으로 돌아갑니다.` 라는 안내가 나오고 기본 양식으로 돌아갑니다. 올린 파일은 목록에 남아 있어 나중에 다시 **활성화**할 수 있습니다.

### 연결되지 않은 자리 표시가 있을 때

양식 파일 안의 자리 표시를 시스템이 읽어 어떤 데이터가 들어갈지 정합니다. 올린 뒤 자동 활성화나 **활성화**를 눌렀을 때 연결되지 않은 자리 표시가 있으면 **미매핑 자리표시자** 상자가 나타납니다. 자리 표시마다 연결할 데이터 이름을 입력하고 **매핑 저장 후 활성화**를 누릅니다. 위 표에 없는 이름은 양식을 만든 분에게 확인하세요.

## 추가 필드 만들기

작업, 이슈, 주간보고 행에 우리 프로젝트만의 정보 칸(예: 고객 요청 번호, 우선도)을 더하는 곳입니다. **추가 필드** 목차에 있습니다.

카드 위쪽의 탭 **WBS**, **이슈**, **주간보고** 로 어느 화면에 붙일 필드인지 고릅니다. 이슈나 주간보고 기능이 꺼져 있으면 그 탭에서는 필드를 관리할 수 없다는 안내가 나옵니다. 그때는 [기능 켜고 끄기](#기능-켜고-끄기)에서 해당 기능을 먼저 켜세요.

### 필드 추가하기

1. 탭을 고르고 목록 아래의 **필드 추가**를 누릅니다. 새 필드가 `새 필드` 이름으로 생기고 오른쪽에 편집 칸이 나타납니다.
2. 다음 칸을 채웁니다.
   - **필드 key**: 영소문자로 시작하는 영문·숫자·밑줄 32자 이하입니다. 저장한 뒤에는 바꿀 수 없습니다.
   - **표시 이름**: 화면에 보이는 이름입니다. 1~40자입니다.
   - **유형**: **한 줄 텍스트**, **여러 줄 텍스트**, **숫자**, **날짜**, **예/아니오**, **단일 선택**, **다중 선택** 가운데 고릅니다.
   - **편집 권한**: **멤버**(멤버 이상이 입력) 또는 **관리자**(관리자만 입력)를 고릅니다.
   - **설명**: 필드의 설명입니다. 300자 이하입니다.
3. 체크 칸으로 동작을 정합니다. **활성**은 지금 쓰는지, **목록 표시**는 목록에 열로 보일지, **검색 포함**은 검색 대상에 넣을지, **필수**는 반드시 입력해야 하는지입니다. 주간보고 탭에는 **다음 주 이월**도 있어, 체크하면 새 주차 시트를 만들 때 이전 주의 값이 이어집니다.
4. 유형에 따라 나타나는 칸을 채웁니다.
   - 텍스트: **최대 글자 수**
   - 숫자: **최솟값**, **최댓값**, **소수 자릿수 (0~4)**, **단위**
   - 단일 선택·다중 선택: **선택지** 목록(**선택지 추가**로 늘리고 각 선택지에 **코드**, **이름**, **색상**, **활성 선택지**를 정함). 다중 선택에는 **최대 선택 개수**도 있습니다.
5. 필요하면 **기본값**을 정합니다. 지우려면 **기본값 비우기**를 누릅니다. **필수**로 만들려면 기본값이 있어야 합니다.
6. **필드 설정 저장**을 누릅니다. **필드 설정을 저장했습니다.** 라고 나옵니다.

필드 순서는 목록에서 끌어다 놓거나 필드 이름 아래의 위·아래 화살표로 바꿉니다. 한 대상(작업, 이슈, 주간보고 행)에 최대 60개까지 만들 수 있고, 그 가운데 **활성**은 30개, **목록 표시**는 8개까지입니다. 넘으면 `활성 필드는 최대 30개입니다.` 또는 `목록 표시 필드는 최대 8개입니다.` 라고 나오고 저장되지 않습니다.

### 이미 값이 있는 필드 다루기

필드를 고르면 **전체 20행 · 값 있음 18행 · 미입력 2행**처럼 사용 건수가 보입니다.

- **기본값으로 채우고 필수로 전환**: 비어 있는 행을 기본값으로 모두 채우고 **필수**로 바꿉니다. 먼저 필드를 저장한 뒤에 쓸 수 있습니다.
- **값과 필드 삭제…**: 필드와 입력된 값을 모두 지웁니다. 지울 값의 건수를 확인 칸(**삭제할 값의 건수**)에 그대로 입력해야 **필드 영구 삭제** 버튼이 켜집니다. 되돌릴 수 없으니 신중하게 누르세요.
- 값이 있는 필드는 지우지 말고 **활성**을 풀어 비활성으로 두면 값을 보존할 수 있습니다.
- 방금 만든 필드를 저장하기 전에 버리려면 **추가 취소**를 누릅니다. 고친 내용을 모두 버리려면 **변경 취소**를 누릅니다.

## 상태와 승인 설정

**상태·승인** 목차에 이슈 상태, 작업 승인 흐름, 에이전트, 상태 계산 방식 안내가 모여 있습니다.

### 이슈 상태

이슈 기능이 켜져 있을 때 **이슈 상태** 카드가 보입니다. 이슈의 표시 상태를 정합니다. 상태마다 **범주**(**열림**, **진행중**, **보류**, **해결**)를 정하고, 범주 사이의 이동은 정해진 규칙을 따릅니다. 새 이슈는 열림 범주의 첫 상태로 시작합니다. 사용법은 [용어와 분류 고치기](#용어와-분류-고치기)의 표와 같습니다.

### WBS 승인 흐름

**WBS 승인 흐름** 카드는 개발 워크플로 대상 작업이 검수를 거쳐 완료되는 방식을 정합니다. 한 카드 안에 두 구역이 있고 각각 **저장** 버튼이 따로 있습니다.

### 단계 이름 고치기

작업이 거치는 단계(**미착수**, **할당됨**, **작업 중**, **검수 대기**, **완료**)의 표시 이름을 우리 프로젝트의 말로 바꿀 수 있습니다. 단계 자체가 바뀌는 것은 아니고 이름만 바뀝니다.

1. **단계 이름** 구역에서 다섯 칸을 봅니다. 각 칸의 연한 글자가 기본 이름입니다.
2. 바꾸고 싶은 칸에 새 이름(1~20자)을 입력합니다. 비워 둔 칸은 기본 이름을 씁니다.
3. 해당 구역의 **저장**을 누릅니다. **저장했습니다.** 라고 나옵니다. 모두 비우고 저장하면 전부 기본 이름으로 돌아갑니다.

### 승인 단계와 승인자 정하기

개발 워크플로 대상 작업은 **검수 대기**에서 **완료**로 가기 전에 승인을 받습니다. 승인은 1~3단계로 나눌 수 있습니다.

1. **승인 단계** 구역의 표에서 단계 줄을 봅니다. 줄마다 **단계 이름**, **승인자**, 위·아래(`↑` `↓`)와 **삭제** 버튼이 있습니다. 처음에는 이름이 비어 있는 기본 단계 하나만 있고 승인자는 **상위 담당자 또는 관리자**입니다. 이름이 비어 있으면 화면에는 **승인**이라고 나옵니다.
2. **승인자**를 고릅니다.
   - **상위 담당자 또는 관리자**: 그 작업 위쪽 항목의 담당자이거나 프로젝트 관리자이면 승인할 수 있습니다.
   - **프로젝트 관리자만**: 프로젝트 관리자만 승인할 수 있습니다.
3. 단계를 더하려면 **단계 추가**를 누릅니다(최대 3개). 새 단계는 승인자가 **프로젝트 관리자만**으로 시작합니다. 새로 추가한 단계에는 이름이 꼭 필요합니다. **단계 코드**는 영소문자로 시작하는 1~20자(영소문자·숫자·밑줄)이고 새 단계에서만 입력할 수 있습니다. 저장한 뒤에는 바꿀 수 없습니다.
4. **단계마다 다른 승인자**를 체크하면 한 검수에서 같은 사람이 두 단계를 승인할 수 없습니다. 처음에는 체크되어 있습니다.
5. **선행 작업 기준**을 고릅니다. 먼저 끝나야 하는 선행 작업을 가진 후속 작업이 언제부터 시작 가능한지를 정합니다.
   - **검수 대기부터 후속 착수(현행)**: 선행 작업이 검수 대기에 도달하면 후속 작업을 시작할 수 있습니다.
   - **최종 승인 뒤 후속 착수**: 선행 작업이 최종 승인을 받은 뒤에 시작할 수 있습니다.
6. **저장**을 누릅니다.

> **주의** 단계 구성과 순서는 다음 검수부터, 이름과 승인자는 바로 적용됩니다. 검수 중인 단계는 지울 수 없고(`'review' 단계로 검수 중인 항목이 3건 있어 지울 수 없습니다. 그 검수가 끝난 뒤 지우세요.`), 승인을 기다리는 항목이 있는 단계의 승인자를 **상위 담당자 또는 관리자**처럼 넓히는 것도 안 됩니다. 이미 시작한 후속 작업은 선행 기준을 바꿔도 되돌리지 않습니다.

### 에이전트 크레딧

**에이전트** 카드에는 에이전트 현황을 보는 **에이전트 페이지에서 관리** 링크와 **개발 워크플로 크레딧**이 있습니다. 에이전트는 AI가 작업을 대신 수행하는 기능이며 자세한 내용은 [에이전트](/help/agents) 장에 있습니다. 에이전트 기능이 꺼져 있다는 안내가 나와도 값은 편집할 수 있고, 다시 켤 때 그대로 쓰입니다.

크레딧은 개발 워크플로 대상 작업의 단계가 바뀔 때 실적%를 자동으로 정하는 값입니다. 처음 값은 **할당됨** 0, **작업 중** 30, **반려·재작업** 50, **검수 대기** 80, **완료** 100입니다.

1. 가로 막대 위의 핸들을 끌거나, 핸들 위의 숫자 칸을 직접 고쳐 값을 정합니다. 키보드로는 핸들을 선택하고 방향키를 누릅니다. **완료**는 100에 자물쇠로 잠겨 있어 고칠 수 없습니다.
2. 막대 아래 **미리보기 · 위임 Task 흐름** 표에서 줄을 눌러 보면 그 단계의 값이 막대에 표시됩니다. **계획 진척** 값을 바꿔 보면 같은 실적이 계획에 비해 진행중인지 지연인지 어떻게 판정되는지 볼 수 있습니다. 미리보기는 저장되지 않습니다.
3. **입력 단위**(1 또는 5)와 **최소 간격**(단계 사이의 최소 차이, 1~10)을 정할 수 있습니다.
4. **변경 내용 검토**를 누르면 바뀌는 값이 나열됩니다. 맞으면 **저장**을 누릅니다.

> **팁** 저장해도 이미 기록된 실적%는 바뀌지 않습니다. 새 값은 다음 단계 이동부터 적용됩니다. 단계 값은 순서대로 커져야 하고 사이 간격은 최소 간격 이상이어야 합니다.

### 프로젝트 상태 관리 안내

**프로젝트 상태 관리** 카드는 안내만 보여 주며 직접 바꾸는 곳이 아닙니다. 작업 상태(시작전, 진행중, 지연, 완료)는 실적·계획·기준일을 비교해 저절로 계산됩니다(**자동 상태 동기화**). 오른쪽 **공정율 기준일 정책**에는 지금 기준일이 **자동 · 오늘**인지 **수동 고정**인지 보입니다. 기준일은 [달력 설정](#달력-설정)에서 정합니다.

## 달력 설정

**달력** 목차의 **달력 — 기준일·주 시작·근무 요일·날짜 예외** 카드에서 일정 계산의 바탕이 되는 값을 정합니다. 새 프로젝트는 만들 때 워크스페이스의 값을 한 번 복사해 시작하고, 이후에는 워크스페이스 값을 바꿔도 이 프로젝트는 바뀌지 않습니다.

### 주 시작·근무 요일·시간대

세 항목은 같은 영역에서 함께 저장합니다.

1. **주 시작**: **일요일** 또는 **월요일**을 고릅니다. 주간보고와 이번 주 보기가 한 주를 시작하는 요일입니다.
2. **근무 요일**: 일하는 요일을 **월**부터 **일**까지 체크합니다. 하나 이상 골라야 합니다.
3. **시간대**: 칸에 `Asia/Seoul`처럼 "지역/도시" 모양의 이름을 입력합니다. 입력하면 아래로 후보 목록이 보입니다. "오늘"이 몇 월 며칠인지와 시각 표시의 기준입니다. 브라우저의 시간대와 다르면 **이 브라우저의 시간대(…)로 제안** 버튼이 나오며, 누르면 그 값이 채워집니다.
4. 영역 맨 아래 **저장**을 누릅니다. `3개 설정을 저장했습니다.` 처럼 몇 개가 저장됐는지 나옵니다.

각 항목 오른쪽 위에는 값의 출처(**프로젝트 설정**, **제품 기본값** 등)와 적용 시점이 보입니다.

| 항목 | 적용 시점 |
|---|---|
| **주 시작** | 다음 주부터 적용됩니다. 지난 주간보고는 그대로입니다. |
| **근무 요일** | 즉시 적용됩니다. 이미 저장된 진척 기록은 다시 계산하지 않습니다. |
| **시간대** | 즉시 적용됩니다. 저장된 날짜는 바뀌지 않습니다. |

### 주 시작을 바꿀 때의 검토

**주 시작**을 바꾸면 라디오 아래에 **변경 내용 검토** 결과가 나옵니다. 예를 들면 `2026-11-02 부터 월요일 시작입니다. 바뀌기 직전 주 하나가 5일입니다(전환 주). 기존 주간보고 12건은 그대로입니다.` 처럼 언제부터 바뀌는지, 기존 주간보고가 몇 건 유지되는지 알려 줍니다.

- 주간보고가 아직 없으면 `주간보고가 아직 없어 저장하면 바로 월요일 시작으로 바뀝니다.` 라고 나옵니다.
- 이미 만든 주간보고가 새 규칙과 맞지 않으면 `이미 만든 주간보고가 새 규칙과 맞지 않아 저장할 수 없습니다.` 와 해당 주차가 나옵니다. 그 주간보고를 정리하거나 다른 시점에 다시 바꾸세요.
- 아직 적용 전인 전환이 예약되어 있으면 `예정: 2026-11-02 부터 월요일 시작`이 보입니다. 지금 적용되는 요일을 다시 고르고 저장하면 예약이 취소됩니다.

검토 결과를 받기 전이거나 저장할 수 없는 변경이면 저장 버튼 옆에 이유가 붉은 글씨로 나옵니다.

### 공정율 기준일

작업의 계획 진척을 계산하는 기준 날짜입니다. 같은 카드 아래쪽 **공정율 기준일 (Base date)** 구역에서 정합니다.

- 아무것도 정하지 않으면 **자동 · 오늘 기준**으로 표시되고 매일 오늘을 기준으로 계산합니다.
- 고정하려면 날짜를 고르고 **적용**을 누릅니다. 표시가 **수동 고정 · 2026-10-01**로 바뀌고 **공정율 기준일을 적용했습니다.** 라고 나옵니다.
- 다시 자동으로 돌리려면 **자동으로**를 누릅니다. **자동(오늘) 기준으로 전환했습니다.** 라고 나옵니다.

> **주의** 기준일을 고정하면 진척 계산 전체가 그 날짜 기준이 됩니다. 며칠이 지나도 값이 바뀌지 않으니 보고용으로 특정 날짜를 맞출 때만 쓰고, 끝나면 **자동으로** 돌려놓으세요.

### 날짜 예외(휴무와 근무)

근무 요일 규칙과 다른 날만 적습니다. 국가 공휴일은 자동으로 들어가지 않으니 쉬는 공휴일은 여기에 **휴무**로 등록해야 합니다. 계획 공정율, 간트, 의존성 일정이 이 날짜를 따릅니다.

| 종류 | 뜻 |
|---|---|
| **휴무** | 쉬는 날입니다. |
| **근무** | 근무 요일이 아닌데 일하는 날입니다. |

1. **날짜 예외 · 휴무와 근무** 구역에서 **날짜**를 고릅니다.
2. **종류**에서 **휴무** 또는 **근무**를 고릅니다.
3. 필요하면 **명칭(선택)** 에 이름을 입력합니다. 예: `창립기념일`
4. **추가**를 누릅니다. **날짜 예외를 저장했습니다.** 라고 나오고 목록에 날짜가 나타납니다.

목록의 각 날짜 오른쪽 휴지통 버튼을 누르면 **날짜 예외를 지웠습니다.** 라고 나오며 삭제됩니다. 같은 날짜를 다시 추가하면 종류와 이름이 새 값으로 바뀝니다.

> **팁** WBS 엑셀 내보내기에는 휴무만 실리고 근무 예외는 빠집니다. 그 파일을 다시 가져와도 이 화면에 등록한 근무 예외는 그대로 남습니다.

## 설정 변경 이력 보기

**기록** 목차의 **설정 변경 이력** 카드에서 누가 언제 어떤 설정을 바꿨는지 볼 수 있습니다. 이력은 읽기 전용이며 여기서 값을 되돌릴 수는 없습니다. 되돌리려면 해당 카드에서 값을 다시 고쳐 저장하세요.

한 줄이 설정 항목 하나의 변경입니다. 줄 맨 앞에는 바뀐 설정의 이름이 한국어로 보입니다. 그 옆에 `개정 12 · 2026-10-14 15:30` 같은 번호와 시각(이 프로젝트의 시간대 기준), `홍길동 · 직접 변경` 같은 바꾼 사람과 출처가 보입니다. 출처는 **직접 변경**, **생성**, **복사**(프로젝트를 만들 때 다른 곳의 값을 복사함), **시스템 변경**처럼 나옵니다. 제품 업데이트 과정에서 옮겨진 값을 가리키는 표시도 있습니다.

1. **변경 전 → 변경 후**를 누르면 줄이 펼쳐지고 **변경 전**과 **변경 후**의 값이 나란히 보입니다.
2. 목록 끝에서 **이전 기록 더 보기**를 누르면 20건씩 더 불러옵니다.
3. **새로고침**을 누르면 처음부터 다시 읽습니다.

기록이 없으면 `설정 변경 기록이 없습니다.` 라고 나옵니다. 불러오지 못하면 `설정 이력을 불러오지 못했습니다. 다시 시도하세요.` 라고 나옵니다.

## 설정에서 보이지 않을 수 있는 항목

설정 화면에는 프로젝트 관리자에게 보이지 않는 카드가 있습니다.

- **공개 범위**: 프로젝트를 **비공개**나 **전체 공개**로 바꾸는 카드입니다(**비공개로 전환**, **전체 공개로 전환**). 프로젝트 관리자라면 누구나 바꿀 수 있습니다. 비공개로 두면 프로젝트 관리자·멤버, 워크스페이스 관리자, 플랫폼 관리자에게만 보입니다. 그 밖의 사람에게는 프로젝트 목록·검색·챗봇·회의록 화면에서 빠지고, 링크(URL)로 열어도 찾을 수 없는 화면(404)이 나옵니다. 화면에서 숨기는 것이며 데이터베이스의 접근 권한을 바꾸지는 않는다고 카드에 적혀 있습니다. 바꾸면 "공개 범위를 변경했습니다."라고 나옵니다.
- **서버 LLM 설정**: AI 기능이 쓰는 언어 모델을 서버 전체에서 고르는 카드입니다. 플랫폼 관리자에게만 보입니다. 프로젝트가 아니라 서버 전체에 적용됩니다.
- **위험 구역**: 프로젝트 삭제입니다. 워크스페이스 관리자(플랫폼 관리자 포함)에게만 보입니다. 프로젝트를 지워야 한다면 [워크스페이스 관리자](/help/workspace-admin) 장의 프로젝트 삭제 안내를 보세요.

## 멤버와 권한 관리

프로젝트에 참여하는 사람과 권한은 **팀 구성** 화면에서 한 곳에서 관리합니다. 화면 제목은 `프로젝트 이름 팀 구성`입니다. 관리자에게는 카드 이름이 **명단 · 권한**으로 보입니다. 관리자가 아닌 사람에게는 같은 표가 **참여자 명단**으로 읽기 전용으로 보입니다.

### 팀 구성 화면 보는 법

**명단 · 권한** 카드는 한 사람이 한 줄입니다. 안내 문구는 다음과 같습니다. `한 사람이 한 행입니다. 팀은 여러 개를 고를 수 있고 대표 팀이 맨 앞에 옵니다. 권한(없음/멤버/관리자)도 같은 행에서 정하고, 행마다 저장합니다. 기록이 있어 삭제할 수 없는 사람은 비활성으로 바꾸세요.`

표의 열은 다음과 같습니다.

| 열 | 내용 |
|---|---|
| **이름** | 사람 이름. 계정이 연결되지 않은 사람에게는 **계정 미연결** 표시가 붙습니다. |
| **이메일** | 이메일. 여기서는 고칠 수 없습니다. |
| **팀** | 소속 팀. 여러 팀을 고를 수 있고 굵은 글씨가 대표 팀입니다. |
| **역할 라벨** | `PL`, `디자이너`처럼 자유롭게 붙이는 역할 이름입니다. |
| **직함** | 직함입니다. |
| **권한** | **없음(조회 전용)**, **멤버**, **관리자** 가운데 하나입니다. |
| **실효 역할** | 실제로 적용되는 권한(**관리자**, **멤버**, **조회 전용**). 워크스페이스 관리자가 명단에 있으면 권한 칸과 관계없이 **관리자**로 표시되고, 권한 칸이 **관리자**가 아니면 **워크스페이스 관리자에서 상속** 이 붙습니다. **비활성** 행은 명단의 권한이 효력이 없어서 워크스페이스 관리자가 아니면 **조회 전용**으로 표시됩니다. |
| **상태** | **활성** 또는 **비활성** |
| (맨 오른쪽) | **저장** 버튼과 삭제(휴지통) 버튼. 표가 가로로 넘쳐도 오른쪽에 붙어 있습니다. |

### 사람 추가하기

1. 표 아래 **사람 추가** 줄에서 이름 칸에 이름을 입력합니다. 이름은 꼭 있어야 하며, 비어 있으면 **사람 추가** 버튼이 눌리지 않고 `이름을 입력하면 추가할 수 있습니다.` 라고 나옵니다.
2. 이메일 칸(**이메일(선택 — 없으면 외부 인력)**)에 이메일을 입력합니다. 로그인 계정이 있거나 곧 만들 사람은 이메일을 넣고, 계정이 없는 외부 인력은 비워 둡니다.
3. **사람 추가**를 누릅니다. 표에 새 줄이 생기고 잠시 강조됩니다.
4. 새 줄에서 팀, 역할 라벨, 직함, 권한을 정하고 줄 오른쪽의 **저장**을 누릅니다.

> **팁** 추가한 뒤에 팀과 권한을 정합니다. 이메일 없이 추가한 사람은 계정이 없는 외부 인력이라 권한을 줄 수 없습니다.

몇 가지 경우에는 안내가 나옵니다.

- 같은 이메일의 사람이 이미 명단에 있으면 `같은 이메일의 사람이 이미 있습니다. 목록에서 선택하세요.` 라고 나오고 `홍길동 선택` 링크가 생깁니다. 누르면 표의 그 줄로 이동합니다.
- 이름만 같은 사람이 있으면 `같은 이름의 사람이 이미 팀 구성에 있습니다(홍길동). 다른 사람(동명이인)이 맞으면 추가를 한 번 더 누르세요.` 라고 나옵니다. 정말 다른 사람이면 한 번 더 누르면 추가됩니다.
- 이메일이 워크스페이스에 이미 있는 사람과 같으면 그 사람이 명단에 올라오고 `기존 인물 홍길동을(를) 추가했습니다.` 라고 나옵니다. 입력한 이름과 다르게 보일 수 있습니다.

### 권한 바꾸기

권한은 사람 줄의 **권한** 칸에서 고릅니다.

| 선택 | 뜻 |
|---|---|
| **없음(조회 전용)** | 명단에는 있지만 볼 수만 있습니다. |
| **멤버** | 일반 사용자 권한으로 일합니다. |
| **관리자** | 프로젝트 관리자 권한입니다. 워크스페이스 관리자 이상만 고를 수 있습니다. |

1. 고칠 사람의 줄에서 **권한** 칸을 눌러 새 권한을 고릅니다.
2. 줄 오른쪽의 **저장**을 누릅니다. 변경한 줄만 저장됩니다. 다른 줄은 따로 저장해야 합니다.

저장하지 않은 채 다른 화면으로 가려 하면 `저장하지 않은 변경사항이 있습니다. 나가시겠습니까? 변경사항은 취소됩니다.` 라는 확인 창이 나옵니다.

> **주의** **관리자** 권한을 주거나 회수하는 일은 워크스페이스 관리자만 할 수 있습니다. 프로젝트 관리자에게는 **관리자** 선택지가 `(워크스페이스 관리자 전용)` 이라고 적혀 눌리지 않습니다. 이미 관리자인 사람의 줄은 이름·팀·역할 라벨·직함까지 읽기 전용이 되고 `관리자 행은 워크스페이스 관리자만 수정할 수 있습니다.` 라고 표시됩니다. 화면이 오래되어 선택지가 남아 있다가 저장이 거절되는 경우에는 `관리자 권한은 워크스페이스 관리자만 부여·회수할 수 있습니다.` 라는 안내가 나옵니다. 관리자 권한이 필요하면 워크스페이스 관리자에게 요청하세요.

> **주의** 프로젝트 관리자 본인의 줄도 관리자 줄이라 읽기 전용입니다. 내 이름·팀·직함을 바꾸거나 권한을 내려놓으려면 워크스페이스 관리자에게 요청하세요. 화면이 오래되어 저장이 거절되면 `본인의 권한은 회수할 수 없습니다.` 라는 안내가 나올 수 있습니다.

권한을 받으려면 사람에게 로그인 계정이 있어야 합니다. 계정이 없는 사람에게 권한을 주려 하면 `계정이 연결되지 않은 사람에게는 권한을 줄 수 없습니다. 이메일로 초대하거나 계정을 먼저 만드세요.` 라고 나옵니다.

### 팀 지정하기

1. 사람 줄의 **팀** 칸을 누르면 이 프로젝트의 팀 목록이 펼쳐집니다.
2. 소속시킬 팀을 체크합니다. 여러 팀을 체크할 수 있습니다.
3. 대표 팀을 정하려면 팀 오른쪽의 **대표** 동그라미를 누릅니다. 대표 팀은 칸에서 맨 앞에 굵게 나옵니다.
4. 목록 밖을 누르거나 Esc를 눌러 닫고, 줄 오른쪽 **저장**을 누릅니다.

팀이 없으면 칸에 **팀 없음**, 목록에는 `이 프로젝트에 팀이 없습니다.` 라고 나옵니다. 먼저 [팀 관리](#팀-관리)에서 팀을 만드세요. 이 프로젝트에서 고를 수 없는 팀을 지정하면 `이 프로젝트에서 고를 수 있는 팀이 아닙니다.` 라고 나옵니다.

### 계정 없는 외부 인력

로그인 계정이 없는 사람도 명단에 올릴 수 있습니다. 이메일 없이 **사람 추가**로 넣으면 됩니다. 이런 사람에게는 **계정 미연결** 표시가 붙습니다.

- 근태와 회의 참석자의 기준이 되는 명단에 오를 수 있습니다.
- 로그인을 하지 않으므로 권한을 받을 수 없습니다. 권한 칸의 **멤버**와 **관리자**가 눌리지 않고 `로그인 계정과 연결되지 않은 사람입니다. 계정이 있어야 권한을 줄 수 있습니다.` 라고 나옵니다.
- 나중에 이 사람에게 계정이 필요해지면 [이메일로 초대하기](#이메일로-초대하기)로 초대합니다. 이메일이 없던 줄에는 계정이 붙지 않고, 합류하면 명단에 새 줄이 생깁니다. 그 뒤 옛 외부 인력 줄은 **비활성**으로 바꾸거나 삭제하세요.

### 비활성으로 바꾸기와 삭제하기

- **비활성으로 바꾸기**: 줄의 **활성** 체크를 풀고 **저장**합니다. 줄이 흐려지고 **상태**가 **비활성**이 됩니다. 기록은 그대로 남습니다.
- **삭제하기**: 줄 끝의 휴지통 버튼을 누르면 **팀 구성에서 삭제** 창이 열립니다. `홍길동 님을 이 프로젝트의 팀 구성에서 삭제합니다. 이 프로젝트의 권한도 함께 사라지며 되돌릴 수 없습니다.` 라고 나옵니다. **삭제**를 누르면 지워집니다.

> **주의** 근태, 담당, 회의 참석 기록이 있는 사람은 삭제되지 않고 `담당·참석 기록이 있는 사람은 삭제할 수 없습니다. 비활성으로 바꾸세요.` 라고 나옵니다. 관리자 권한이 있는 사람은 워크스페이스 관리자만 명단에서 삭제할 수 있습니다.

### 이메일로 초대하기

아직 이 서비스에 계정이 없거나 이 프로젝트에 아직 없는 사람을 이메일로 초대할 수 있습니다. 같은 카드 아래쪽 **초대 링크** 구역에서 합니다.

> **주의** 합류한 사람은 이 프로젝트뿐 아니라 전체 회의록·WBS·이슈·근태를 조회할 수 있습니다. 신뢰할 수 있는 인원에게만 발급하세요.

초대 허용 이메일 도메인이 비어 있으면 구역 위에 `초대 허용 도메인이 비어 있어 지금은 초대를 보낼 수 없습니다.` 라는 노란 안내가 나옵니다. 워크스페이스 관리자에게는 **워크스페이스 설정 열기** 링크도 나옵니다. 프로젝트 관리자는 워크스페이스 관리자에게 도메인 설정을 요청하세요.

1. **이메일** 칸에 초대할 사람의 이메일을 입력합니다.
2. **권한**을 고릅니다. **없음(조회 전용)**, **멤버**가 있고, 워크스페이스 관리자 이상(플랫폼 관리자 포함)에게는 **관리자**도 나옵니다.
3. 필요하면 **역할 라벨**(예: `PL`)을 입력합니다.
4. **팀**에서 소속시킬 팀을 고릅니다. 첫 팀이 대표 팀입니다. 비워 두면 팀 없이 초대되고 팀은 나중에 정합니다.
5. **유효기간(일)** 을 정합니다. 처음 값은 7일이고 1~30일 사이여야 합니다.
6. **초대 보내기**를 누릅니다.

결과는 두 가지입니다.

- 메일이 갔으면 `초대 메일을 보냈습니다.` 라고 나옵니다. 이미 계정이 있는 주소라면 `이미 계정이 있는 주소라 로그인 후 합류하게 됩니다.` 라고 함께 나옵니다.
- 메일이 가지 않았으면 `초대는 만들었지만 메일 발송에 실패했습니다. 링크를 복사해 전달해 주세요.` 라고 나옵니다.

초대를 보내면 아래에 초대 링크 상자가 나타납니다. **링크 복사**를 눌러 복사한 뒤 직접 전달할 수도 있습니다. 복사하면 버튼이 **복사됨**으로 잠시 바뀝니다. 복사에 실패하면 칸의 글자를 직접 선택해 복사하세요. 닫으려면 **닫기**를 누릅니다.

> **주의** 초대 링크는 발급한 직후 한 번만 보입니다. 상자를 닫거나 새로고침하면 같은 링크를 다시 볼 수 없습니다. 메일이 닿지 않았다면 지금 복사해서 전달하세요. 다시 보내야 하면 초대를 취소하고 새로 발급합니다.

받은 사람이 링크로 합류하면 이 프로젝트 명단에 선택한 팀(첫 팀이 대표)으로 오르고, 이미 명단에 있는 사람이면 기존 팀은 그대로 남고 이 팀이 더해집니다.

이메일 주소가 허용 도메인이 아니면 `허용된 이메일 도메인(@example.com)으로만 초대할 수 있습니다.` 라고 나옵니다. 같은 주소로 보낸 초대가 아직 유효하면 `이 주소로 발급한 초대가 아직 유효합니다. 취소 후 다시 보내세요.` 라고 나옵니다.

### 초대 취소하기

보낸 초대는 구역 아래 표에서 확인합니다. 열은 **이메일**, **권한**, **팀**, **상태**, **만료**, **합류**입니다. **상태**는 **유효**, **합류 완료**, **취소됨**, **만료됨** 가운데 하나입니다.

1. 취소할 초대 줄의 **취소**를 누릅니다(유효한 초대와 만료된 초대에만 나옵니다).
2. **초대 취소** 창에서 대상 이메일을 확인하고 **초대 취소**를 누릅니다. **초대를 취소했습니다.** 라고 나옵니다. 이미 합류한 사람에게는 영향이 없습니다.

> **팁** 만료된 초대가 남아 있으면 같은 주소로 다시 보낼 수 없습니다. 만료된 줄을 취소한 뒤 다시 발급하세요.

## WBS를 엑셀로 가져오기

이미 엑셀로 관리하던 작업 목록과 일정을 한 번에 작업 계획으로 옮기는 마법사입니다. 프로젝트 관리자만 쓸 수 있습니다. 관리자가 아닌 사람이 열면 **임포트 권한이 없습니다** 안내가 나옵니다.

마법사는 세 단계(**파일 선택** → **확인 및 실행** → **결과**)로 이어집니다. 맨 위 단계 표시에서 끝낸 단계를 눌러 앞 단계로 돌아갈 수도 있습니다. 진행 상황은 그대로 유지됩니다. 결과 단계가 되면 돌아갈 수 없습니다.

### 가져오기 전에 준비할 것

1. **설정**의 **일반** 목차에서 **WBS 데이터 가져오기 · 내보내기** 카드를 찾아 **가져오기 마법사 열기**를 누릅니다. 작업 계획이 비어 있다면 작업 계획 화면의 **엑셀로 가져오기**를 눌러도 됩니다.
2. 화면 제목이 `프로젝트 이름 임포트 마법사`로 열립니다.
3. 화면 위쪽에 탭이 두 개 있습니다. 처음에는 **WBS 마크다운 (wbs.md)** 이 선택되어 있습니다. 엑셀을 쓸 때는 **엑셀 (.xlsx)** 탭을 누릅니다. 마크다운 탭은 [마크다운 문서 올리기](#마크다운-문서-올리기)를 보세요.
4. 처음이라면 **양식 다운로드 (.xlsx)** 를 눌러 양식을 받아 채우는 것이 가장 쉽습니다. 기존 엑셀 파일도 구조를 자동으로 알아봅니다.

양식 파일 `wbs-양식.xlsx`에는 시트가 세 개 있습니다.

| 시트 | 내용 |
|---|---|
| **WBS** | 작업 목록. 머리글은 **코드**, **업무명**, **업무영역**, **산출물**, **시작일**, **종료일**, **가중치**, **실적%**, **담당** 입니다. 예시 행이 들어 있으니 지우고 실제 항목을 넣습니다. |
| **Holiday** | 회사 휴일(날짜, 이름)을 적는 시트. 기본으로 들어 있는 휴일은 없습니다. |
| **작성법** | 작성 규칙 안내. 지워도 됩니다. |

작성 규칙은 양식의 **작성법** 시트에 자세히 있고 핵심은 다음과 같습니다.

- 시트 이름 **WBS**, **Holiday**와 머리글 이름은 바꾸지 않습니다.
- 계층은 **코드** 열에 번호(`1`, `1.1`, `1.1.1`)로 나타냅니다.
- 가져오기는 단수에 제한을 두지 않고 코드에 적힌 단수대로 읽습니다(예: `1.1.1.1`은 4단). 프로젝트의 WBS 단계 이름은 최대 10개까지 정할 수 있으니 단수를 그 개수에 맞추세요.
- 날짜는 날짜 셀이나 `2026-09-01` 같은 글자로 적습니다. 상위 행의 기간은 하위 행을 덮도록 적습니다.
- 가중치는 화면과 같은 % 값으로 적고(50 또는 50%) 형제 항목끼리의 비율로 쓰입니다. 비우면 형제가 똑같이 나눕니다.
- **담당** 열에는 팀 이름(또는 코드)을 적습니다.
- **실적%** 는 비워 둡니다. 진도는 프로젝트 안에서 관리합니다.

### 1단계 파일 선택과 분석

1. 점선 상자의 **엑셀 파일 선택**을 눌러 `.xlsx` 파일을 고릅니다. 다른 형식은 올릴 수 없습니다. 파일을 고르면 상자에 파일 이름이 나옵니다.
2. 오른쪽 아래 **양식 분석하기**를 누릅니다. 버튼이 **분석 중…** 으로 바뀝니다.
3. 파일이 정상이면 2단계로 넘어갑니다. 실패하면 상자 아래 붉은 글씨로 이유가 나옵니다. 파일을 고치거나 다른 파일을 고르세요.

### 2단계 확인과 실행

마법사가 파일에서 자동으로 찾아낸 열 구조가 화면에 채워져 있습니다. 미리보기 표를 보면서 맞는지 확인하고 필요하면 고칩니다. 값을 바꾸면 아래 미리보기 표가 바로 갱신됩니다.

**자동 감지 확인이 필요합니다** 라는 주황 상자가 나오면 마법사가 확신하지 못한 부분이 목록으로 나온 것입니다. 하나씩 확인하세요.

위쪽의 **감지 결과 사용** 버튼은 내가 열을 고친 것을 모두 버리고 파일에서 감지한 값으로 되돌립니다.

**계층 방식**

작업의 깊이를 어떻게 읽을지 고릅니다.

- **열 = 계층**: 왼쪽부터 오른쪽으로 얕은 단계 순서입니다. 한 행에 하나의 열만 채워집니다. 이 방식을 고르면 **계층 열**에서 계층으로 읽을 열을 체크합니다. 체크한 열 가운데 왼쪽 열이 가장 얕은 단계입니다.
- **아웃라인 코드**: `1.2.3` 같은 번호 열로 깊이를 판단합니다. 이 방식을 고르면 **코드(아웃라인) 열**과 **이름 열**을 고릅니다.

계층 열이나 이름 열이 비어 있으면 `계층 열을 하나 이상 골라야 실행할 수 있습니다.` 또는 `이름 열을 골라야 실행할 수 있습니다.` 라고 나오고 **가져오기 실행**이 눌리지 않습니다.

**논리 열 매핑**

**업무영역(Biz)**(프로젝트에서 [추가 축 이름](#추가-축-이름-바꾸기)을 정했다면 그 이름으로 나옴), **코드**, **산출물**, **시작일**, **종료일**, **가중치**, **실적%** 가 파일의 어느 열인지 고릅니다. 해당하는 열이 없으면 **사용 안 함**을 고릅니다.

**담당 마크 사전**

엑셀에서 담당을 `●`, `△` 같은 기호로 표시했을 때 그 기호의 뜻을 정하는 곳입니다. 줄마다 **마크 문자**(4자 이하)와 **마크 종류**(**주관** 또는 **지원**)를 정합니다. **마크 추가**로 줄을 더하고 휴지통으로 지웁니다.

**가져오기 방식**

- **추가(append)**: 기존 WBS는 그대로 두고 새 항목을 맨 뒤에 더합니다. 기존 항목의 번호는 바뀌지 않습니다.
- **전체 교체(replace)**: 현재 트리를 지우고 파일 내용으로 다시 채웁니다. [전체 교체 때 꼭 알아 둘 점](#전체-교체-때-꼭-알아-둘-점)을 먼저 읽으세요.

**이 양식을 프로젝트 기본값으로 저장**

체크하면 이번에 정한 열 구조가 프로젝트에 저장되어 다음 가져오기와 엑셀 내보내기가 같은 양식을 씁니다. 파일 구조를 확실히 감지하지 못한 경우에는 `이 파일의 구조를 확실히 감지하지 못했습니다 — 열 지정을 직접 고치지 않으면 양식은 저장되지 않습니다.` 라는 안내가 나옵니다.

저장된 양식이 이미 있는데 이번 파일의 열 구조와 다르면 붉은 상자 **저장된 양식과 이 파일의 열 구조가 다릅니다**가 나옵니다. 어느 항목이 다른지가 목록으로 나오고, 기본으로는 파일에서 감지한 구조로 읽습니다. 저장된 양식으로 읽으려면 **저장된 양식 사용**을 눌러 직접 고르세요. 저장된 양식이 더는 맞지 않으면 상자 아래 **프로젝트 설정 열기** 링크로 가서 [저장된 양식 비우기](#엑셀로-내보내기와-저장된-양식-비우기)를 합니다.

**그 밖의 안내**

- **새로 만들 팀 3개**: 파일에 있지만 이 프로젝트에 없는 팀 이름입니다. 실행하면 등록할지 한 번 더 묻습니다. 기존 팀을 뜻한다면 파일의 팀 이름을 그 팀의 이름이나 코드로 고치세요.
- **건너뜀(특정일 근무와 충돌)**: Holiday 시트의 날짜가 이 프로젝트에 근무일로 등록된 날과 겹쳐 휴일로 바꾸지 않은 날짜입니다. 쉬는 날로 바꾸려면 [날짜 예외](#날짜-예외휴무와-근무)에서 종류를 **휴무**로 고치세요.
- `이름도 값도 없는 행 4개는 건너뜁니다.` 라는 안내가 나올 수 있습니다.

### 미리보기를 확인하고 실행하기

**미리보기(상위 10행)** 표를 봅니다. 첫 열 **깊이**는 읽은 깊이이고, 머리글 밑 작은 글씨는 각 열이 어떻게 읽혔는지(**계층**, **팀: 설계팀**, **추가 필드: …**, **업무영역(Biz)** 등)를 알려 줍니다. 값이 제 열에 있는지 꼭 확인하세요. 이곳이 실행 전 마지막 확인 지점입니다.

1. 모든 확인이 끝나면 오른쪽 아래 **가져오기 실행**을 누릅니다. 버튼이 **실행 중…** 으로 바뀝니다.
2. 파일에 오류가 있으면 실행되지 않고 `데이터 오류 3건을 확인하세요`와 `엑셀 12행: …`처럼 행 번호가 있는 목록이 나옵니다. 엑셀 파일을 고쳐서 다시 올리거나 **처음부터 다시**를 눌러 1단계로 돌아갑니다.
3. 새 팀이 있으면 **등록되지 않은 팀이 있습니다** 창이 열립니다. 팀 이름이 나열되고 `이 팀들을 등록하시겠습니까? 등록 후 가져오기를 계속 진행합니다.` 라고 나옵니다. **등록하고 계속**을 누르면 이 프로젝트의 팀으로 등록되고 가져오기가 이어집니다. 그만두려면 **취소**를 누릅니다.
4. 이 프로젝트가 공용 팀을 상속하고 있으면 같은 창에 `이 프로젝트는 지금 공용 팀 2개를 씁니다. 등록하면 그 팀들을 같은 코드·이름·색의 이 프로젝트 팀으로 전환하고 …` 라는 설명과 전환될 공용 팀 목록이 나옵니다. 전환은 되돌릴 수 없으니 읽고 결정하세요.

### 3단계 결과 확인

성공하면 **가져오기 완료**와 `42건을 반영했습니다` 가 나옵니다. 화면에서 확인할 것은 다음과 같습니다.

- **실행 ID**: 이 실행을 구별하는 8글자(영문·숫자) 표시입니다. 옆의 **실행 기록 보기**를 누르면 [실행 기록](#실행-기록-보기)이 열립니다.
- **방식**: **추가(append)** 또는 **전체 교체(replace)**
- **AI 색인 갱신**: 갱신된 문서 수
- **프로파일 저장**: 열 구조 양식이 **저장됨**인지 **저장 안 함**인지
- 주황 상자 **양식은 저장되지 않았습니다**: 가져오기는 끝났지만 양식 저장은 실패했다는 뜻입니다. 다음 가져오기에서 양식 저장을 다시 체크하면 저장됩니다.
- 주황 상자 **확인해야 할 사항**: 가져오기는 됐지만 확인이 필요한 경고 목록입니다.
- `이름도 값도 없는 행 4개를 건너뛰었습니다.`
- 같은 실행을 다시 보냈다면 **이미 처리된 실행입니다** 라고 나오고 처음 실행의 결과를 보여 줍니다.
- **프로파일로 내보내기(펼침)**: 방금 쓴 양식에 세부업무 열을 끼워 별도 행으로 펼친 엑셀을 내려받습니다.

그 아래 **WBS 화면으로 이동**을 누르면 작업 계획에서 결과를 볼 수 있습니다. 파일을 하나 더 가져오려면 **다른 파일 가져오기**를 누릅니다.

### 전체 교체 때 꼭 알아 둘 점

**전체 교체(replace)** 를 고르면 빨간 상자 **전체 교체는 되돌릴 수 없습니다**가 나옵니다.

- 현재 WBS 항목 몇 개를 전부 삭제한 뒤 파일 내용으로 다시 채웁니다.
- 변경 이력은 함께 삭제되며 백업에도 포함되지 않아 복구할 수 없습니다.
- 회의록 문단과 작업 사이의 연결(작업 상세의 **회의록 원문**)도 함께 지워지고, 백업에도 포함되지 않아 되살릴 수 없습니다. 이 내용은 빨간 상자와 실행 결과 양쪽에 나옵니다.
- 휴일은 삭제되지 않고 갱신만 됩니다.

전체 교체는 실행 전에 지금 작업 계획의 백업 파일을 내려받아야만 실행할 수 있습니다.

1. **실행 전 백업** 줄의 **실행 전 백업 받기**를 누릅니다. **백업 받는 중…** 을 거쳐 **백업 파일 내려받기를 시작했습니다. 파일을 확인한 뒤 실행하세요.** 라는 안내가 나옵니다.
2. 내려받은 백업 파일을 안전한 곳에 보관합니다.
3. **가져오기 실행**이 켜지면 누릅니다.
4. 실행이 끝나면 교체 직전의 백업을 한 번 더 내려받습니다.

> **주의** 파일, 양식, 방식, 양식 저장 여부를 바꾸면 백업을 다시 받아야 합니다. 백업을 받지 못하면 `백업을 받지 못해 실행할 수 없습니다` 라고 나오고 실행되지 않습니다. 화면에는 백업 파일로 되돌리는 버튼이 없습니다. 백업은 복구가 필요할 때를 대비한 보관용이니 실행 전에 꼭 받아 두세요.

> **팁** 되돌릴 수 있는지 걱정되면 **추가(append)** 로 먼저 시험하세요. 추가 방식은 기존 항목을 건드리지 않습니다. 잘못 들어온 항목은 작업 계획에서 그 항목을 열어 삭제할 수 있습니다.

### 자주 나오는 오류

| 화면 안내 | 해결 방법 |
|---|---|
| `먼저 파일을 선택하세요` | `.xlsx` 파일을 고른 뒤 **양식 분석하기**를 누릅니다. 파일을 고르기 전에는 **양식 분석하기**가 눌리지 않습니다. |
| `양식 분석에 실패했습니다` | 파일이 엑셀(`.xlsx`)이 맞는지, 시트와 머리글이 있는지 확인합니다. |
| `네트워크 오류가 발생했습니다. 잠시 후 다시 시도하세요.` | 인터넷 연결을 확인하고 다시 누릅니다. 실행 중에 이 안내가 나왔다면 서버에서 이미 적용됐을 수 있으니, 같은 파일로 다시 누르면 같은 실행으로 인식해 중복 적용하지 않습니다. |
| `데이터 오류 N건을 확인하세요` | 아래에 나오는 `엑셀 N행: …` 목록을 보고 엑셀 파일의 해당 행을 고칩니다. 날짜 형식, 실적% 범위, 가중치가 음수인 경우, 이름이 빈 행 등이 해당합니다. |
| **저장된 양식과 이 파일의 열 구조가 다릅니다** | 감지한 구조로 읽는 것이 기본입니다. 저장 양식이 낡았다면 [저장된 양식 비우기](#엑셀로-내보내기와-저장된-양식-비우기)를 합니다. |
| **자동 감지 확인이 필요합니다** | 안내된 열 매핑을 확인하고 고칩니다. |

### 실행 기록 보기

**실행 기록 보기**를 누르면 같은 화면 위쪽에 **실행 기록** 상자가 열립니다. **실행 ID**, **방식**, **처리 건수**, **실행 시각**이 나옵니다. 실행 기록은 그 가져오기를 실행한 관리자에게만, 실행한 프로젝트에서만 보입니다. 다른 관리자의 기록이나 다른 프로젝트의 기록을 열면 `이 프로젝트에서 그 실행 기록을 찾지 못했습니다` 라고 나옵니다.

### 마크다운 문서 올리기

마법사의 **WBS 마크다운 (wbs.md)** 탭은 에이전트용 작업 문서(`wbs.md`)를 올리는 곳입니다. 개발 문서를 이 형식으로 관리하는 팀이 쓰는 고급 기능이고, 일반적인 엑셀 가져오기와 다릅니다.

1. **파일 선택**을 눌러 `.md` 파일을 고릅니다.
2. 미리보기 카드에서 **종류**(**골격** 또는 담당 파트별 문서), **부착 위치**, **WBS 단계**(**새로 정함** / **프로젝트 단계와 일치** / **프로젝트 단계와 불일치**), **신규 / 갱신** 건수를 확인합니다. 파일에 적힌 부착 위치로 자동으로 붙을 곳을 정합니다. 부착 위치가 없는 골격 파일은 이 프로젝트의 WBS 단계 이름을 처음 정합니다.
3. `검증 에러 N건 — 적용 불가`가 나오면 적용할 수 없습니다. 파일을 고쳐 다시 올립니다. 경고는 적용은 가능합니다.
4. 문제가 없으면 **적용**을 누릅니다. **취소**를 누르면 선택을 지웁니다. 적용되면 `적용 완료 — 30건 반영, 주문 5건 발행` 같은 결과가 나옵니다. 주문은 에이전트에게 맡긴 작업 지시입니다.

에이전트를 끈 프로젝트에서는 작업 지시가 발행되지 않을 수 있고, 안내가 나옵니다. 자세한 내용은 [에이전트](/help/agents) 장을 보세요.

## 엑셀로 내보내기와 저장된 양식 비우기

**설정**의 **일반** 목차 **WBS 데이터 가져오기 · 내보내기** 카드 아래쪽에는 내보내기와 양식 비우기가 있습니다.

### Excel 내보내기

1. **Excel 내보내기**를 누릅니다. 버튼이 **내보내는 중…** 으로 바뀌고 엑셀 파일이 내려받아집니다.
2. 버튼 왼쪽에 어떤 양식으로 만들어지는지 표시됩니다. **표준 양식(프로젝트 팀·단계로 생성)** 이면 프로젝트의 팀과 단계 이름으로 만들고, **저장된 양식(임포트 마법사, 2026-10-01)** 이면 가져오기 때 저장한 열 구조로 만듭니다.

현재 WBS, 일정, 담당, 실적을 내려받으며 같은 형식으로 다시 가져올 수 있습니다. 내보내기에 실패하면 `내보내기에 실패했습니다` 와 함께 이유가 나옵니다. 이유별 해결 방법은 다음과 같습니다.

| 안내 | 해결 |
|---|---|
| WBS 단계 이름 설정이 손상되었거나 없어 내보낼 수 없습니다 | [WBS 단계 이름 정하기](#wbs-단계-이름-정하기)에서 단계 이름을 확인하고 저장합니다. |
| 프로젝트 달력 설정이 손상되어 내보낼 수 없습니다 | [달력 설정](#달력-설정)에서 값을 고칩니다. |
| 저장된 엑셀 양식이 손상되었습니다 / WBS가 저장된 엑셀 양식의 계층 열보다 깊습니다 | **저장된 양식 비우기**를 합니다. |
| 서버에서 엑셀 파일을 만들지 못했습니다 | 잠시 뒤 다시 시도합니다. |

### 저장된 양식 비우기

저장된 엑셀 양식이 있을 때만 카드 맨 아래에 **저장된 양식 비우기**가 나타납니다. 양식이 손상됐거나 WBS 단계와 맞지 않아 내보내기가 막힐 때 씁니다.

1. **저장된 양식 비우기**를 누릅니다. **저장된 엑셀 양식을 비울까요?** 확인 창이 열립니다.
2. 내용을 읽고 **비우기**를 누릅니다. **저장된 양식을 비웠습니다** 라고 나옵니다.

비우면 다음 가져오기는 파일에서 감지한 구조로 시작하고, Excel 내보내기는 표준 양식으로 만듭니다. WBS 데이터는 바뀌지 않습니다. 되돌리려면 가져오기 마법사에서 양식 저장을 다시 체크해야 합니다.

## 작업 계획에서 관리자만 하는 조작

**작업 계획** 화면의 자세한 사용법은 [WBS 작업 계획](/help/wbs) 장에 있습니다. 여기서는 프로젝트 관리자에게만 열려 있는 조작을 모아 설명합니다. 일반 멤버는 이 가운데 일부(담당 작업의 실적% 입력, 산출물 입력 등)만 할 수 있습니다.

### 작업을 직접 추가하기

1. 화면 오른쪽 위의 **작업 추가**를 누릅니다(보드 보기에서는 나타나지 않습니다). 작업이 하나도 없을 때는 빈 화면 가운데에도 **작업 추가**와 **엑셀로 가져오기** 버튼이 있습니다.
2. 표 위에 `새 단계 이름 (예: 1. 준비)` 입력칸이 열립니다. 칸의 이름은 프로젝트의 1단계 이름을 따릅니다. 이름을 입력합니다(200자 이하).
3. Enter 또는 **추가**를 누릅니다. 최상위 항목이 추가되고 `단계 항목을 추가했습니다` 라고 나옵니다. 같은 이름이 이미 있으면 중복일 수 있다는 안내가 함께 나옵니다. 그만두려면 Esc 또는 **취소**를 누릅니다.

### 하위 작업 추가, 순서 바꾸기, 삭제

1. 작업 이름을 누르면 오른쪽에 상세 패널이 열립니다.
2. 패널 아래쪽의 **구조 편집** 상자를 찾습니다.
   - **하위 추가**: 이 항목 아래에 새 항목을 만듭니다. 이름을 입력하고 **추가**를 누릅니다. 하위 항목이 없던 항목에 처음 하위를 더하면, 그 항목에 입력해 둔 실적%가 하위 항목에서 계산한 값으로 대체된다는 경고가 나옵니다.
   - **팀 분담 항목 추가**: 담당 팀별로 세부 항목을 나눕니다. **담당 팀**과 **역할**(**주관** 또는 **지원**)을 고르고 **추가**를 누릅니다. 모든 팀이 이미 추가되어 있으면 안내가 나옵니다.
   - 위·아래 화살표(**위로 이동**, **아래로 이동**): 같은 형제 사이에서 순서를 바꿉니다.
   - **삭제**: 항목을 지웁니다. 확인 줄에 `하위 5건과 변경 이력·첨부·의존성까지 삭제되며 되돌릴 수 없습니다. 계속할까요?` 라고 나옵니다. 한 번 더 **삭제**를 눌러야 지워집니다.
3. 패널 위쪽 연필 버튼(**편집**)으로 이름, **계획시작**, **계획종료**, **산출물**을 고칩니다. **저장**을 누릅니다.

### 가중치와 일정 고치기

- **가중치**: 표의 가중치 칸을 눌러 % 값을 입력합니다. 비우면 형제의 남은 몫을 똑같이 나눕니다. 형제의 가중치 합이 이미 100% 이상이면 비운 항목의 몫이 0이 되어 진척에 반영되지 않으니 `남은 몫 없음` 안내를 보고 다시 나눕니다.
- **일정**: 상세 패널의 연필 버튼(**편집**)에서 **계획시작**, **계획종료**를 고치거나, 간트 막대를 끌어서 옮깁니다. 막대를 옮기면 **간트 일정 변경 검토** 창이 열려 원래 일정과 변경 예정 일정, 선행·후행 작업에 주는 영향을 보여 줍니다. 확인하고 **일정 변경 적용**을 누릅니다. 이 창은 자동으로 후속 작업을 함께 옮기지 않는다는 점도 알려 줍니다.

### 선행 작업 연결하기

상세 패널의 **선행 작업** 구역에서 **선행 추가**를 눌러 **선행 작업 선택**, **관계**(**완료 후 시작(FS)** 또는 **동시 시작(SS)**), **대기(영업일)** 를 정하고 **작업 연결**을 누릅니다. 연결을 지우려면 줄의 **의존성 삭제**를 누릅니다. 파일(`wbs.md`)로 가져온 연결에는 **가져옴** 표시가 붙고 화면에서 지울 수 없습니다.

### 담당자와 단계 지정하기

상세 패널의 **담당·단계** 구역에서 합니다. 관리자가 아니면 **담당자**와 **단계**는 읽기 전용이고 `보기 전용 — 프로젝트 관리자만 변경할 수 있습니다.` 라고 나옵니다. 다만 그 작업 위쪽 항목의 담당자(상위 담당자)는 **개발 워크플로 대상** 체크와 승인 버튼을 쓸 수 있습니다.

1. **담당자** 칸에서 이름이나 팀으로 검색해 담당자를 고릅니다. 비우려면 **담당자 없음**을 고릅니다.
2. 하위 항목이 있으면 **미지정 하위 항목에도 적용** 체크 칸이 나옵니다. 체크한 채 담당자를 고르면 담당자가 없는 하위 항목에도 같이 적용되고, `5건에 적용되었습니다` 라고 나옵니다.
3. **개발 워크플로 대상** 체크(관리자와 상위 담당자가 쓸 수 있습니다)로 이 작업이 단계(**할당됨**, **작업 중**, **검수 대기**, **완료**)를 거치게 합니다. 단계는 하위 항목이 없는 최종 작업에만 지정할 수 있습니다.
4. **단계** 드롭다운에서 단계를 고릅니다. 승인 단계가 둘 이상이면 **완료**는 고를 수 없고 승인으로만 됩니다.

고친 값은 잠시 뒤에 저장됩니다. `5초 뒤 저장`처럼 남은 초가 줄어드는 표시가 보이고, **지금 저장**을 누르면 바로 저장합니다. 에이전트에게 위임된 작업은 단계를 직접 바꿀 수 없고 승인·반려로만 바뀝니다.

### 여러 행 한꺼번에 고치기

관리자에게는 표의 번호 칸이 체크 칸으로 보입니다.

1. 고칠 행의 체크 칸을 체크합니다. 화면 아래에 대량 작업 바가 나타나고 `3개 선택됨` 처럼 개수가 보입니다. 표시된 결과를 전부 선택하려면 `결과 전체 N개 선택`을 누릅니다.
2. **대량 수정**을 누르면 **WBS 작업 대량 수정** 창이 열립니다. 산출물, 업무 분류, 시작일, 종료일, 담당자, 주관 팀, 작업 단계를 한 번에 바꿀 수 있습니다. 항목마다 **변경 안 함**, **새 값 지정**, **값 비우기**를 고르고 **총 N개 항목에 적용**을 누릅니다. 단계와 담당자 변경은 각각 따로 적용해야 합니다.
3. **붙여넣기**를 누르면 **WBS 붙여넣기 검토** 창이 열립니다. 엑셀에서 복사한 셀을 붙여넣고 **N개 항목에 적용**을 누르면 산출물, 계획시작, 계획종료, 업무 분류 열 가운데 화면에 보이는 열에 반영됩니다. 빈 셀은 값을 지웁니다. 화면에 보이는 열만 대상이고, 먼저 표시해야 합니다.
4. 선택을 풀려면 **선택 해제**를 누릅니다.

일부 항목이 실패하면 **부분 실패 발생** 상자에 `총 5개 중 4개 성공, 1개 실패`와 실패 목록이 나옵니다. **실패한 N건만 다시 시도**로 이어서 처리할 수 있습니다.

### 명세 편집

상세 패널의 **명세** 구역에서 명세 본문과 우선순위 등을 고치는 일도 프로젝트 관리자만 할 수 있습니다.

## 주간보고 시트와 업무영역

주간보고는 주차마다 시트(문서) 하나를 만들고 업무영역별로 금주 실적과 차주 계획을 적습니다. 시트를 처음 만드는 일은 프로젝트 관리자만 할 수 있습니다. 멤버는 만들어진 시트의 셀을 입력합니다. 시트 입력 방법은 [주간보고](/help/weekly) 장에 있습니다.

### 새 주차 시트 만들기

1. 왼쪽 메뉴 **주간보고**를 엽니다. 위쪽의 **이전 주**, **다음 주** 버튼으로 시트를 만들 주차로 이동합니다. 주차는 `10월 2주차 (10/05~10/11)` 모양으로 보입니다.
2. 그 주차에 시트가 없으면 `10월 2주차 (10/05~10/11) 시트가 없습니다` 라는 안내가 나옵니다. 관리자에게는 `이전 주차에서 이월하거나 업무영역 3개(설계·개발·테스트)로 기본 시트를 시작하세요.` 라고 나오고 버튼이 보입니다. 일반 멤버에게는 `주차 시트 생성은 프로젝트 관리자가 합니다.` 라고만 나옵니다.
3. 시작 방법을 고릅니다.
   - **이전 주차에서 이월해 시작**: 이전 주차의 차주계획이 이번 주 금주실적 초안으로 들어옵니다. 이월할 이전 시트가 있을 때만 이 버튼이 나옵니다.
   - **기본 시트로 시작**: 활성 업무영역마다 빈 행을 만든 시트로 시작합니다.
4. 시트가 만들어지면 표가 나타납니다.

시트는 자동으로 만들어지지 않고 관리자가 이 버튼을 눌러야 생깁니다.

> **주의** 주차가 프로젝트 기간 밖이면 `이 주차는 프로젝트 기간 밖입니다. 만든 시트는 지울 수 없으니 주차를 다시 확인하세요.` 라는 노란 안내가 나옵니다. 한번 만든 시트는 지울 수 없습니다.

### 비활성 영역의 내용 이월하기

**이전 주차에서 이월해 시작**을 눌렀을 때 이전 주차 차주계획에 지금은 비활성인 업무영역의 내용이 있으면 **이월할 내용의 업무영역 고르기** 창이 열립니다.

1. 줄마다 `비활성 영역 설계 — 대기 2칸`처럼 옮겨질 내용이 나옵니다.
2. 오른쪽 선택 상자에서 옮겨 담을 활성 영역을 고르거나 **옮기지 않음**을 고릅니다. 옮기지 않아도 이전 주차 시트의 내용은 그대로 남습니다.
3. **이 매핑으로 이월**을 누릅니다.

옮긴 내용이 칸 상한을 넘으면 `옮긴 내용이 칸 상한(20,000자)을 넘어 시트를 만들지 않았습니다 — 다른 영역이나 '옮기지 않음'을 고르세요.` 라고 나옵니다. 다른 영역을 고르거나 **옮기지 않음**을 고르세요.

### 업무영역이 없거나 행이 없을 때

- 활성 업무영역이 하나도 없으면 `주간보고 영역을 먼저 설정하세요` 라는 안내가 나옵니다. 관리자에게는 **업무영역 설정으로** 링크가 있어 [업무영역 관리](#업무영역-관리)로 바로 갑니다.
- 시트는 있는데 행이 없으면 `○ 시트에 업무영역 행이 없습니다` 라고 나옵니다. 활성 업무영역을 저장하면 이번 주 이후 시트에 행이 생깁니다.

> **팁** 업무영역을 새로 저장하거나 비활성으로 바꾸면 이번 주 이후 시트에만 영향이 갑니다. 지난 주 시트는 그대로 보존됩니다.

## 주간 보고서와 AI 브리핑

**작업 계획** 화면 위쪽의 **주간보고** 버튼(마우스를 올리면 `주간보고서 생성`)이나 **개요** 화면의 **주간보고서 요약(PPT)** 버튼을 누르면 **주간 보고서** 창이 열립니다. 팀별 진척과 지연 작업이 요약된 화면이며 **Excel**, **PPT** 로 내려받을 수 있습니다. 이 창은 누구나 열 수 있지만 AI 브리핑을 만드는 일은 프로젝트 관리자만 합니다.

1. 창 아래쪽 **AI 코멘트 포함**은 PPT 마지막에 AI 종합 코멘트 슬라이드를 넣는 선택입니다. 신선한 AI 브리핑이 있어야만 체크할 수 있습니다.
2. 브리핑이 없거나 오래됐으면 관리자에게 **AI 브리핑 생성** 버튼이 나옵니다. 누르면 **생성 중…** 을 거쳐 브리핑이 만들어집니다. 실패하면 **생성 실패 — 다시 시도**로 바뀝니다.
3. 관리자가 아니면 그 자리에 `AI 브리핑 생성은 프로젝트 관리자만 할 수 있습니다` 라고만 나옵니다.

**개요** 화면의 **주간보고서 요약(PPT)** 버튼으로 여는 같은 창에서도 마찬가지입니다.

## 관리자 승인이 필요한 일

### 작업 완료 승인

개발 워크플로 대상 작업(**개발 워크플로 대상**을 체크한 최종 작업)은 담당자가 단계를 **검수 대기**로 올리면 승인 절차를 거쳐야 **완료**가 됩니다. 승인 단계의 수와 승인자는 [승인 단계와 승인자 정하기](#승인-단계와-승인자-정하기)에서 정합니다.

1. 담당자가 작업을 **검수 대기**로 올립니다.
2. 승인할 작업의 이름을 눌러 상세 패널을 엽니다.
3. **담당·단계** 구역에 **승인(1/2 · 승인)** 처럼 현재 승인 단계와 이름이 적힌 버튼이 보입니다. 누르면 승인됩니다.
4. 승인 단계가 하나뿐이면 승인과 동시에 **완료**가 되고 실적이 100%가 됩니다. 단계가 여러 개면 한 단계 승인할 때마다 다음 승인 단계의 승인 자격자에게 알림이 가고, 마지막 단계를 승인하면 **완료**가 됩니다. 승인 요청과 반려 알림은 놓치면 업무가 멈추므로 워크스페이스에서도 끌 수 없습니다.

누가 승인할 수 있는지는 단계의 **승인자** 설정에 따릅니다.

| 승인자 설정 | 승인할 수 있는 사람 |
|---|---|
| **프로젝트 관리자만** | 프로젝트 관리자(워크스페이스 관리자와 플랫폼 관리자 포함) |
| **상위 담당자 또는 관리자** | 프로젝트 관리자, 또는 그 작업 위쪽 항목의 담당자. 관리자가 아닌 상위 담당자는 자기가 담당했거나 착수한 작업을 승인할 수 없습니다. |

> **주의** 관리자가 아닌 사람은 자기 담당 작업을 승인할 수 없습니다. 상위 담당자가 자기 담당이거나 자기가 착수한 작업을 승인하려 하면 `자기 담당이거나 자기가 착수한 항목의 완료는 승인할 수 없습니다 — 다른 관리자나 상위 담당자에게 요청하세요.` 라고 나옵니다. 프로젝트 관리자(워크스페이스 관리자와 플랫폼 관리자 포함)는 자기 담당 작업도 승인할 수 있습니다. 다만 **단계마다 다른 승인자**가 켜져 있으면(처음에는 켜져 있습니다) 한 검수에서 두 단계를 혼자 승인할 수는 없습니다.

> **팁** 승인 단계가 둘 이상이면 실적%에 100을 직접 입력해 완료할 수 없습니다. `이 프로젝트는 승인 단계가 둘 이상이라 완료(100%)는 단계 승인으로만 됩니다 — 99% 까지 입력할 수 있습니다.` 라고 나옵니다. 단계 드롭다운에서도 **완료**를 고를 수 없습니다.

승인을 누르려는 순간 승인 단계가 바뀌었다면 `승인 단계가 바뀌었습니다 — 새로 불러온 단계를 확인한 뒤 다시 승인하세요.` 라고 나옵니다. 패널을 새로 읽은 뒤 다시 누르세요.

### 에이전트가 올린 완료 보고

에이전트에게 맡긴 작업은 완료 보고가 올라오면 승인 또는 반려해야 합니다. 같은 승인자 규칙이 적용되고, 반려와 재작업 요청은 관리자, 담당자 본인, 상위 담당자가 모두 할 수 있습니다. 화면과 사용법은 [에이전트](/help/agents) 장을 보세요.

## 다른 화면에서 관리자만 하는 일

아래 일은 해당 화면의 장에서도 설명하지만, 프로젝트 관리자가 알아 두면 좋은 것을 한곳에 모았습니다.

| 화면 | 관리자만 할 수 있는 일 | 자세한 설명 |
|---|---|---|
| 공지사항 | **공지 작성**, **공지 수정**, 공지 삭제. 아직 게시 전이거나 기간이 끝난 공지도 관리자에게는 보입니다. 회의 한 회차를 바탕으로 공지를 만드는 일도 관리자만 합니다. | [공지사항](/help/announcements) |
| 회의 | 다른 사람이 만든 회의를 고치거나 지우기. 다른 사람이 만든 회의의 안내 메일 보내기. 작성자 본인은 자기 회의를 같은 방식으로 다룰 수 있습니다. | [회의와 회의록](/help/meetings-minutes) |
| 이슈 | 다른 사람이 쓴 이슈의 전체 편집·삭제, 이슈 첨부 정리, 이슈 조치 경과의 **완전 삭제**(관리자만). 작성자 본인은 자기 이슈를 고칠 수 있습니다. | [이슈](/help/issues) |
| 위키 | 위키 항목의 검토(받아들임·거절), 정리(완료 처리, 숨기기, 자동 갱신 고정 등), 갈라진 주제 병합 | [위키](/help/wiki) |
| 에이전트 | 에이전트 설정 관리, 승인자를 **프로젝트 관리자만**으로 둔 단계의 승인 등. 완료 보고의 승인·반려 가운데 상위 담당자나 담당자 본인이 할 수 있는 것은 [에이전트](/help/agents) 장을 보세요. | [에이전트](/help/agents) |
| AI 어시스턴트 | 프로젝트 색인 다시 만들기, AI 브리핑 생성 | [AI 도우미](/help/ai-assistant) |

## 프로젝트 삭제

프로젝트를 지우는 일은 프로젝트 관리자가 아니라 **워크스페이스 관리자**만 할 수 있습니다. 프로젝트 설정 맨 아래 **위험 구역**도 워크스페이스 관리자(플랫폼 관리자 포함)에게만 보입니다. 지우기 전에 확인할 것과 순서는 [워크스페이스 관리자](/help/workspace-admin) 장에 있습니다.

## 문제가 생겼을 때

| 증상 | 이유와 해결 |
|---|---|
| 왼쪽 메뉴에 **설정**이 없습니다. | 이 프로젝트의 관리자가 아니기 때문입니다. **팀 구성**에서 내 권한을 확인하고, 필요하면 워크스페이스 관리자에게 관리자 권한을 요청하세요. |
| 설정 화면에 들어갔는데 **개요**로 돌아갑니다. | 같은 이유입니다. 관리자만 설정을 열 수 있습니다. |
| 기능을 켰는데 메뉴가 나타나지 않습니다. | 먼저 필요한 다른 기능이 켜져 있는지 확인하세요(예: 이슈 분석은 이슈가 필요합니다). 워크스페이스가 허용하지 않은 기능이면 [기능 켜고 끄기](#기능-켜고-끄기)에서 설명한 노란 상자에 나옵니다. |
| 권한 칸에서 **관리자**를 고를 수 없습니다. | 관리자 권한은 워크스페이스 관리자만 줄 수 있습니다. 요청하세요. |
| 권한 칸에서 **멤버**와 **관리자**가 눌리지 않습니다. | 그 사람이 **계정 미연결**인 외부 인력입니다. 이메일로 초대하면 합류할 때 명단에 새 줄로 오릅니다([이메일로 초대하기](#이메일로-초대하기)). 그 뒤 옛 외부 인력 줄은 **비활성**으로 바꾸거나 삭제하세요. |
| 사람을 삭제할 수 없습니다. | 근태·담당·회의 참석 기록이 있는 사람입니다. **활성** 체크를 풀어 **비활성**으로 바꾸세요. |
| 초대를 보낼 수 없습니다. | 초대 허용 도메인이 비어 있거나 그 도메인이 아닌 주소일 수 있습니다. 워크스페이스 관리자에게 도메인 설정을 요청하세요. |
| 저장했더니 **다른 사용자가 설정을 바꿨습니다.** 가 나옵니다. | 다른 관리자가 먼저 저장했습니다. [저장하는 방법과 충돌 안내](#저장하는-방법과-충돌-안내)를 보세요. |
| 팀 목록이 나오지 않고 **팀 목록을 불러오지 못했습니다. 잠시 후 다시 시도하세요.** 가 나옵니다. | 잠시 뒤 새로고침합니다. 계속되면 워크스페이스 관리자에게 알립니다. |
| 주간보고 시트를 만들 수 없습니다. | 활성 업무영역이 없거나 관리자가 아닌 경우입니다. [업무영역 관리](#업무영역-관리)와 [주간보고 시트와 업무영역](#주간보고-시트와-업무영역)을 보세요. |
| 엑셀 내보내기가 실패합니다. | [엑셀로 내보내기와 저장된 양식 비우기](#엑셀로-내보내기와-저장된-양식-비우기)의 표에서 안내문에 맞는 해결 방법을 따르세요. |
