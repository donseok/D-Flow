# 한국어 기술 문서 작성 규칙

## 1. 머리말

### 1.1 목적

- 한국어 기술 문서의 작성 기준을 한 곳에 모읍니다.
- ASD-STE100(Simplified Technical English)의 원칙을 한국어에 맞게 옮긴 규칙입니다.
- 제1원칙: 독자가 추론할 것을 남기지 않습니다. 생략된 조사와 서술어를 채우고, 어려운 말을 풀고, 여러 뜻으로 읽히는 표현을 하나로 정합니다.

### 1.2 적용 범위

- 적용: 기술 문서, 매뉴얼, 화면 안내 문구, 에이전트 답변입니다.
- 제외: 마케팅, 문학, 설득이 목적인 글입니다.
- 제외: 법령, 계약처럼 문구가 정해진 글입니다. 원문을 바꾸지 않습니다.
- 제외: 스킬 문서, 레인·에이전트 메시지, 작업 메모입니다. 이 글은 `Korean-STE-LLM-Guide.md`를 따릅니다.
- 코드, 명령, 경로, 식별자, 로그 인용은 원문 그대로 둡니다.

### 1.3 등급

- 필수: 반드시 지킵니다.
- 권장: 특별한 이유가 없으면 지킵니다.
- 참고: 상황에 맞게 판단합니다.

## 2. 본문 규칙

### 2.1 문장 길이와 구조

**문장은 짧게 씁니다.** `권장`
- 기준: 절차문 16어절 권장, 20어절 상한. 설명문 20어절 권장, 25어절 상한.
- 긴 문장은 짧은 문장 여러 개로 나눕니다. 나눈 문장은 앞에 불릿(`-`)을 붙여 한 줄에 하나씩 씁니다.
- 순서가 있는 동작이면 불릿 대신 번호 목록을 씁니다(2.6). 화면 문구처럼 목록을 쓸 수 없는 곳에서는 문장만 나눕니다.
- 예: `예약 작업은 MCM이 매일 07시에 실행하고, 실패하면 3번까지 다시 시도하며, 결과는 이력 화면에서 확인할 수 있습니다.` → 아래처럼 나눕니다
  - `MCM이 예약 작업을 매일 07시에 실행합니다.`
  - `실패하면 3번까지 다시 시도합니다.`
  - `결과는 이력 화면에서 확인합니다.`

**지시 한 문장에 동작 하나를 씁니다.** `권장`
- 같은 대상의 연속 동작만 `-ㄴ 후`로 한 번 이을 수 있습니다.
- 예: `예약 작업을 열고 실행 주기를 고치세요.` → `예약 작업을 연 후 실행 주기를 고치세요.`

**조건을 동작 앞에 씁니다.** `권장`
- 조건이 뒤에 오면 독자는 동작한 뒤에야 조건을 읽습니다.
- 한 문장에 조건은 하나입니다.
- 예: `저장 버튼을 누르세요, 필수 칸을 모두 채웠으면.` → `필수 칸을 모두 채웠으면 저장 버튼을 누르세요.`

**한 단락에 한 주제만 쓰고 6문장을 넘기지 않습니다.** `참고`

**세미콜론과 줄표를 쓰지 않습니다.** `권장`
- 문장을 둘로 나누거나 앞뒤 관계를 말로 씁니다.
- 코드와 정규식 안의 세미콜론은 제외합니다. 기술 보고서에서는 `참고`로 낮춥니다.
- 예: `MCM을 내립니다; 모듈의 예약 작업이 멈춥니다.` → `MCM을 내리면 모듈의 예약 작업이 멈춥니다.`

### 2.2 태와 서술어

**이중피동을 쓰지 않습니다.** `필수`
- 예: `조회되어집니다` → `조회됩니다`

**설명문은 행위자를 주어로 써서 능동으로 씁니다. 지시문은 주어를 생략합니다.** `권장`
- 행위자가 없거나 불명이면 피동을 씁니다.
- 지시문의 주어는 언제나 독자입니다. 행위자가 둘 이상일 때만 주어를 씁니다.
- 예: `머지 허가는 조정자에 의해 내려진다.` → `조정자가 머지를 허가한다.`

**불필요한 `-시키다`를 쓰지 않습니다.** `참고`
- 필요한 사동(`발전시키다`)은 그대로 둡니다.
- 예: `조회 속도를 향상시킨다` → `조회 속도를 높인다`

**목적어와 서술어의 호응을 맞춥니다.** `권장`
- `을/를` 뒤에 피동 서술어를 쓰지 않습니다.
- 예: `만료된 세션을 삭제될 수 있습니다.` → `만료된 세션을 삭제할 수 있습니다.`

**명사화 표현을 동사로 풉니다.** `권장`
- 새로 쓰는 문서에만 적용합니다. 기존 문서와 규정문은 일괄로 고치지 않습니다.
- 예: `메뉴·권한 실측을 수행한다.` → `메뉴·권한을 실측한다.`

**조사를 생략하지 않습니다. 명사를 조사 없이 길게 잇지 않습니다.** `권장`
- 명사 잇기 기준: 절차문과 개발자 문서는 3어절, 기술 보고서는 4어절까지입니다. 6어절 이상은 `필수`로 금지합니다.
- 고정 명칭, 제목, 표, 목차는 제외합니다.
- 예: `조회후 저장버튼 클릭` → `조회한 후 저장 버튼을 눌러`
- 예: `예약 작업 실행 결과 갱신 실패 처리 방식` → `예약 작업의 실행 결과를 갱신하지 못했을 때의 처리 방식`

**서술어를 풀어 씁니다.** `권장`
- `-중에 있다`, `N 시`로 서술어를 대신하지 않습니다.
- 예: `가림 함수 실패 시 그 대상은 올리지 않는다` → `가림 함수가 실패하면 그 대상은 올리지 않는다`

**본문 문장은 서술어로 끝냅니다.** `필수`
- 제목, 목록 항목, 표 셀은 제외합니다.
- 예: `수동 실행과 재실행 요청은 화면에서 불가하며` → `수동 실행과 재실행 요청은 화면에서 할 수 없으며`

### 2.3 종결과 문체

**한 문서에서 종결 체계 하나만 씁니다.** `권장`
- 프로젝트의 기존 문서가 정한 어미를 따릅니다. 정하지 않은 채팅 답변은 합니다체입니다.
- 장르별 종결 체계:

| 장르 | 지시 | 설명 | 의무 |
|---|---|---|---|
| 독자에게 말하는 문서(매뉴얼·절차서·개발자 문서·답변) | `-세요`, `-지 마세요` | `-ㅂ니다` | `-어야 합니다` |
| 규정·명세·보고서 | 쓰지 않음 | `-ㄴ다` | `-어야 한다` |

- 예: `저장 전 입력값 확인 부탁드려요!` → `저장하기 전에 입력값을 확인해 주세요.`

**지시문에 `-할 것`, `-바람`, `-요망`을 쓰지 않습니다.** `필수`
- 지시는 위 표의 지시 어미로 씁니다.
- 서술문에는 명령형을 섞지 않습니다(`참고`).
- 예: `재기동 전에 실행 중인 작업을 확인할 것` → `재기동하기 전에 실행 중인 작업을 확인하세요.`

### 2.4 어휘

**같은 뜻을 겹쳐 쓰지 않습니다.** `필수`
- 예: `기존에 있던 컬럼정보들은 모두 삭제됩니다.` → `기존 컬럼 정보는 모두 삭제됩니다.`

**한 대상에 한 단어만 씁니다.** `필수`
- 영문과 한글을 섞어 같은 대상을 부르지 않습니다. 핵심어를 대명사로 바꾸지 않습니다.
- 용어집에 정한 표기가 있으면 그 표기를 씁니다.
- 예: `예약 작업`과 `스케줄 작업`을 섞어 씁니다. → `예약 작업`만 씁니다

**번역투를 쓰지 않습니다.** `필수`·`권장`
- `필수`: `에 있어서`, `필요로 하다`, `득하다`, `갈음하다`는 예외 없이 고칩니다.
- `권장`: `에 의해`, `을 통해`, `에 대하여`, `에 위치하다`는 문맥으로 판단합니다. 행위자가 있으면 능동으로 고칩니다.
- 예: `깨진 값이 팝업을 통해 계속 재주입됐다.` → `깨진 값이 팝업으로 계속 재주입됐다.`

**어려운 한자어를 쉬운 말로 바꿉니다.** `권장`
- `본 시스템`처럼 장르와 독자에 따라 정당한 표현은 둡니다.
- 예: `향후 지원하려면` → `앞으로 지원하려면`

**외래어는 한글 표기법에 맞게 씁니다. 기술 용어는 우리말로 바꾸지 않습니다.** `권장`
- 기술 용어는 원어나 통용 음차로 씁니다(`패스워드`, `업데이트`, `카테고리`, `query`, `cache`).
- 맞추는 것은 표기뿐입니다. 다듬은 말(`누리집`, `내려받다`)로 바꾸지 않습니다.
- 예: `스케쥴러` → `스케줄러`

**낯선 약어는 처음 한 번만 풉니다.** `참고`
- 처음 한 번 `전체 이름(약어)`으로 쓰고, 이후에는 약어만 씁니다.
- 통용 약어(URL, API), 제품 이름, 표준 이름은 풀지 않습니다.
- 예: `마스터 데이터 관리(MDM)`

**명령, 파일, 식별자는 설명 대신 실제 이름을 씁니다.** `권장`
- 예: `MDM 서버를 띄우는 스크립트를 실행하세요.` → `` `local-run.sh --mdm -q`를 실행하세요. ``

**지시어와 대명사는 대상이 바로 앞에 있을 때만 씁니다.** `참고`
- `해당`, `상기`, `이것`, `그 부분`은 대상이 멀면 이름을 다시 씁니다.
- 예: `해당 항목은 확정하지 않고` → `불일치한 항목은 확정하지 않고`

**효과를 주장하는 말 대신 사실이나 측정값을 씁니다.** `권장`
- 예: `예약 작업을 안정적으로 실행한다` → `실행에 실패하면 3번까지 다시 시도한다`

**모호한 표현을 구체적으로 씁니다.** `권장`
- `어느 정도`, `다소`, `등`, `기타`, 의존명사 `것`을 항목이나 수치로 바꿉니다.
- 예: `권한 등을 확인합니다` → `메뉴 권한과 버튼 권한을 확인합니다`

### 2.5 표기

**숫자는 아라비아 숫자로 쓰고 단위를 띄어 씁니다.** `참고`
- 단위를 붙여 쓴 관용 표기(`3MB`)도 허용합니다.
- 예: `3만건` → `3만 건`

**날짜와 시간은 한 형식으로 씁니다.** `참고`
- 날짜는 `YYYY-MM-DD`, 시각은 24시간제 `HH:MM`입니다.
- 예: `2026.10.9 오후 7시 30분` → `2026-10-09 19:30`

**범위는 물결표(`~`) 대신 하이픈(`-`)으로 씁니다.** `필수`
- 마크다운에서 물결표 두 개는 취소선이 되어 글자가 지워져 보입니다.
- 날짜·시각처럼 값 안에 `-`나 `:`가 있으면 범위 하이픈의 앞뒤를 띄웁니다.
- 코드 안의 `~`(경로, 연산자)는 원문 그대로 둡니다.
- 예: `1~3단계`, `10:00~12:00` → `1-3단계`, `10:00 - 12:00`, `2026-10-09 - 2026-10-12`

**띄어쓰기와 맞춤법을 지킵니다.** `권장`
- 예: `입력값을 확인해주세요.` → `입력값을 확인해 주세요.`

### 2.6 절차문

**순서가 있는 동작은 번호 목록에 한 줄 한 동작으로 씁니다.** `참고`
- 결과는 다음 문장에 씁니다.
- 예: `MDM을 먼저 띄우고 포털에 로그인한 뒤 화면을 여세요.` → `1. MDM을 띄우세요.` `2. 포털에 로그인하세요.` `3. 화면을 여세요.`

**참고(Note)에는 정보만 쓰고 지시를 넣지 않습니다.** `참고`
- 지시는 번호 항목으로 옮깁니다.

### 2.7 설명문과 답변

**첫 문장에 결론이나 결과를 씁니다.** `권장`
- 질문을 다시 쓰지 않습니다.
- 예: `예약 작업이 멈춘 이유를 설명드리겠습니다.` → `MCM이 꺼져 있어서 멈췄습니다.`

**인사말과 맺음말을 쓰지 않습니다.** `권장`
- 결정이 필요한 질문만 마지막에 씁니다.
- 예: `더 궁금한 점이 있으면 말씀해 주세요.` → 삭제

**근거를 씁니다.** `권장`
- 코드는 `경로:줄`, 커밋은 해시, 명령은 전체 명령으로 씁니다.

**글 유형별 패턴을 따릅니다.** `참고`

| 유형 | 패턴 |
|---|---|
| 오류 메시지 | 무엇이 실패했는지 → 원인(아는 경우만) → 사용자가 할 일 한 문장 |
| 런북·절차서 | 번호 목록, 한 단계 한 동작, 조건 먼저, 되돌릴 수 없는 단계 앞에 경고 |
| 사고 보고서 | 영향과 현재 상태 → 시간순(번호나 표) → 모르는 원인은 「원인을 확인하지 못함」 |
| 릴리스 노트 | 사용자에게 보이는 변화 먼저, 한 항목에 변화 하나 |
| 에이전트 지시문 | 목적, 범위, 완료 조건을 각각 한 문장. 하지 말 일을 명시 |
| 결정 요청 | 번호 선택지, 추천을 첫째에 두고 「(권장)」 표시 |

### 2.8 목록, 표, 강조

**항목이 셋 이상이면 세로 목록으로 씁니다.** `참고`
- 예: `MCM, MDM, MLS, MQC를 차례로 띄웁니다.` → 항목마다 한 줄로 씁니다

**같은 속성으로 여러 대상을 비교할 때는 표를 씁니다.** `권장`

**굵은 글씨와 제목을 아낍니다.** `권장`
- 굵은 글씨는 결론 한 곳이나 경고에만 씁니다.
- 제목은 3문장 이상인 단락에만 답니다.

### 2.9 경고와 주의

**위험 수준 식별어는 문장 안이 아니라 블록 머리에 둡니다.** `권장`
- 경고는 데이터 손실, 되돌릴 수 없는 작업, 서비스 중단 위험입니다.
- 주의는 성능 저하, 설정 오류 위험입니다.

**경고는 [조건] → 지시 → 결과 순서로 씁니다.** `권장`
- 결과가 자명하지 않으면 별도 문장으로 씁니다.
- 예: `운영 DB에서는 DROP을 실행하지 마세요. 테이블과 데이터가 모두 사라집니다.`

**되돌릴 수 없는 작업 앞에 경고를 둡니다.** `권장`
- 예: `이력을 지우세요. 되돌릴 수 없습니다.` → `되돌릴 수 없습니다. 이력을 지우기 전에 백업하세요.`

### 2.10 정보 보존과 사실

**숫자, 단위, 식별자, 코드, 고유명사를 원문 그대로 보존합니다.** `필수`
- 표기만 바꾸는 것(`1200건` → `1,200건`)은 됩니다.
- 예: `5분마다 실행하세요.`를 `자주 실행하세요.`로 바꾸지 않습니다.

**부정 표현과 핵심 명사를 보존합니다.** `권장`
- 고친 뒤 `않`, `못`, `없`, `아니`, `마세요`가 그대로인지 확인합니다.

**확신 수준을 바꾸지 않고, 확인한 것과 못 한 것을 구분합니다.** `권장`
- 근거 없이 `일 수 있다`를 `이다`로 바꾸지 않습니다. 원문의 `약`, `대략`도 둡니다.
- 예: 근거가 없으면 `원인은 락 경합입니다` 대신 `원인을 확인하지 못했습니다`라고 씁니다.

**원문에 없는 수치, 원인, 담당자, 날짜를 만들지 않습니다.** `권장`
- 뜻을 바꿔야만 짧아지면 짧게 하지 않습니다.

**오류 메시지와 로그는 원문 그대로 인용합니다.** `권장`
- 줄이거나 바꾸지 않고 코드로 인용합니다. 파괴적 작업 전의 확인 문구도 줄이지 않습니다.
