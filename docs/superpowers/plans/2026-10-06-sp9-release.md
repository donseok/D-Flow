# SP9 출시 준비 실행 계획

정본: 개정 설계 §6.2 SP9, §6.5.8–9 및 원 설계 §5.5.4.
현재 SPU3 브랜치에서 검증을 마친 뒤 출시 준비를 이어간다. 사용자 데이터 DB의 초기화는 하지 않는다.

## 완료 기준

- [ ] SPU3 브라우저: 대량 선택·부분 성공·충돌 보존·재시도·붙여넣기, 390px/확대/짧은 화면, 포커스·Esc, 라이트/다크 캡처 검토
- [ ] 전체 단위·RLS·설정 검증·린트·타입·프로덕션 빌드
- [ ] 격리 DB 전체 초기화 및 마이그레이션 리허설 증빙
- [ ] 준비 체크리스트: 기본 정보 → 사용 기능 → 달력·업무 규칙 → 첫 데이터, 건너뛰기·이어하기
- [ ] 기존 가져오기 RPC의 authenticated 실행권 및 팀 직접 쓰기 경로 정리, 롤백·실행형 권한 검증
- [ ] 합성 S1–S10: 미활성 S7·S10까지 구현하고 건너뜀 없이 실행
- [ ] 자체호스트 R1–R10: standalone, Auth, Storage, Realtime, 잡, SMTP, 로컬 AI 및 외부 연동
- [ ] 31라우트 × 테마 2종 × 크기 4종, Q01–Q14 판정 및 J1–J3 워크스루
- [ ] 설정 카탈로그의 지원 상태 전 항목 검토
- [ ] main 통합·푸시·CI, 사용자 DB 적용 및 배포 결과 확인

## 검증 기록 규칙

실제로 실행한 결과만 통과로 적는다. 미검증에는 사유를 남긴다. 공개 배포와 사용자 DB 적용은 구체적인 변경·리허설 결과를 제시한 뒤 진행한다.
DB 구조를 바꾸는 RLS 테스트와 브라우저 검증은 같은 DB에서 동시에 실행하지 않는다.
