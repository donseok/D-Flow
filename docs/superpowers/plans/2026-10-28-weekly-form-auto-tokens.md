# 주간보고 PPT 양식 — 자리표시자 없는 표 자동 연결·업로드 즉시 활성화 (2026-10-28)

## 문제

사용자가 회사 주간업무보고서 pptx 를 양식으로 올렸는데 주간보고 상세 PPT 는 기본 양식(흰 바탕)으로 나왔다. 운영 DB 로 확인한 원인은 둘이다.

1. 양식은 `form_templates` 에 v1 로 등록됐지만(`active=false`) **활성화를 누르지 않아** `forms.weekly_report_pptx.template_id` 가 null 이었다 → 기본 양식.
2. 더 근본적으로 그 파일에는 **자리표시자(`{{…}}`)가 0개**다. 엔진(정본 §4.4)은 토큰을 채우는 방식이라, 활성화해도 올린 파일이 그대로 나온다(내용 없음).

사용자 결정(10-28): 표 자동 인식 + 업로드 즉시 활성화. 엔진의 토큰 방식은 바꾸지 않는다.

## 결정

- **등록 때 토큰을 넣는다**(`src/lib/report/forms/autoTokens.ts`). `weekly_report_pptx` 이고 스캔 결과 자리표시자가 0개면, 슬라이드의 표 가운데 "구분 | 전주·금주(실적) | 금주·차주(계획)" 머리글을 가진 표를 찾아 첫 데이터 행의 세 칸에 `{{#rows sections}}{{.name}}` · `{{.this_content}}` · `{{.next_content}}` 를 넣고, 그 뒤의 표본 행을 지우고, 데이터 행 높이를 머리글 행 높이로 줄인다(복제 행이 슬라이드를 넘지 않게). 바뀐 바이트를 v<n> 으로 저장하고 다시 스캔한다. 그 뒤 활성화·매핑·렌더는 기존 그대로다.
- 머리글 판정 규칙(결정형·설명 가능):
  - 이름 열: `구분·업무영역·영역·팀·항목·부문·분류·과제·업무명·부서` 가운데 가장 왼쪽. 없으면 그 표는 건너뛴다.
  - 내용 두 열: 머리글에 `실적·완료·수행·결과·진척·진행` → 금주 실적(`.this_content`), `계획·예정` → 차주 계획(`.next_content`). 둘이 명시되지 않으면 기간 낱말의 순서로 — `전주·지난주`(-1) < `금주·이번주·당주`(0) < `차주·다음주·익주·내주`(+1) — 앞 기간이 실적, 뒤 기간이 계획이다. (부산운영팀 양식의 "전주 | 금주" 는 전주=실적·금주=계획, 흔한 "금주 실적 | 차주 계획" 도 그대로 맞는다.)
  - 내용 열은 머리글 칸이 가로 병합(gridSpan>1)이 아니고 열 너비가 표의 15% 이상이어야 한다 — 요일 격자(월~금 5칸 위의 "전주/금주" 그룹 머리글)를 배제한다.
  - 표가 여럿 맞으면 내용 두 열의 너비 합이 가장 큰 표, 같으면 덱 순서 앞.
- 자리표시자가 그래도 0개면 등록은 하되 `RECOMMENDED_MISSING` 경고를 스캔 결과에 남기고(화면의 "경고 1"), 화면은 "내용이 들어갈 자리가 없다"고 알리며 자동 활성화하지 않는다.
- **업로드 직후 활성화**: 화면(`FormTemplatesManager`)이 등록 성공 뒤 바로 `activateFormTemplate` 을 부른다. 미매핑이면 기존 매핑 상자로 넘어간다. 등록 결과에 `placeholderCount`·`autoTokens`(슬라이드 번호·머리글 세 개·지운 행 수)를 더해 안내 문구에 쓴다.
- 머리글의 날짜 글자("10/05~10/16")는 손대지 않는다 — 양식 작성자가 `{{report.week_range}}`·`{{report.next_week_range}}` 로 바꿀 수 있게 매뉴얼에 데이터 이름 목록을 적는다.

## 검증

- 단위: 픽스처 표 4종(전주|금주, 금주 실적|차주 계획, 금주|차주, 요일 격자 배제)·토큰 있는 양식 불변·표 없음·렌더 왕복(영역 7개 → 2장).

- 배포 뒤 사용자는 같은 파일을 다시 올리면 v2 가 자동 연결·활성화된다(v1 은 그대로 남는다).


## 2차(2026-10-29) — 구분 열 없는 두 열 표·되풀이 슬라이드·자리표시자 0개 활성화 차단

운영에서 사용자가 다른 파일(42주차 보고서, 13장)을 올렸다: "금주 (…) 실적 | 차주 (…) 계획" 두 열 표가 슬라이드 2~12에 되풀이되고(한 장에 2줄, 영역 이름은 내용 앞 "[생산계획] …"), 1장은 "금월 | 차월" 월간 요약, 13장은 교육·출장 격자. 1차 규칙(구분 열 필수)에 걸려 `no_table` → 자리표시자 0개로 등록됐고, 사용자가 목록에서 수동 활성화해 보고서가 올린 파일 그대로 나왔다.

결정:
- 구분 열이 없으면 내용 칸 첫 문단에 `[{{.name}}]`(차주 칸도 같은 이름) — 사람이 쓰던 꼴. 구분 열이 있는 표는 점수 가산(+0.5)으로 앞세운다.
- 월 낱말(금월·차월·전월·당월·익월·이달·다음달·지난달·월간)만 있는 머리글 열은 단서로 보지 않는다.
- 고른 표와 같은 열 수·같은 머리글 행 글자(signature)의 표가 바로 뒤 슬라이드에 이어지면 되풀이 — 첫 장만 남기고 파트·rels·Override·sldIdLst·노트 슬라이드까지 지운다(`removeSlides`). 엔진 `writeDeck` 의 삭제 범위 + 노트.
- 표본 데이터 행 수를 `rowsPerSlide` 로 돌려주고 등록 화면이 `options.max_rows_per_slide` 에 저장한 뒤(매핑 저장과 같은 길) 새 revision 으로 활성화한다. 저장 실패면 활성화하지 않고 알린다.
- `assessFormActivation` 이 자리표시자 0개를 `NO_PLACEHOLDERS` 로 거부한다 — 수동 활성화 길도 막힌다.

검증: 실제 v3 파일 → 슬라이드 2, 되풀이 10장 삭제, 2줄/장, 스캔 토큰 5개·오류 0; 12영역 렌더 → 1 + 6 + 1 = 8장, 남은 토큰 0, 표본 글자 0, rels·Override 대상 누락 0.


## 3차(2026-10-29) — 업무 건 단위·머리글 날짜·칸 크기·줄 경계 분할

사용자: "사람이 작성한 것 대비 만들어 낸 것이 너무 부족하다". 운영 산출물(로컬 재현 — 크기 바이트까지 같음)과 원본을 Quick Look 으로 슬라이드 이미지를 떠서 비교했다(Keynote 자동화는 첫 실행 상태라 멈춤). 차이:
- 사람은 **업무 건마다 한 줄**(왼쪽 실적 · 오른쪽 같은 건의 계획), 생성본은 **영역마다 한 줄** — 글 없는 영역 7개가 빈 줄·빈 장을 만들고, `[품질설계 · 내용]` 이름표가 붙었다.
- 머리글 날짜가 양식의 옛 날짜(2026.10.05~10.16) 그대로.
- 긴 칸이 글자 수 기준으로 잘려 "… 24Hr 가동 / 지원" 처럼 문장 중간에서 다음 행으로 넘어갔다.
- sections 의 줄은 단계 들여쓰기로 정규화돼 사람이 적은 들여쓰기가 사라졌다.

결정:
- 카탈로그 `tasks`(list<record>: code·area·title·this_content·next_content·this_tagged·next_tagged) — 영역 글을 빈 줄·"[분류] 제목" 줄(들여쓰기 ≤1)로 나누고, 첫 줄이 같은 금주·차주 건을 묶는다. 짝 없는 차주 건은 영역 끝. 줄은 원문 들여쓰기(탭→공백 넷). 작성 항목이 있으면 첫 항목 칸. 보고서 라우트는 `tasks` 루트가 있을 때만 만든다.
- 두 열 표 자동 연결 토큰을 `{{#rows tasks}}{{.this_tagged}}`·`{{.next_tagged}}` 로. 구분 열 표는 sections 그대로.
- 고른 표의 내용 두 열 머리글 날짜 범위를 `report.(next_)week_range_ymd|_mmdd`(새 카탈로그 값 — 달력 표시 요일 첫날~끝날) 또는 `report.(next_)week_range` 로 바꾼다(서식 따라). 여러 런에 걸치면 첫 런 서식으로 합친다.
- 데이터 행 높이 = 표본 행 높이 평균, `linesPerCell` = (평균 높이 − 91440) / (글자 크기 × 1.2), 등록 화면이 `max_lines_per_cell` 도 저장.
- 엔진 `splitRowItem` 이 {{#items}} 없는 칸도 문단 경계(paginateLines)에서 나누고, 한 문단이 예산을 넘을 때만 글자 단위로.

남은 것: 표가 없는 슬라이드(월간 요약, 인원·교육/출장·휴가)는 양식 글자 그대로 나온다. 휴가·출장은 근태 기록(catalog `attendance`)으로 채울 수 있으나 이 프로젝트 근태 기록이 0건이라 미착수. PowerPoint 글머리 기호(buChar)는 글자가 아니라 웹 글에 없으면 재현하지 않는다.
