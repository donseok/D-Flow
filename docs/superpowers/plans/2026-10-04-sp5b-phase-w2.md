## 결정 기록(구현 중)

- gate 는 `evaluateStartReadiness`·`deriveWaitReason`·`loadDependsInfo` 의 **선택 인자**다(생략 = `'reached'` — 현행 호출·테스트 불변, 호환 규칙 S1).
  선택 인자라 빠뜨려도 조용히 현행으로 도는 위험은 불변식 `predecessor-gate-wiring` 이 src 의 호출처마다 gate 전달을 검사해 닫는다.
- 기준·승인 주문·단계 이름 로더(`predecessorGate`·`approvedItems`)는 단위 테스트 전역 셋업이 기본값('reached'·빈 목록·{})으로 mock 한다 —
  W1 의 `approvalState` 와 같은 이유(기존 테스트의 admin 조회 큐가 밀리지 않게). 진짜 모듈은 전용 테스트가 본다.
- `stageTransition` 은 승인 주문 축을 **final 이고 im 인 선행이 있을 때만** 읽는다. 기준 판독이 실패하면 알림을 내지 않는다(거짓 "착수 가능" 알림 없음 — fail-closed).
- claim 거부 문구는 기준마다 충족 조건을 말하되(reached "검수 대기 이상" / final "최종 승인") code `dependency_not_met`·사전 키는 그대로 — 에이전트 계약 불변.
- E2E 는 final 게이트를 화면으로 검증하지 않는다 — depends 를 화면 액션으로 만들 길이 없고(E2E 규칙상 svc 로 `wbs_items` 를 쓰지 않는다),
  대신 `claim-gate-final` 이 라우트 핸들러 수준에서 reached/final × 선행 im/xx/승인 주문을 고정한다.
- 중간 단계 알림 `work.approval_step` 수신자는 W1 그대로 **프로젝트 관리자만**(승인한 본인 제외). 서브트리 관리자에게 넓히는 것은 대기 단계 승인자별 수신자 계산이
  필요해 이월(스펙 §8 질문 — 기본값 적용).
- 승인 셈은 "서로 다른 승인자" 가 켜져 있으면 이번 라운드에 이미 승인한 사람에게 대기열·배지에서 빼고, 허브 승인 버튼도 숨긴다(서버 판정과 같은 축).
- 단계 이름이 손상이면 편집기는 경고와 함께 빈 칸에서 다시 쓰게 하고, 화면은 사전 기본 이름으로 돈다(손상 값을 표시에 쓰지 않는다).
