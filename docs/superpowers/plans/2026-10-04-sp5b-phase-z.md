## 결정 기록

- 합성 `S3-flow` 의 둘째 승인자는 R 워크스페이스 관리자 계정(계정 생성 액션) — 워크스페이스 관리자는 그 워크스페이스 모든 프로젝트의 관리자를 승계해 명단 행이 필요 없다
  (합성 러너는 설정·명단을 service_role 로 쓰지 않는다). 리프는 S2 가져오기의 첫 리프, 흐름 켜기는 `setWbsDevWorkflow`.
- `S9-workflow` 의 C 엑셀 대조는 R 변경 **직전**(S3 뒤) 스냅샷과 글자 단위로 — 흐름 설정 전 스냅샷은 S3 의 C 리프 승인으로 이미 달라지므로 설정·이슈만 그 시점과 대조한다.
- 성능 화면 A/B 는 두 앱이 같은 DB 를 읽게 했고(SP5 기록의 한계 제거) 라운드를 교대로 돌렸다. RPC A/B 는 0026 롤백 ↔ 재적용을 실행마다 번갈았다.
- RPC 판정 사건의 초과는 설정 행 `FOR SHARE`·새 트리거를 빼는 실험으로 원인이 아님을 확인했다 — 개정 §2.4.1 의 advisory 대안은 효과가 없다. 판정 본문(원장 삽입·대기 단계 질의)의
  비용이라 기능 비용으로 기록하고 사용자 확인 항목으로 올린다(기본값 수용). 최적화 마이그레이션은 만들지 않았다.
- `ISSUE_STATUS_META` 는 가드 패턴에서 뺐다 — 표시 상태가 아니라 범주 메타이고 대시보드 카운트는 범주 기준이다(스펙 §6.1 정정).
- 상수 허용 넷의 `removedBy` 는 `'never'`(새 값) — 정의·폴백 자리라 지울 SP 가 없다.
