# SP5 B2 — 회의록 팀·폴더(마감) 구현 계획

## 실측(코드 조사)

- 팀 루트 판정은 `parent_id null ∧ created_by null`(+ 이름 = 팀 code) — `domain/minutes.ts`(`isTeamRootFolder`·`teamRootFolderIdOf`·`teamSubOfFolder`·`isTeamRootName`), `minutes/folders.ts`(`resolveTeamRootFolderId`·`ensureProjectTeamRoot`·`FolderSnapshot.seedRoots`), `actions/teams.ts` 시드, `MinuteChatPanel` 인라인, `api/minutes/chat` 의 `seedRootIdOf`. 폴더 로더 셋이 `kind`·`team_id` 를 읽지 않는다.
- `addTeam` 의 폴더 시드는 트랜잭션 밖(실패 시 팀만 남고 `ok:false`). 개명은 폴더를 건드리지 않는다(루트 이름 = code 라 불변이었다).
- `create_minute_with_version`(0007)·`update_minute_metadata_with_wiki_retraction`(0000)은 `team_code` 를 워크스페이스 안 아무 활성 팀 code 로만 본다(프로젝트 범위 없음).
- `convert_inherited_teams`(0014)·`team_ref_owned_scope`(0016) 에 회의록 두 표가 없다. 세션 공용 팀 INSERT 정책 `wsadmin_insert_teams`(0003:609).

## 설계 결정(스펙 정정·구체화)

- **`team_id` 해석은 트리거 한 곳**(`minutes_team_code_echo`, DEFINER): INSERT·`team_code` 변경·`project_id` 변경이면 code 단위 규칙(그 프로젝트의 같은 code 전용 팀 → 없으면 같은 워크스페이스 공용 팀, 무프로젝트는 공용만, 다른 프로젝트 전용 팀 제외)으로 `team_id` 를 다시 해석하고, `team_id` 를 직접 바꾸면 `team_code` 를 메아리한다. 새로 고른 팀이 비활성이면 INSERT·`team_code` 변경에서 `MINUTE_TEAM_INVALID`(23503 — 전용이 비활성이면 공용으로 내려가지 않는다). 그래서 수신 RPC 둘(⑦)의 본문을 다시 쓰지 않는다 — 모든 쓰기 길(생성·메타·이동·외부 API·재편철)이 같은 규칙을 지나고, 재편철의 `team_id` 재해석(S13)도 같은 트리거다. 스펙 §3.4 ⑦("RPC 본문에서 해석")을 이렇게 구현한다(원장에 기록).
- 범위 가드(②′)는 열 목록 없는 `BEFORE INSERT OR UPDATE` — 메아리 트리거가 바꾼 `team_id` 도 보도록(열 목록 트리거는 SET 대상 열로만 발화). 이름 순서로 메아리 → M1 → 범위 가드 순.
- 폴더 종류 가드(D49)는 INVOKER, 세션(`authenticated`·`anon`)만 판정.

- **경로 언어는 팀 code 그대로**(D52 ④): 팀 루트 이름은 팀 이름이 되지만 외부 API 에코·배치 `from`/`to`·재편철이 쓰는 경로의 팀 루트 칸은 팀 code 다(`folderPathOfSnapshot` 의 `'api'`). 화면 breadcrumb 만 이름(`'display'`). 이름을 그대로 내면 재편철이 ②(한 칸 내림)로 루트를 겹친다.
- **스냅샷의 팀 루트는 (범위, 팀 code)** — 같은 범위에 같은 code 의 전용·공용 루트가 함께 있으면 전용(조인한 팀의 `project_id`). 폴더 로더 셋은 `kind`·`team_id`·`team:teams(code)` 를 한 매퍼(`folderRow.ts`)로 읽는다.
- **지연 생성**(`ensureTeamRoot`): 그 범위의 code 단위 활성 팀 → 이름 = 팀 이름 → 23505 재조회. 워크스페이스 루트도 같은 길(D50 ④ 지연 수렴). custom 모드 경로는 부르지 않는다.
- **custom 루트**: 정규화 대상 범위(회의록의 프로젝트, 없으면 워크스페이스)의 `custom_root` 이름 또는 설정 `names` 에 있는 이름(없으면 그 범위에 만든다 — service_role). 스펙에 생성 시점이 없어 업로드 지연 생성으로 정했다(SP7 화면이 열리면 다시 본다). 재편철은 워크스페이스 폴더(`project_id` 없음)면 그대로 둔다.
- **모드 판독 실패**: 외부 업로드·배치는 500(새 오류 code 없음 — Q6), 세션의 프로젝트 변경 재편철은 건너뛴다(폴더 유지 — 추측해 옮기지 않는다).
- **`?team=` 은 팀 id**: 선택지 = 그 화면 범위의 활성 팀(`?project=` 면 그 프로젝트의 전용 + 공용, 아니면 공용 — 워크스페이스 레이아웃의 팀과 같다). 옛 code 링크는 code 단위로 한 번 해석해 리다이렉트, 모르는 값은 파라미터 제거. 보관함 챗의 담당 필터는 폴더 루트 판정이 code 계약이라 고른 팀의 code 를 넘긴다.
- **재색인 대상**: 메타 RPC 는 `team_code` 변화를 보고(색인 본문·`ai_documents.team` 은 SP7 까지 code — D18), `team_id` 를 바꾸는 모든 쓰기는 메아리 트리거가 `team_code` 를 함께 바꾼다 — RPC 를 다시 쓰지 않는다(`team-id-contract`).
