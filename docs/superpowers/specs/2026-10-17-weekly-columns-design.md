# 프로젝트별 주간보고 작성 항목

프로젝트 설정의 **추가 필드 → 주간보고 작성 항목**에서 관리자가 1~12개 항목을 구성한다. 각 항목은 불변 ID, 표시 이름(1~40자), 이월 여부를 갖는다. 이름 중복과 빈 구성은 저장하지 않는다. 항목을 추가·삭제·위아래 이동할 수 있다. 금주실적과 차주계획은 같은 항목 구성을 사용한다.

설정 키는 `weekly.columns`이며 프로젝트 설정의 검증·권한·revision CAS·명령 재시도 경로를 그대로 사용한다. 기본 구성은 내용 / 이슈 및 주요 이벤트다. 새 항목의 ID는 자동 생성하므로 이름이나 순서를 바꿔도 저장된 값이 다른 항목으로 옮겨가지 않는다. 삭제한 항목은 입력·이월·AI·출력 대상에서 빠진다. 항목을 다시 추가하면 새 ID를 부여한다. 기존 작성 내용의 이전은 요구하지 않는다.

셀 주소는 `this_<항목 ID>` / `next_<항목 ID>`다. 기본 항목 두 개는 기존 저장 슬롯을 사용하고, 나머지는 `weekly_report_rows.cells` JSONB에 저장한다. 서버가 현재 프로젝트에 정의된 주소인지 확인하고, DB 트리거도 항목 ID·문자열·20,000자 상한을 검증한다. 기존 행의 RLS를 유지하고 세션에는 cells 열 UPDATE 권한만 추가한다. JSON 변경은 행 updated_at CAS로 병합해 다른 셀의 동시 변경을 덮어쓰지 않는다.

시트 선택·복사·붙여넣기·채우기·삭제·키보드 이동·undo는 화면의 가변 열 배열을 받는다. 실시간 병합은 dirty 셀만 로컬 값을 유지한다. 항목 수가 많으면 표 내부에서 가로 스크롤한다. 점검과 AI 다듬기는 같은 열 배열과 표시 이름을 사용한다.

이월을 켠 항목의 이전 차주계획만 새 금주실적으로 복사한다. 비활성 업무영역의 매핑과 길이 초과 거부는 기존 규칙대로 동작한다. 생성 RPC가 JSON 셀까지 한 트랜잭션으로 저장한다.

AI 조회·주차 비교·검색 색인은 현재 항목 이름과 값을 사용한다. 구성 저장 후 해당 프로젝트의 주간보고를 다시 색인한다. 기본 PPT와 Excel은 `업무영역 · 항목 / 금주실적 / 차주계획`으로 출력하며, 항목별 반복 구간을 만들어 모든 항목을 포함한다. 업로드한 사용자 양식에도 동일한 sections 데이터를 제공한다.

DB 변경: `supabase/migrations/0060_weekly_columns.sql`. 데이터 삭제나 사용자 작성 데이터 이전은 하지 않는다. 분리된 로컬 QA DB에서 적용과 RLS를 검증한다.
