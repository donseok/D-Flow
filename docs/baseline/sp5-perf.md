- 기준선: `git worktree` 로 `07d8bd1` 을 따로 빌드해 3103 에서 `next start`. 그 편의 `dev-bootstrap`·`perf-baseline seed` 를 로컬 DB 에 돌렸다 — DB 스키마는 그때의 로컬 DB(후보 쪽 0024)였다. 기준선 앱은 0019~0024 가 더한 열·표를 읽지 않으므로 쿼리 모양은 기준선 그대로지만, DB 에는 앞선 E2E 데이터가 남아 있었다.
- 후보: `db:reset`(0024) → `dev:bootstrap` → `perf-baseline seed` → 빌드 → 3102 에서 `next start`. 즉 두 편의 시드는 같은 스크립트지만 DB 상태가 같지 않다(기준선 쪽에 E2E 잔여 데이터가 더 있다 — 판정에 불리한 쪽은 기준선이다).
- 라운드 순서는 **교대(ABBA)가 아니라 기준선 3 라운드 → 후보 3 라운드**였다(14:33~14:35 기준선, 14:38~14:40 후보). 1분 load average: 기준선 앞 1.22·뒤 2.02, 후보 앞 1.40·뒤 3.22 — 모두 3 근처 이하.
