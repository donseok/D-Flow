# SP4 실측 노력과 남은 일정 재산정 (스펙 SP4 §2.1·§2.2 · SP3a D31 관례)

SP4 스펙 §2.1 은 체크포인트마다 실측 노력을 원장에 적고 B 의 마감 묶음에서 이 문서로 남기라고 정했다(SP3a `sp3a-effort.md` 와 같은 네 절).
개정 문서의 표는 고치지 않는다 — 이 문서가 SP4 뒤의 기준이고, 개정 표를 바꿀지는 사람이 정한다.

측정일 2026-10-03(KST). 근거는 커밋 시각(`git log --format='%h %ad'` — rebase·쌓기가 작성 시각을 지켰다)과 레인 A 원장(`.superpowers/sp4/progress.md`)의
리뷰 기록, 체크포인트 기록(`sp4-e2e.md` A1·A2·B 절)이다. **추정이 섞인 값은 그렇게 적었다.**

- SP4 는 SP3a 보다 약 3배 빨랐다(0.039~0.055 대 0.11~0.17). 스펙 §2.2 가 SP3a 비율로 어림한 에이전트 시간 "약 4일(3.8~4.2)"에 견주면 실제 달력은 1.5일이다.
  차이의 대부분은 **계획 해상도**로 보인다 — A1 계획은 21,693줄(36과제), A2 6,114줄(24과제), B 2,466줄(16과제)로 코드·테스트·명령을 과제마다 미리 적었고, 구현자는 그것을
  Step 0 대조 → 실패 테스트 → 구현 순으로 따랐다. 스펙·계획·비평 시간(10-01 13:00~18:30 부근 — 원장 "스펙 단계")은 이 표에 들어 있지 않다.
- 체크포인트 안에서는 검증이 여전히 큰 몫이다 — A1 의 체크포인트 꼬리 2.1시간(결함 수정·재실행·눈확인 세 번), A2 의 성능 재측정, B 의 체크포인트 45분(눈확인 상호작용 여덟 번 — 테마 선호·multipart 가로채기 같은 하네스 함정). SP3a 문서의 결론(검증 비용이 지배)과 같은 방향이다.

## 4. 이 계산이 틀릴 수 있는 곳

- **한 표본의 비율** — SP4 하나에서 나온 0.039~0.055 다. SP4 는 스펙 비평·재검토가 길었고(스펙 단계 하루) 계획이 아주 촘촘했다 — 계획이 얇은 SP 에서는 SP3a 쪽(0.11~0.17)에 가까울 수 있다. 위 표에 두 환산을 나란히 둔 이유다.
- **병렬 겹침** — 묶음 리뷰와 다음 묶음 구현이 겹쳐 돌았다. 커밋 시각의 경과는 에이전트 시간의 합이 아니다(합은 1.5~2.5배 — 어림).
- **들어 있지 않은 것** — 스펙·계획·비평 시간, 사람 게이트·push 대기, Phase 최종 리뷰의 일부(B 는 이 기록 뒤), 성능 재측정 같은 꼬리.
- **B 의 정지 처리** — B 의 경과에서 정지 7.1시간을 빼면 비율이 0.009~0.014 로 크게 내려간다. 표의 SP4 전체 비율은 정지를 포함한 달력이다(보수적으로).
- **SP5 의 겹침** — SP5 Phase A 는 이미 `sp5/a` 에 일부 구현돼 있다. 그 몫을 빼지 않았다(rebase·재검증 비용과 비기는 것으로 보았다 — 추정).
