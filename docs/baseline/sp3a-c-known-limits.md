# SP3a Phase C — 남아 있는 한계

Phase C(설정 화면·브랜딩·카탈로그) 체크포인트 시점에 **알고 남긴** 것들이다. 이 브랜치(`ui/sp3a-settings`)를 머지하는 사람이
읽어야 하고, 다음 작업자(SP3b·SPU1·Phase D)가 이어받는다. 리뷰 원문은 SDD 원장(`.superpowers/sdd/2026-09-30-sp3a-phase-c/review-*.md`)에
있으나 그 원장은 브랜치에 따라가지 않으므로 여기에 옮긴다. 이미 고친 것(`chooseMine` 의 미편집 키 덮어쓰기, 모듈 편집기의
허위 충돌·저장 뒤 동기화 실패 뒤 막힌 복구, 없어진 토글을 가리키는 문구, 카탈로그 심볼 검사 구멍 등)은 적지 않는다.

## 운영자가 알아야 하는 것

- **`agents` 는 기본 모듈 목록에 이미 들어 있지만 등록 행(`agent_projects`)은 없다.** 프로젝트 설정의 모듈 편집기에서 에이전트가 켜진 것으로
  보여도, 등록 행이 없으면 두 원천 AND 라 에이전트 API 는 404 다. 행은 (a) 모듈을 껐다 다시 켜거나(`syncAgentsModule` 은 '새로 켬'에서만 돈다)
  (b) WBS 항목에 에이전트 위임을 체크할 때 만들어진다. 옛 토글은 같은 값 저장으로도 행을 만들었다. 로컬 E2E 는 끈 뒤 켜는 경로로 고쳤다.
  SP3b(허브 상태 화면)가 '켜짐인데 등록 안 됨'을 보여 주어야 한다.
- **위키 재구성 잡은 파괴적 선점 뒤 `skipped` 로 닫힌다**(Phase B 한계 — `sp3a-b-known-limits.md`). 모듈을 껐다 켜도 위키 지식이 복구되지 않으며
  `/api/wiki/reindex` 의 `enqueue` 한 번이 복구다. Phase C 는 이를 바꾸지 않았다(워커 주석만 Phase B 끝에 복원).

## 스펙 §5.3 계약과 다른 곳 (SPU1 이 공통 훅으로 일반화한다 — 스펙이 그렇게 정했다)

- 저장 상태 기계(충돌·결과 불명·새/같은 `commandId`·변경 없음)는 편집기 여덟 곳의 **사본**이다. 이번에 여덟 편집기 모두 같은 동작을 하도록 맞추고
  공통 케이스를 테스트로 고정했지만, 고치려면 여덟 곳을 같이 고쳐야 한다.
- 충돌 비교에서 **키별 재적용**은 없다 — 선택은 편집기 전체 단위다(다중 키 편집기는 `WorkspaceFieldsEditor` 하나이고, 안 고친 키는 자동으로 최신으로 간다).
- 모듈 편집기 둘은 공통 비교 컴포넌트 `ConflictCompare` 를 쓰지 않고 각자 마크업이며 버튼 문구가 "내 값 다시 **검토**" 다.
- 출처·적용 시점·편집 주체 표시가 일부 키에만 있다. 프로젝트 키(`core.level_labels`·`modules.enabled`·`workflow.stage_credits`)와 워크스페이스 전용
  편집기(로고·accent·메뉴)에는 출처 라벨이 없고, D23 '생성 시 복사' 라벨(이력 `source='copy'` 사용)도 없다.
- 설정 검색은 **카드 단위**이고 카드 전체 텍스트에 일치한다(필드 단위 아님). 목차·범주 앵커는 이번에 범주 컨테이너로 맞췄다.

## 동작상의 경계

- 모듈 편집기에서 **손상·필수 누락을 복구할 때 선택이 빈 목록으로 시작**한다 — 아무것도 고르지 않고 검토→저장하면 `modules.allowed = []`(워크스페이스의
  모든 모듈 불허)가 저장된다. fail-closed 이고 화면 문구가 "새 선택으로 복구"라고 말하지만 기본값 제안은 없다.
- 설정 조회가 실패하면 표시·발송 소비처(초대 메일·회의 알림·내보내기)는 **기본 제품명으로 대체하고 로그만 남긴다**(표시 = 로깅은 충족). 워크스페이스 이름이 아닌
  기본 브랜드의 제목·발신명으로 외부에 나갈 수 있다. 발송을 막을지는 설계 판단이다.
- 프로젝트 복사는 원본의 **필수 설정 누락(`required_missing`)** 을 손상으로 세지 않는다 — 손상(`invalid`)만 거부한다(D29). 빈 단계 라벨·기본 모듈로 조용히 진행한다.
- `StageCreditSlider` 의 '내 값 다시 적용' 뒤 검토 패널은 충돌 전 기준의 'X% → Y%' 를 보인다(최신 값 기준 아님).
- 워크스페이스 허용 축소 미리보기는 프로젝트 하나라도 `modules.enabled` 가 손상이면 전체가 '영향을 확인하지 못했습니다'로 끝난다(0 으로 위장하지 않는다 —
  다만 어느 프로젝트인지 알리지 않고 저장도 막는다).
- `WorkspaceFieldsEditor` 는 '설정 손상' 키를 건드리지 않아도 변경에 넣는다 — 같은 편집기의 다른 필드를 저장할 때 손상 키에 표시용 자리값이 함께 쓰인다.
- 저장 성공 뒤 `router.refresh()` 는 편집기 state 를 재초기화하지 않아 서버가 정규화한 값(마일스톤 키워드 소문자, accent base 소문자)이 새로고침 전까지 입력 그대로 보인다.

## 브랜딩·보안

- 저장하지 않은 로고와 교체된 옛 로고가 비공개 버킷에 남는다(옛 파일을 지우지 않는 것은 D36). 그 워크스페이스 멤버는 Storage API 를 직접 불러 **경로를 알면** 읽을 수
  있다(목록 권한 포함). `/api/brand` 라우트는 현재 슬롯만 주지만 버킷 정책은 워크스페이스 단위다. 로고는 공개해도 되는 자산이라 위험은 낮다.
- `accent` 파생: 무채색 입력(#808080·#fff·#000)의 `soft` 색이 위험색 계열 분홍으로 나오고, 극단 입력에서 hover/pressed 가 배경색과 같아진다. 임계 경계 고정과 함께
  SP3b UI-1(소비 쪽)이 조정한다(D30).
- 파비콘은 **마크가 저장된 워크스페이스의 `/w/<슬러그>` 아래에서만** 바뀐다(메타데이터 `icons` 가 루트 파일 아이콘을 덮는다는 것을 실측). 셸·`/p/*`·`/projects` 의 반영은 SP3b ★8.

## 테스트가 덜 보는 곳

- 카탈로그 `verified` 상태는 `tests` 경로가 **실재하는지**만 본다 — 그 테스트가 그 키를 실제로 다루는지는 보지 않는다. 자동 절 비교는 `CATALOG_WRITE=1` 이면 차이를
  쓰고 통과시킨다(CI 에는 설정돼 있지 않다).
- 영향 미리보기 테스트는 표 이름을 mock 해서 본다(표 이름 자체는 `0000_baseline` 과 대조해 확인했다).

## E2E 실행 메모

- 로컬 E2E 는 `next dev` 전제다(`next start` 는 팀 캐시 TTL 때문에 임포트 단계가 409). 작은 머신에서 dev 서버가 메모리 감시로 재시작해 요청이 끊길 수 있어, 서버 액션
  호출은 매니페스트가 비면 그 페이지를 다시 열어 복구한다(이번에 스크립트에 넣음). 재시작이 있어도 단계가 통과하면 결과는 유효하다.
