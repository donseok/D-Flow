# SP7 자격증명 판정부 구현 (2026-10-05)

기준 main `cbcc9775`. 정본 generic-platform-design §5.1.2~5.1.3·§5.2.2 및 개정 문서 §6.2 SP7.

## 구현한 계약

- `generateCredentialToken(kind)`는 에이전트 PAT(`dflow_pat_`)와 회의록 연동(`dflow_int_`)을 발급한다. `generateAgentToken`·`PAT_RE`의 기존 계약은 유지한다.
- `resolveCredential`은 해당 API 킬스위치를 먼저 검사하고, 유형에 맞는 Bearer 토큰으로 `integration_credentials`를 조회한다. enabled → revoked → expires → hash 순서로 검증한다. 조회 장애·손상된 행은 동일한 401로 거절하고 인증 성공 결과에는 해시/평문을 포함하지 않는다.
- `last_used_at`은 행 ID와 워크스페이스 ID를 함께 걸어 갱신하며 완료를 기다린다. 갱신 실패는 인증을 거절하지 않는다. 로그에는 DB 오류 상세나 토큰을 넣지 않는다.
- `narrowActor`는 현재 워크스페이스 소속과 프로젝트 허용 범위로 모든 권한 맵을 좁힌다. 플랫폼 관리자 승격은 제거하며, 소속 회수 뒤 남은 프로젝트 명단도 제거한다. 기존 `roleIn` 판정자를 그대로 사용한다.
- `actorFromCredential`은 매 요청 현재 권한을 읽는다. PAT에 다른 사용자 ID를 전달하면 DB 권한 조회 전에 거절한다.
- `authorizeAgentCredentialProject`는 토큰 스코프·현재 역할·자원 범위·활성 agents 모듈의 교집합이다. 권한 판정 뒤 모듈을 읽고 구조 쓰기는 현재 관리자만 허용한다. 기존 `work:report` → `work:claim` 호환을 유지한다.
- `resolveCredentialTeam`은 명시된 매핑 → 코드 일치 → 기본 팀 순서다. 명시된 매핑이 삭제·범위 밖·비활성 팀을 가리키면 기본 팀으로 넘어가지 않는다. 상속된 객체 속성은 매핑으로 해석하지 않고, 코드가 모호하면 거절한다. 호출부는 프로젝트/워크스페이스로 제한한 후보 팀을 제공해야 한다.

## 통합 상태 및 다음 순서

이 구현은 공통 판정부이며 **기존 라우트의 인증 방식은 아직 전환하지 않았다**. 기존 환경에서 `integration_credentials`가 없을 수 있어 전환은 DB 이관·라우트·발급 UI가 검증된 뒤 한 묶음으로 적용해야 한다. 따라서 현재 사용자 발급 토큰과 외부 회의록 수신 경로는 기존 인증을 사용한다.

SP7 전용 작업트리 `/Users/jerry/D-Flow-wt/lane-a-sp4`의 기존 미커밋 초안은 보존했다. 초안을 그대로 적용하지 않고 다음을 보완해야 한다.

1. 다중 워크스페이스 무제한 PAT를 `workspace_members`의 첫 행에 임의 배정하는 이관은 정본의 선택/회전 계약과 대조한다. 소속 없는 토큰을 조용히 건너뛰는 동작도 명시적으로 처리한다.
2. `agent_projects`를 삭제하기 전에 모든 소비처를 설정 단일 원천으로 옮긴다. 데이터·정책·트리거를 복원하지 않는 롤백을 보완한다.
3. `team_map`의 객체/문자열 값 검증, 범위 드리프트·소속 회수 시 갱신 계약을 DB 가드/RLS 테스트로 검증한다.
4. 검증한 스키마와 기존 API 응답 계약을 바탕으로 에이전트·회의록 라우트 및 발급/회수 UI를 연결한다. 사용자 DB 적용과 원격 push는 별도 기존 게이트를 따른다.

DB 스키마 변경·리셋·사용자 DB 적용은 이번 묶음에 없다. Docker 데몬이 꺼져 있음을 읽기 전용으로 확인했다. DB 검증 결과로 간주하지 않는다.
