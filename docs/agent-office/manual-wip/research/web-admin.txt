  REAL: 「중단」은 에이전트가 점유한 모든 줄 — 작업 중·무응답·끊김·결정 대기·반려·재작업 — 에 관리자·상위 담당자에게 보인다.  (src/components/agent-hub/DelegationTable.tsx:59-63, src/lib/domain/seatState.ts:50-59)
- GUIDE: 메뉴의 에이전트 옆 숫자는 승인을 기다리는 완료 보고의 개수 (앱 매뉴얼 11-agents.md 51행)
  REAL: 내가 승인할 수 있는 것만 센다. 상위 담당자는 자기 담당·자기 착수 건이 빠지고, 다단계 설정의 관리자 전용 단계·같은 사람 금지도 반영된다.  (src/lib/data/agentApprovals.ts:34-58, src/lib/domain/approvable.ts:14-38)

## OPEN
- 다단계 승인 프로젝트에서 위임 표 줄의 「승인」이 단계 코드 없이 보내져 서버가 approval_stale 로 거부하는지 로컬 재현이 필요하다(코드 판독상 그렇다 — DelegationTable.tsx:499-502, 0026_workflow_policy.sql:418-421). 매뉴얼에 '다단계면 카드에서 승인'이라 쓸지, 코드를 고칠지 결정 필요.
- 운영 배포에 AGENT_API_ENABLED=true 가 설정돼 있는지 확인 못 했다(운영 접속 금지). 꺼져 있으면 토큰 발급('에이전트 API가 꺼져 있어 발급할 수 없습니다.')과 에이전트 API 전체가 막힌다.
- 토큰 화면의 work:claim 설명 '— 조회 포함'이 서버 동작(work:read 별도 요구)과 다르다. 화면 문구를 고칠지, 서버가 claim 을 read 로 인정하게 할지 정해야 매뉴얼 문장이 확정된다.
- 관리자의 자기 승인 허용이 의도인지 — 용어집·실습 안내서는 '스스로 승인할 수 없다'로 쓰고 코드는 관리자를 예외로 둔다.
- 완료 보고 알림이 명단 권한 '관리자' 행에게만 가서, 워크스페이스 관리자(상속 관리자)는 알림을 못 받는다. 매뉴얼에 '승인자는 명단에 자신을 관리자로 올려 두라'고 안내할지, 수신자를 넓힐지.
- '대기' 타일이 위임 안 된 개발 작업 주문까지 세어 요약 문장('위임한 n건 중…')과 어긋날 수 있다 — 의도인지.
- 새 매뉴얼을 앱 안(src/content/manual)에 넣을지 별도 문서로 낼지. 앱 안이면 시험이 '모듈'·'API'·영문 token 을 금지해 「모듈·메뉴」, 「모듈 사용 범위」, 「에이전트 API가 꺼져 있어…」 같은 실제 화면 문구를 그대로 인용할 수 없다.
- 다단계 + '단계마다 다른 승인자'에서 이미 한 단계를 승인한 관리자에게 카드 안내가 '승인은 관리자가 합니다…'로 나와 오해를 부를 수 있다(ApprovalQueue.tsx:93-95) — 문구 보완 여부.
