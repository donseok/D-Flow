- [표⑭ 좌석에서 결재하기] 행 = 승인 대기 / 머지 완료 / 업무 중·결정 대기·반려 / 무응답·끊김 / 빈자리. 열 = 나오는 버튼 | 누를 수 있는 사람(관리자 · 담당자 본인 · 상위 항목 담당자에 ○/×) | 누른 뒤(즉시 실행 / 사유 입력 → '…확정' / 확인 상자 → '중단 확정') | 결과(WBS 단계·실적). 회색 버튼 위 툴팁 말풍선 예시 2개('권한이 없습니다 — …').
- [해부도⑮ 상세 카드] 윗줄 '프로젝트A · WP-02 병렬 개발 · 주문 1a2b3c4d' + X / 'TSK-02-01' / '합계 함수 개발' / 상태 알약 / 다섯 칸 사다리(design 25 · build 60 · verify 85 · reported 100 · merged 100 — 지난 칸 파랑, 지금 칸 검정, 반려 칸 빨강) / 사실 표(에이전트·진행·마지막 신호·heartbeat·재개 요청) / 메모 인용 / 결재 큰 버튼 / 사유 입력 상자(필수, 확정·취소) / 'WBS 에서 열기'. '보고 본문은 여기 없음 → 위임·승인 탭' 화살표.
- [순서도⑯ '이어서 시작'은 이렇게 처리된다] 사람: 무응답 좌석 [이어서 시작] → 서버: 재개 표식(주문·시각 그대로, 버튼 잠김 '재개 요청됨(대기 중)…') → 그 PC의 같은 계정 /dflow-team 팀장: 다음 watch(최대 30분) 응답에서 요청 수신 → 팀원 다시 띄움 → 첫 heartbeat → 표식 지워짐, 좌석 '업무 중'. 갈림길: 그 PC에 /dflow-poll·수동 세션만 있음 → 아무도 안 가져감 → 그 PC에서 '/dflow-dev <주문 앞 8자리>'.
- [순서도⑰ '중단'] [중단] → 상세 카드 확인 상자 '중단할까요? …' → [중단 확정] → 서버: 위임(agent 태그) 끔·주문 취소·단계 as → 화면: 좌석 사라짐(실시간 1~7초) → PC: 다음 도구 호출의 heartbeat 가 409 cancelled 받음 → 세션 정지(약 1분) → 다시 맡기려면 위임·승인 탭 체크. '훅이 없으면 PC가 모를 수 있음' 경고 아이콘.
- [문제 해결 나무⑱ 오피스가 비었거나 팀장이 안 보일 때] '아무것도 없다' → ◇지금 보기 = 에이전트? → 평면도로 바꿈 → ◇범위 = 내 작업? → 전체 → ◇평면도에도 없음 → 위임·승인 탭에서 위임 체크했나? → 에이전트 기능 켜짐? → 내가 그 프로젝트 멤버 이상? / '팀장이 안 보인다' → ◇위임 주문이 하나라도 있나 → ◇마지막 감시 신호 70분 안? → ◇그 PC에서 /dflow-team·/dflow-poll 실행 중? / '무응답이 계속' → 훅 설치·.dflow-agent·agent/ 브랜치·state.json phase·.env 확인.
- [시계⑲ 화면은 언제 새로 바뀌나] 원형 시계: 30초마다 자동 재조회 눈금, 1초마다 경과 시간 증가, 번개(단계·실적 변화만 1~7초), 탭 숨김 = 일시정지 → 돌아오면 즉시 1회, 사유 입력·중단 확인 중 = 일시정지, 버튼·범위 단추 = 즉시. 실패 시 '갱신 실패 …' 빨간 글씨와 '마지막 화면 유지' 메모.
- [비교표⑳ 머리 숫자 두 벌] 위: 평면도·상태 레인 타일 4칸(업무 중=업무 중+무응답+반려+결정 대기 / 승인 대기 / 빈자리·끊김 / 감시 중), 아래: 에이전트 보기 타일 5칸(업무 중=업무 중+반려 / 결정 대기 / 무응답 / 끊김 / 빈자리=빈 팀원 자리). 같은 이름 다른 뜻 칸을 같은 색 점선으로 연결.
## OPEN
- '머지 완료' 라벨은 실제 코드 합치기가 아니라 승인(approved) 상태다. 매뉴얼에서 '승인 완료(코드 합치기는 /dflow-merge 로 따로)'라고 풀어 쓸지, 화면 라벨 자체를 바꿀지 제품 결정이 필요하다.
- 수동(대화형) /dflow-dev 가 세션에서 사람에게 질문하고 답을 기다릴 때 dflow.sh heartbeat --phase blocked 를 보내는지 확인하지 못했다. 팀원 워커 지침(worker-prompt.md)과 dflow-work 스킬에는 있지만 dflow-dev 의 대화형 경로에는 명시가 없다. 보내지 않으면 그 좌석은 '결정 대기'가 아니라 5분 뒤 무응답, 30분 뒤 끊김으로 보인다 — 실측 필요.
- 프로젝트 오피스의 '감시 중' 숫자가 같은 워크스페이스의 다른 프로젝트 감시자까지 세는 것(층 머리 '감시 중 ·' 표시와 숫자가 다를 수 있음)이 의도된 동작인지.
- 에이전트 보기 빈 문구('감시를 시작하거나 … 잡으면 여기에 자리가 생깁니다')와 달리, 위임 주문이 하나도 없는 프로젝트는 감시자를 아예 읽지 않아 팀장이 나타나지 않는다. 문구와 동작 중 어느 쪽에 맞출지.
- 워크스페이스 홈 '에이전트 현황' 위젯이 reported 를 '결정 대기'로 부르고 위임(agent 태그) 여부를 거르지 않는다. 매뉴얼에 '오피스와 숫자·이름이 다를 수 있다'고 적을지, 위젯을 고칠지.
- 진행 막대·실적 숫자(착수 30, 반려 50, 완료 보고 80, 승인 100)는 기본 크레딧 기준이다. 실습 WBS(docs/agent-office/agent-office-demo-wbs.md)의 frontmatter credits(대기 0·설계 20·구현중 50…)가 프로젝트 크레딧 표(workflow.stage_credits)에 반영되는지는 확인하지 못했다 — 실습 프로젝트에서 막대가 몇 %로 보일지 확인 필요.
- 운영(dflow-prod)에서 Supabase 실시간(private broadcast) 채널이 실제로 동작하는지는 확인하지 않았다(네트워크 금지 규칙). 동작하지 않으면 모든 변화가 30초 자동 갱신으로만 보인다.
- Windows(WSL) PC 의 hostname 슬러그가 어떤 모양으로 나오는지(예: desktop-abc123) 실측이 필요하다. 에이전트 보기 카드 이름·'이어서 시작' 대상 PC 표기에 그대로 쓰이므로 매뉴얼 그림 예시를 정하려면 필요하다.
- 한국어 전용 제품인데 상세 카드 사다리(design·build·verify·reported·merged), 'heartbeat' 줄 이름, '<build> 에서 끊김'·'진척 30% · 단계 build'의 단계 값이 영어 그대로 나온다. 매뉴얼에 영어 그대로 싣고 뜻을 풀어 줄지, 화면을 한국어로 바꿀지 결정 필요.
- 실제 화면 캡처는 하지 않았다(읽기 전용) — 와이어프레임은 코드에서 재구성한 것이다. 매뉴얼에 스크린샷을 넣으려면 로컬 dev 에서 시드 데이터(위임 주문·감시자·heartbeat)를 만들어 캡처해야 한다.
