## DIAGRAM IDEAS
- 전체 흐름 수영 레인(가로 4줄: 관리자 웹 · D-Flow 서버 · 개발 PC(Claude Code + 킷) · GitHub). ①위임 체크 → ②/dflow-dev(또는 poll·team)가 claim → ③설계·구현·검증 커밋 → ④push agent/<id8>-<slug> → ⑤done(승인 대기) → ⑥웹 승인/반려 → ⑦/dflow-merge 가 main 에 --no-ff 머지·push. 화살표마다 쓰는 명령·API 이름을 작게 적는다.
- 설치 순서도(세로 단계 상자): D-Flow 소스 clone → scripts/kit-build.sh ~/dflow-kit → ~/dflow-kit/install.sh <리포> --hooks → .env 채우기 → dflow.sh doctor·me → .claude/skills 커밋·push → ~/.claude/settings.json 에 훅 등록 → 리포 루트에서 claude. 옆에 빨간 X 상자 'D-Flow/kit/install.sh 직접 실행 금지(skills 없음 → cp 오류)'.
- install.sh 가 만드는 파일 지도(트리 그림): <리포>/.claude/skills/dflow-*(7)·_shared·DFLOW_KIT_VERSION, .claude/settings.json(permissions.allow: Bash(<git 경로> *)), .env, .gitignore(+.env), .gitattributes(+eol=lf) 와 홈 폴더 ~/.dflow/hooks/heartbeat.sh, ~/.claude/settings.json(사람이 등록). '커밋할 것 / 커밋하지 말 것(.env)' 색 구분.
- .env 해부 카드: 키 5개(DFLOW_API_BASE·DFLOW_PATS·DFLOW_PROJECT_ID·DFLOW_AS·DFLOW_AUTOMERGE)를 행으로, 칸은 '필수?/어디서 값을 얻나/틀리면 나오는 메시지'. 프로젝트 UUID 는 주소창 /p/<UUID>/ 그림에서 괄호로 짚는다.
- 토큰 모양 그림: dflow_pat_[prefix 12자]_[비밀 43자] 를 블록으로 나누고 prefix 블록에서 화살표 두 개 → 웹 토큰 표의 'prefix' 칸, .env 의 DFLOW_AS=. 아래에 스코프 체크 상자 두 개(조회 work:read ☑ · work:claim ☑)를 '둘 다 체크' 로 강조.
- /dflow-dev 사이클 원형 다이어그램: 01-가 승인 스윕 → 01 claim·브랜치·기준선 → 02 설계(design.md, 진행 25) → 03 구현 TDD(60) → 04 검증(85) → 05 리팩터 → 06 push·done(승인 대기). 각 칸 옆에 오피스 좌석에 보이는 단계 이름(설계·구현·검증·리팩터·보고)과 그 단계의 모델(opus/sonnet/haiku)을 단다.
- 주문 상태 기계(상자와 화살표): 대기 ready(할당됨 as) —claim→ claimed(작업 중 ip) —done→ reported(승인 대기·검수 대기 im) —승인→ approved(완료 xx·실적 100). reported —반려→ claimed, claimed —release→ ready, ready/claimed —중단→ cancelled. 화살표 색으로 'PC(킷)가 일으킴' 과 '웹(사람)이 일으킴' 을 구분.
- 자동 착수 깔때기: 모든 대기 주문 → 이 리포 프로젝트(DFLOW_PROJECT_ID) → 나에게 배정됨(assigned) → 상태 RD → agent 태그(위임 체크) → 명세 본문 있음 → 선행 충족 → 착수. 각 단계에서 떨어지는 예(담당자 미지정, 태그 없음, spec 비어 있음)를 옆에 표시.
- 세 실행 방식 비교표(3열 카드): /dflow-dev(1건·수동·대화형) · /dflow-poll(1건씩·자동·낮 18:00까지·5분 간격) · /dflow-team(최대 4명 동시·tmux/Orca·3분 간격·여러 날). 행: 누가 고르나, 동시 수, 승인 시 머지, 반려 시 자동 재작업, 오피스 '감시 중' 표시 여부.
- /dflow-team 구조도: 팀장 세션(기본 브랜치 체크아웃, dflow-team.lock, poll.sh 180초, 결과 감시 20초, TICK 30분) 아래로 팀원 상자 w1~w4(.claude/worktrees/dflow-<id8> 또는 Orca 탭, 권한 확인 생략, /dflow-dev --worker) → 각 팀원의 .result → 팀장 결과 처리 → 승인 스윕 → main. 멈추는 두 길('팀장 종료' 말하기, dflow-team.stop 파일)을 빨간 버튼으로.
- heartbeat 타임라인(가로 시간축): 도구 사용마다 훅 실행, 60초 안의 것은 건너뜀(회색 점), 신호 전송(초록 점). 마지막 신호 뒤 5분 '무응답'(노랑), 30분 '끊김'(빨강) 경계선. 별도로 웹 '중단' → 다음 신호에서 409 cancelled → 세션 멈춤(continue:false) 분기.
- 브랜치·파일 지도: main 줄기에서 갈라진 agent/<id8>-<slug> 가지, 가지 위 커밋마다 'DFlow-Order: <UUID>' 꼬리표, 끝에 'merge: <TSK> <제목> (approved)' 머지 점과 'chore(<TSK>): phase=merged'. 옆에 docs/tasks/<TSK>/ 폴더(spec.md·design.md·state.json·screens/) 펼친 그림.
- 스택 브랜치 머지 순서 그림: 선행 A 가지 위에 후속 B 가지(branch_base=A 커밋). '/dflow-merge 는 A 먼저, A 가 미승인이면 B 도 보류' 를 신호등으로.
- 종료 코드 신호등 표: 0 초록(성공) / 2·4 노랑(설정·push·선행 — 고치고 다시) / 3·5·7 빨강(인증·권한·꺼짐 — 사람에게 확인) / 6 주황(네트워크 — 잠시 뒤) / 10 검정(웹에서 중단 — 즉시 멈춤). 각 칸에 '이럴 때 할 일' 한 줄.
