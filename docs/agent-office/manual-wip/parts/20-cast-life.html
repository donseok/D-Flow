01등장하는 것들

사람 계정 둘, 연결 키 하나, 개발 PC 한 대, 저장소 하나가 나옵니다. 첫 실습에는 이 다섯이면 충분합니다.

관리자 계정 웹 · 관리자

지금 쓰는 내 계정입니다. 에이전트 기능을 켜고, 작업을 맡기고, 결과를 승인합니다. 프로젝트 관리자 이상이면 됩니다.

개발 계정 웹 · 개발 계정

개발 PC 한 대마다 하나 만듭니다(예: 개발-Mac1). 프로젝트 권한은 「멤버」입니다. 이 계정이 작업의 담당자이면서 토큰의 주인입니다.

개인 액세스 토큰(PAT)

개발 계정이 발급하는 연결 키입니다. 개발 PC의 .env 파일에 넣습니다. 전체 값은 발급 직후 한 번만 보입니다.

개발 PC + D-Flow 킷 /PC

Claude Code가 실제로 코드를 쓰는 곳입니다. D-Flow 킷(스킬 7개와 신호 훅)을 개발 저장소에 설치합니다.

개발 저장소 GitHub

개발할 코드가 있는 저장소입니다. 실습에서는 office-demo를 씁니다. 작업마다 agent/… 브랜치가 생기고, 승인된 것만 main에 합칩니다.

D-Flow 서버

https://d-flow-eight.vercel.app. 작업 주문을 내주고 신호와 보고를 받습니다. PC가 몇 대든 모두 이 한 곳에 붙습니다. PC에 서버나 DB를 설치하지 않습니다.

네 고리가 한 계정으로 이어져야 합니다

PC가 작업을 가져가려면 아래 네 칸이 모두 같은 개발 계정이어야 합니다. 하나라도 어긋나면 그 아래의 증상이 나옵니다.

왜 계정을 나누나요

관리자 계정의 토큰을 PC에 쓰지 않습니다. 개발 계정은 「멤버」라서 승인 권한이 없고, 누가 무엇을 개발했는지가 계정으로 남습니다. 관리자는 규칙상 자기가 담당하거나 착수한 작업도 승인할 수 있습니다. 그래서 개발과 결재를 계정으로 갈라 두는 편이 안전합니다.

계정은 세 종류이고, 서로 따로입니다

종류하는 일몇 개 필요한가
D-Flow 계정·토큰누가 어떤 작업을 개발하는지 구별합니다.PC마다 개발 계정 하나 + 승인용 관리자 계정
Claude Code 로그인PC에서 AI 개발 도구를 씁니다.각 서비스의 이용 조건대로
GitHub 로그인코드를 받고, 작업 브랜치를 올리고, 합칩니다.실습 저장소에 쓰기 권한이 있으면 됨

D-Flow 개발 계정을 넷 만든다고 Claude나 GitHub 계정을 넷 만들 필요는 없습니다. 다만 동시에 돌리는 수가 늘면 AI 사용량도 늘어납니다.

02작업 하나의 일생

작업에는 '작업 주문'이 하나씩 붙습니다. 주문은 아래 네 칸을 차례로 지나고, 칸마다 누구 차례인지가 정해져 있습니다. 같은 칸을 화면마다 다른 이름으로 부르니 이름 짝을 같이 봐 두세요.

같은 상태, 화면마다 다른 이름

이름에 속지 마세요

오피스의 「머지 완료」는 웹에서 승인됐다는 뜻입니다. 코드가 main에 들어갔는지는 서버가 모릅니다. 승인 뒤 PC에서 /dflow-merge를 돌려야 실제로 합쳐집니다(6장).

작업 중일 때는 '신호'로 상태가 갈립니다

개발 PC의 heartbeat 훅은 Claude Code가 도구를 쓸 때마다 불리지만, 서버로는 작업 하나당 1분에 한 번만 보냅니다. 에이전트가 질문을 띄우고 답을 기다리면 도구를 쓰지 않으니 신호도 멈춥니다.

  • 결정 대기는 에이전트가 직접 "사람 결정이 필요하다"고 알린 상태입니다. 주로 /dflow-team 팀원이 보냅니다. 답은 웹이 아니라 그 작업을 돌리는 PC의 세션에서 합니다.
  • 수동 /dflow-dev는 질문을 PC 화면에 바로 띄웁니다. 답을 기다리는 동안 신호가 없으니 5분 뒤 「무응답」으로 보일 수 있습니다. PC 앞에서 답하면 다시 「업무 중」이 됩니다.
  • 훅을 설치하지 않으면 단계가 끝날 때의 진행 보고 말고는 신호가 없어, 긴 단계 중에 「무응답」이 됩니다(3장 C4).

맡겼는데 왜 아직 「대기」일까 — 사유 칸은 이 순서로 정해집니다
